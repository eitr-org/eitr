# Gitアカウント

Walker > Development > Git Accountsを開きます。GitHubおよびGitLabのアカウントを同時に使用でき、同じプロバイダーや企業のホスト名にある複数のアカウントも扱えます。新規インストール環境にはGitHub CLI（`gh`）およびGitLab CLI（`glab`）が同梱されています。変更を反映するには既存のISOイメージを再ビルドする必要があります。

各アカウントは、Gitがどこで使用しているかを示す行として表示されます: **Default**、設定されているフォルダ名、または**Not used yet**。アカウント上でEnterを押すとそのアクションが開き、Shift+Backspaceで一覧に戻ります。

## 初回セットアップ

1. **Add Account**は、プロバイダー、アカウント名、コミット作成者名とメールアドレス、ホスト名、オプションの既存プライベートSSHキー、デフォルトID、フォルダルールを設定するための共通のステップバイステップフォームを開きます。すべての回答は確認画面に表示され、適用前に任意のステップに戻ることができます。EscまたはCtrl+Cで保存せずにキャンセルします。
2. **Import Existing Setup**は、手動で設定されたIDを読み込みます: `~/.gitconfig`または`~/.config/git/config`内のデフォルトの`user.name`/`user.email`およびフォルダごとの`includeIf "gitdir:…"`ルール（インクルードされたファイルが経由するSSHエイリアスとキー（`url.<alias>.insteadOf`）を含む）。見つかった項目を一覧表示し、確認後に一致するアカウントとルールを作成します。ファイルは変更されず、ワイルドカードのフォルダパターンはスキップされたものとして表示されます。

## デフォルトとフォルダ

**default**アカウントは、専用のアカウントを持たないすべてのフォルダに適用されます。**folder**アカウントは、そのフォルダ内のリポジトリにのみ適用されます。より具体的なフォルダの設定が優先されます。リポジトリごとのローカル設定、Gitコマンドライン、環境変数の上書きは引き続き最優先されます。EITRは既存のグローバル設定やコメントを保持し、`~/.gitconfig`の末尾にマークされたインクルードを追加します。確認されたルールは外部インクルードのIDを上書きします。

Walker内のアカウントアクションは、保存前に確認が行われ、通知で結果が報告されます: **Make Default**または**Stop Using as Default**、**Add Folder**（`~/Development`またはその内部のフォルダを選択、または**Other folder…**でパスを入力）、**Remove Folder**。Gitは実際の`.git`ディレクトリと照合するため、リンクされたワークツリーやサブモジュールは親リポジトリのアカウントに従うことができます。

## SSHキー

コミットIDを設定してもリポジトリへのアクセス権が付与されるわけではありません。**Show Public Key**はアカウントの公開鍵を表示し、クリップボードにコピーし、それを追加すべきプロバイダーのページ名を示します（GitHub: Settings > SSH keys）。**Set Existing SSH Key**は`~/.ssh`からキーを選択します。**Create SSH Key**はパスフレーズ付きのEd25519キーを作成し、その公開鍵を表示します。**Test Connection**は、「Hi username!」などのプロバイダーからの応答メッセージを通知で報告します。秘密鍵は決して共有しないでください。

キーはそのプロバイダーのSSHホスト名にのみ適用されます。ランチャーは接続することなく既存のSSHエイリアスを解決し、選択したキーのみを使用し、その接続に対する他のSSH設定を無視します。プロキシ接続は拒否されます。高度なセットアップの場合はリポジトリ固有の`core.sshCommand`を保持してください。known_hostsの検証は有効なまま維持されます。キーが設定されていないアカウントは通常SSHを使用し、他のアカウントのキーを使用することはありません。HTTPSの認証情報および認証情報ヘルパーは変更されません。

## プロバイダーCLI

**Log In to CLI**は、アカウントごとに独立した設定ディレクトリにサインインします。通常のグローバルな`gh`や`glab`のアカウントが切り替わることはありません。そのプロセスのために、継承されたプロバイダートークンの環境変数は削除されます。確認画面では、同一ホスト上のアカウント間で共有されるキーリングエントリを避けるため、トークンが非公開の暗号化されていないCLIプロファイルファイルに保存されることが説明されます。
`~/.config/eitr/git-accounts/cli`は絶対に共有しないでください。EITRのバックアップにも含まれません。

リポジトリからは、アカウント対応のCLIを使用します:

```sh
eitr-git cli auth status
eitr-git cli repo view
```

選択されたデフォルト/フォルダアカウントに応じて`gh`または`glab`が選択されます。通常のCLIコマンドは既存のグローバルな動作を維持します。SSHキーの登録によってCLI API操作が認証されることはありません。Bitbucket CLIは同梱されていません。

## 削除と復旧

**Edit Name and Email**でIDフィールドを変更できます。**Remove Account**は確認後にアカウントとそのルールを削除します。フォルダルールを削除すると、より広範なルールまたはデフォルトにフォールバックします。デフォルトをクリアすると、残りのルールの外部にある既存のGit設定が復元されます。プロジェクト、キー、CLI認証情報が削除されることはなく、ルールを削除してもプロバイダー側のアクセス権が取り消されることはありません。

バージョン管理された設定は`~/.config/eitr/git-accounts.json`に保存されます。適用を行うたびに、グローバルGitファイル、アクティブなインクルード、設定が`~/.local/state/eitr/git-account-backups/<id>`の下に非公開の権限でバックアップされます。`manifest.json`に元のパス、バックアップファイル名、パーミッションが記録されます。キーやCLIトークンがコピーされることはありません。手動で復元を行う場合は、そのマニフェストを確認し、ファイルを復元する前にバックアップ以降に行われた変更を保持してください。編集された、または不正な形式のEITRインクルードブロックは、暗黙のうちに置換されるのではなく拒否されます。

参考文献: [Git条件付きインクルード](https://git-scm.com/docs/git-config)、[GitHub CLIプロファイル](https://cli.github.com/manual/gh_help_environment)、[GitLab CLIプロファイル](https://docs.gitlab.com/cli/configuration/)。
