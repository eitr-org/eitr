# セキュリティとロック

**SUPER + M**で画面を今すぐロックします。バーの左側（AI使用状況の後ろ）にあるアイドルロックのアイコンをクリックすると、非操作時の自動ロックをオンまたはオフに切り替えることができます: ツールチップに現在の状態が表示されます。オンの場合、15分間操作がないと画面がロックされ、30分で画面がオフになり、60分でコンピューターがサスペンドします。コントロールセンターにも同様のアイドルロックの切り替えトグルとロックボタンがあります。

ロックの20秒前に、対応するディスプレイの輝度が前回の約30%まで減光されます（ゼロにはなりません）。操作を再開すると、ロック後であっても前回の正確な輝度レベルに復元されます: アイドルロックをオフにした場合も同様に復元されます。DDCによる輝度制御に対応していない外部モニターはスキップされます。

## パスワードと代替認証

**Settings > Users > Change password**でアカウントのパスワードを変更できます。ログインキーリングもそのパスワードで開くよう維持されます。指紋認証とFIDO2セキュリティキーには、それぞれ専用の登録/有効化ワークフローがあります。FIDO2セキュリティキーは物理的なセキュリティデバイスであり、ノートPCの指紋リーダーではありません。まず登録を行ってから、認証を有効化してください。ヘルパーがPAM設定をバックアップします: 有効なパスワードとTTYへのアクセス手段を必ず確保しておいてください。

Password Authenticationに戻すと、パスワードのみの動作に復元されます。これらの変更は、サポートされているロック画面/ログイン/sudoのPAMサービスに影響します: ハードウェアの対応とインストールされたヘルパーが必要です。指紋認証によってパスワードプロンプトがわずかに遅れる場合があります。このページを閲覧しただけでPAMが変更されることはありません。

## 管理者パスワードプロンプト

アプリまたはEitr自体が管理者権限を必要とする場合（ソフトウェアのインストール、システム設定の変更時）、バーのテーマで描画されたパスワードプロンプトが使用中の画面全体を覆います。要求元の情報、認証するアカウント（複数ある場合は選択肢付き）、およびpolkitアクションを含むリクエストの詳細が表示されます。Enterで認証し、EscapeまたはCancelで拒否します: プロンプトの外側をクリックしても何も起きません。間違ったパスワードを入力するとエラーが表示され、再試行できます。複数のリクエストがある場合は順番を待ち、一度に1つのプロンプトのみが表示されます。パスワードは直接システムに送られ、保存されたりログに記録されたりすることはありません。

ログイン直後にバーがこのプロンプトを提供できない場合、そのセッション中はKDEのパスワードダイアログが代わりを務めるため、管理者リクエストは機能し続けます。

## ファイアウォール

新規インストールでは、ファイアウォールがオンの状態で開始されます。自分のコンピューターから開始された接続への応答、ローカルの名前解決、およびEitrがインストールする共有アプリ（KDE Connectのポート1714〜1764、LocalSendのポート53317）を除き、着信接続は拒否されます。コンピューター上の仮想マシンやコンテナからの接続は引き続き許可され、発信トラフィックがフィルタリングされることはありません。SSHが有効になっている場合は、SSHも引き続き到達可能です。

**Settings > Security > Protection > Firewall**でオンになっているかを確認でき、確認後に切り替えることができます。ファイアウォールが導入される前にセットアップされたコンピューターではオフで開始されます。別のアプリで接続を受け付けるようにするには、`/etc/eitr/firewall.d/`にファイルを追加します（例えば以下の内容を含む`game.nft`）:

```
add rule inet eitr_firewall input udp dport 27015 accept
```

ファイルを追加した後、ファイアウォールを一度オフにしてから再度オンにしてください。

## ディスク暗号化とTPM

ディスク暗号化はインストーラーでの選択項目です。TPM Disk Unlockにより、サポートされている既存のLUKS2 rootにTPM2スロットを追加できます: インストーラーによって自動的には登録されません。パスフレーズ/復旧キーはオフラインで保管してください。スクリーンショットやリポジトリファイル内に保存することは決して避けてください。ファームウェアやセキュアブートの変更により、次回の起動時にパスフレーズが必要になる場合があります。

認証やTPMの設定を変更する前に、[復元とスナップショット](handbook:recovery)をお読みください。[セキュアブート](handbook:secure-boot)は高度な手動プロセスです: EITRがファームウェアキーを登録したり起動ファイルに署名したりすることはありません。誤った操作を行うと、一部のハードウェアで起動できなくなったり、ファームウェア設定にすらアクセスできなくなったりする危険があります。

## ユーザーアカウント

**Settings > Users > Create User…**で個別のログインアカウントを作成します。ユーザー名、オプションのフルネーム、アカウントタイプ、パスワードを入力し、確認後にEnterを押して作成します。適用前であればEscでキャンセルできます。標準アカウントはsudoを使用できません: 管理者アカウントはwheelグループに参加し、パスワードで保護されたsudoルールを受け取ります。

新しいホームフォルダには、既存のアカウントからのファイルは一切含まれません。UWSM経由でHyprlandに初めてログインする際、Eitrはインストーラーのユーザーごとのデスクトップセットアップを実行し、新しいユーザーの権限でパッケージレイアウトを適用します。シェルのセットアップにはインターネットアクセスが必要な場合があります。セットアップに失敗した場合は次回ログイン用の保留マーカーが保持され、成功したセットアップは1回のみ実行されます。アカウントの作成に失敗した場合、不完全なアカウントはロックされ期限切れ状態となり、手動での確認用に残されます。

管理者はSettings > Usersで**Users**および**Manage**タブを確認できます: 標準アカウントにはUsersリストのみが表示されます。管理者はwheelグループに所属しEitrのsudoルールを持ちますが、標準アカウントはどちらも持ちません。Manageでは、アカウントの作成、タイプ変更、他のアカウントのパスワード設定、アカウントの削除が可能です。各操作は確認シートを開いた後、タスクターミナルを開きます: Enterで続行し、Escでキャンセルします。パスワードのリセットでは、ターミナルで新しいパスワードを2回入力します: 対象アカウントのログインキーリングは更新できず、古いパスワードが保持されます。自身のアカウントの場合はUsers内のChange passwordを使用してください。削除時はデフォルトでホームフォルダが保持されます: ファイルを削除するにはDelete home folderを選択します。自分自身、アクティブなログインセッションを持つアカウント、または最後の管理者を削除することはできません: 最後の管理者を一般ユーザーに降格することもできません。管理できるのは人間のアカウント（UID 1000〜65533）のみです。ターミナルから戻ると一覧が更新されます。

プライマリグループがwheelになっているアカウントはここでは降格できません: まず手動の管理者操作でプライマリグループを変更してください。

## プロフィール画像

Settings > UsersにはこのPC上のすべてのアカウントが一覧表示されます。そこで自身の画像をクリックして変更するか、画像の下にあるゴミ箱アイコンを使用して削除できます。画像の選択やトリミングの調整については[設定](handbook:system)をご覧ください。コントロールセンターには画像が表示されるのみです。
