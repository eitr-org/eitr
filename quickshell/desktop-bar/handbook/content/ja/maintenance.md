# アップデート、クリーンアップ、復元

ターミナルには、実行中に各アップデートチェックとスナップショットの段階が表示されます。すべてが最新である場合、メッセージが3秒間表示された後にターミナルが閉じます。

System Updateの待機中のステップでは回転するルーンが表示され、トゥルーカラー対応ターミナルではBifröstレインボーテキストで、それ以外ではテーマのアクセントカラーで流れるように表示され、その後に翻訳されたノースのフレーズと経過時間が続きます。成功したステップは、プレーンなチェックマークとステップテキストとして確定します。

Settings > Updatesを開くと、System UpdateとUpdate Channelを利用できます。Walker > Settings > System > Maintenanceには、クリーンアップ、ミラー、スナップショットが含まれています。システム変更の前には独立したバックアップを必ず保持してください。スナップショットは別ディスクへのバックアップではありません。

System Updateはまず、個別のテンポラリデータベースでcheckupdatesを使用して公式パッケージをチェックし、続いてAURパッケージ（開発版パッケージを含む）およびユーザーFlatpakをチェックします。すべてのチェックでアップデートがないことが確認された場合、スナップショットの作成、アップグレード、再起動プロンプトを表示することなく終了します。チェックが失敗した場合やツールが見つからない場合は、通常のアップデートワークフローが続行されます。

## システムのアップデート

**Settings > Updates > System Update**は、完全なパッケージアップデートを行う通常のワークフローです。構成済みのクリーンなEITRディストリビューションでは、スナップショットサポートを検証し、ブートアーカイブを含む事前/事後スナップショットを作成します。保護機能が失敗した場合はアップグレードは開始されません。ディストリビューションポリシーのない既存のArchデスクトップでは、アップデートを行うためだけにこのセットアップを必要とすることはありません。System UpdateはGeForce NOWなどのFlatpakからインストールされたアプリもアップデートします。Flatpakの失敗は、システムアップデートを取り消すことなく報告されます。

アップグレードの前に、System Updateおよび公式パッケージのターミナルアップデートは、前回のアップグレード以降に公開されたArch Linuxのニュース投稿をチェックします。Archは手動の手順が必要なアップグレードを告知するためにこれを使用します。ニュースがある場合はタイトルとリンクが表示され、**Continue the update? [y/N]**と確認されます。Enterを押すと変更が行われる前にキャンセルされるため、まず投稿を読むことができます。ニュースがない場合やインターネット接続がない場合は、そのまま続行されます。

**Settings > Updates > Update Channel**には両方のチャンネルが一覧表示され、現在のチャンネルに印が付けられます。もう一方を選択すると、ターミナルでパスワードが要求されて切り替わります。これにより、Eitr自体のアップデートの取得元が決まります。デフォルトのStableは、テスト済みのアップデートを受け取ります。Testingは変更をいち早く試すために、公開されるとすぐに新しいビルドを受け取ります。その他はすべて引き続きArchから取得されます。Stableに戻した場合、Stableが追いつくまで新しいEitrバージョンが保持されます。ターミナルからは、`eitr channel`で確認し、`eitr channel testing`または`eitr channel stable`で切り替えます。

アップデートによってコンピューターが起動しなくなった場合、**ブートガード**がそれを元に戻します。アップデート後に2回連続でログイン画面に到達しなかった場合、次回の起動時にアップデート直前のシステムとブートファイルが復元され、再起動されます。ホームフォルダには一切手が加えられず、次回のログイン時に何が起こったかが通知されます。これはEitrインストーラーでインストールされたコンピューターで機能します。詳細は[復元とスナップショット](handbook:recovery)を参照してください。

**ホームフォルダのスナップショット**は、ユーザー自身のファイルの以前のバージョンを保持します。**Walker > Settings > System > Maintenance > Snapshots > Home Folder Snapshots**で有効化してください。1日間は毎時、1週間は毎日取得され、ディスク容量が少なくなると最も古いものが削除されます。キャッシュ、Downloads、VMディスク、ゲームは除外されます。ファイルを元に戻すには、**Restore a File or Folder**を選択し、そのパスを入力して日時を選択します。古いバージョンが現在のものの隣に表示されるため、何かが置き換えられることはありません。

System Updateは、サポートされているディストリビューションインストール上で、スナップショットを伴って公式、AUR、Flatpakの各パッケージをカバーします。AURビルドが失敗したときに公式パッケージのみをアップデートしたい場合や、スナップショットをスキップしたい場合などの稀なケースでは、ターミナルを使用してください: `eitr update pacman`、`eitr update aur`または`eitr update full`（自動スナップショットなし）、または通常の`sudo pacman -Syu` / `yay -Sua`。Flatpak、開発用ランタイム、個別のhomeデータはルートスナップショットの対象外です。

Archの部分的なアップグレードは避けてください。予期しない削除を盲目的に受け入れるのではなく、パッケージのプロンプトをよく読んでください。成功したアップデートタスクは閉じますが、失敗したタスクは出力を失わずにトラブルシューティングできるよう表示されたままになります。

アップデートが成功した後、必要に応じて完了を促す通知が表示されます: カーネル、ファームウェア、マイクロコード、systemd、glibc、グラフィックスドライバー、またはディスク暗号化のアップデート後は**Restart now**、EITR、Hyprland、Quickshell、Walker、PipeWireなどのデスクトップのアップデート後は**Log out now**が表示されます。**Later**を選択して作業を続けることもでき、新しいバージョンは次回の再起動またはログイン時に有効になります。

## クリーンアップとスナップショット

Cleanupはメンテナンスワークフローを実行し、レポートを閲覧用に開いたままにします。提案された内容を確認してください。すべての孤児（orphan）パッケージを未使用として扱わないでください。Snapshotsは既存のSnapperのステータス/構成ワークフローを提供します。サポートされているレイアウトとブートローダーの制限については、[復元とスナップショット](handbook:recovery)をお読みください。

## 初期状態にリセット

初回ログイン時の復旧ポイントを持つサポート対象のディストリビューションインストールでのみリセットが可能です。そのプライベートなベースラインは、通常のSnapperリストやクリーンアップとは分離されています。root権限であれば削除可能であり、ディスク障害によって失われる可能性もあります。2つの個別警告と文字入力による確認が必要です。「すべて削除」と「個人用ファイルを保持」がそれぞれ何を保持するかについての詳細は、[初期状態にリセット](handbook:factory-reset)をお読みください。

## 電源

Main > PowerおよびControl Center > General（**Power…** の奥）には、Lock、Logout、Suspend、Reboot、Shutdownが用意されています。まず作業を保存してください。これらはシミュレーションではなく実際の操作です。

## パッケージミラー

Walker > Settings > System > Maintenanceで、Choose Fastest Mirrorsを選択します。ターミナルに変更内容の説明が表示されます。Enterで確定し、Escでキャンセルします。Reflectorは12時間以内に同期された最大10件のHTTPSミラーを選択し、ダウンロード速度順に並べ替えます。可能であればシステムタイムゾーンから特定された国を優先し、該当するミラーが少なすぎる場合は全世界のミラーを試行します。標準で提供される3つの全世界サーバーは常に末尾に残ります。ランキングに失敗した場合、カスタムミラーを含めリストは変更されません。Reflectorの各実行は最大2分に制限されています。

以前のリストは`/etc/pacman.d/mirrorlist`の横に`mirrorlist.eitr-<timestamp>.bak`として保存されます。バックアップが存在する場合、同じフローで復元が提案されます: `restore`と入力してEnterを押します。復元時にも現在のリストがバックアップされます。結果のリストはEscを押すまで表示されたままになります。

新規インストールでは、各起動の2分後にバックグラウンドで1回の試行がスケジュールされ、接続がある状態で最大3回まで試行されます。オフラインでの起動は通知なしでスキップされ、カウントされません。ランキングに成功すると、それ以降の試行は停止します。ログイン処理がランキングを待つことはありません。すべての試行が失敗した場合は、後でメニューアクションを実行してください。変更されるのはArchパッケージミラーのみであり、EitrおよびFlatpakのリポジトリには影響しません。

読み取り専用ステータス: `/usr/lib/eitr/eitr-system mirrors-status`は、`last_ranking_time`（UTC、成功前はnull）、`mirror_count`, `shipped_fallback`, `backup_available`を含むJSONを出力します。ステータス確認はネットワークアクセスやsudoを使用せずにローカルファイルを読み取ります。

System Updateは、最後に承認済みプラグインバージョンを変更することなく、プラグインの提供状況をチェックします。プラグインのアップデートの確認とインストールは、**Control Center > Plugins > Update Plugins**、**Install > Plugins > Update Plugins**、または`eitr plugin update`から個別に実行してください。オフライン時のチェック失敗は静かに無視されます。アップデート後フックは変更されません。

Settings > Updatesには保留中のパッケージアップデートが表示され、リストを更新できます。読み取り専用のヘルスチェックについては、[トラブルシューティング](handbook:troubleshooting)を参照してください。
