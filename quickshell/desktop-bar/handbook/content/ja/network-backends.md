# ネットワークバックエンド

設定 > 接続 > Wi-Fi > WiFi backend は、iwd（クリーンインストール時のデフォルト）または wpa_supplicant を使用する NetworkManager を選択します。どちらも DNS に systemd-resolved を使用します。共通の Wi-Fi パネルは、次回起動用に保存された選択ではなく、現在実行中のバックエンドを検出します。現在の接続が再起動されることはありません。root 所有のヘルパーがファイルを準備し、`--now` なしで起動サービスを有効化/無効化してから、再起動するかどうかを尋ねます。再起動を拒否した場合、その選択は次回の再起動まで保留されます。

保存された Wi-Fi プロファイルは、各バックエンド独自のストレージに残ります。削除されたり自動的に変換されたりすることはありません。最初の切り替え時には再接続してください。元のバックエンドに戻した場合は古いプロファイルが再利用されます。切り替える前に、カスタムの固定 IP、VPN、ブリッジ、networkd ファイル、またはその他のネットワークマネージャーを確認してください。マスクされたサービス、別のアクティブなマネージャー、またはカスタムリゾルバーが存在する場合、警告なしに置き換えるのではなく処理を拒否します。元の管理ファイルとサービスの有効化状態は `/var/lib/eitr/network-backend` の下に非公開で保存されます。「元のネットワーク構成を復元」を実行すると、現在のネットワークを停止することなく、次回起動時にそれらが復元されます。

`eitr-desktop` パッケージには両方のバックエンドと root 所有のヘルパー `/usr/lib/eitr/eitr-network` が含まれています。ヘルパーを手動でコピーするのではなく、パッケージをインストールしてください（ディストリビューションの README を参照）。以前に手動でインストールされたヘルパーがある場合、`distro/system/adopt-unowned-files.sh --apply` がそれをアーカイブするまでパッケージのインストールがブロックされます。ユーザーが書き込み可能なパスにあるヘルパーを昇格して実行しないでください。ヘルパーをインストールしただけでは、バックエンドは選択されません。

## エンタープライズWi-Fi

パネルは PEAP/MSCHAPv2 および TTLS/PAP をサポートしており、ユーザー名、任意の匿名ID、パスワード、認証サーバーのドメイン、および PEM 形式の CA 証明書パスを設定できます。これらの設定についてはネットワーク管理者にお問い合わせください。サーバー証明書の検証は必須です。EAP-TLS/クライアント証明書、SIM/AKA、その他の高度な認証方法は、引き続き外部でのプロビジョニングが必要です。これらの設定において Impala は引き続きオプションのフォールバックとして残されています。一般的な認証方法がサポートされていることだけを理由に Impala を削除しないでください。

認証情報はプロセスの標準入力（stdin）および D-Bus を介して渡され、コマンドライン引数として渡されることは決してありません。NetworkManager は通常の接続プロファイルを保存します。iwd のプロビジョニングでは PolicyKit 認証を使用し、CA が埋め込まれた root 所有の非公開 `.8021x` プロファイルを使用します。既存のエンタープライズプロファイルが上書きされることはありません。置き換える前にプロファイルを明示的に削除してください。root 所有かつグループ/その他のユーザーへの書き込み権限がないヘルパーのみが受け入れられます。自動テストでは実際のバックエンド切り替え、Wi-Fi 接続、エンタープライズ認証は実行されません。ハードウェア検証済みと説明する前に、予備のハードウェアまたは分離された VM 上で両方を検証してください。
