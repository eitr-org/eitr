# アプリとインストール

公式パッケージをインストールする前に、ターミナルには保留中のシステムアップデートを確認中であることが表示されます。この確認には、管理者パスワードが要求されるまでに少し時間がかかる場合があります。Flatpakのインストールでも準備段階が表示されます。アップデートが保留されている場合、その理由が説明されます。Archは最新のシステムにのみアプリをインストールし、今インストールを行うと復旧用スナップショットなしでシステムの一部がアップグレードされてしまうためです。Enterを押すとスナップショットを作成した上でシステムアップデートが実行され、その後にインストールが行われます。Escを押すと何も変更せずにキャンセルします。

**SUPER + Space**およびMain > Appsは同じアプリ一覧を開きます。Enterでアプリを起動します。AppsではDeleteキーを使用でき、アンインストールの確認が表示されます。**SUPER + F**からのグローバル検索はアプリを起動しますが、アンインストール操作は表示されません。個別のピン留めベースのアプリメニューはありません。

メインメニューで文字を入力すると、インストールされているアプリとすべてのサブメニューのアクションが検索されます。SystemやInstallなどのサブメニュー内で文字を入力すると、そのサブメニューおよびその下にあるすべての項目が検索されます。キーボードレイアウトやクラウドアカウントの下位項目（サービス、リソース、ログ）は、それぞれの専用メニュー内でのみ検索されます。クラウドアカウントの一覧自体は検索対象に残ります。

ライブメニューでは、インストールされているプラグインやGitアカウント内のアクションなど、読み込み済みの子アクションも検索されます。入力時にはメニューが読み込んだデータが再利用されます。別のプロバイダー読み込みが必要な選択肢を検索する場合は、リソースセレクターまたはVisualsを開いてください。サブメニューの行は末尾に**>**が表示されます。**Shift + Backspace**で親メニューに戻ります。

## デフォルトアプリの選択

Settings > Default appsを開くと、Webリンク、ファイル、テキスト、画像、動画、音楽、メール、PDFに対して、インストール済みのハンドラーを選択できます。ここでのターミナルの選択は、Appearance > Terminalと共有されます。音楽ファイルは、別のプレーヤーを選択しない限りDecibelsで開きます。GNOME Musicがインストールされている場合、自身のライブラリ内の曲のみを再生し、ファイルを直接開くことはできません。

## インストール

Installメニュー内の各一覧で、インストール済みの項目でDeleteを押すと、確認の後にアンインストールできます。Web Appsでも削除アクションが維持されます。パッケージ（PacmanおよびYay）では、Ctrl+Dで強調表示されているインストール済みパッケージを確認後に削除できます。Ctrl+Fでインストール済みパッケージのみとすべてのパッケージの表示を切り替えます。Eitrパッケージはインストールされたまま保持されます。必要なシステム依存関係が再帰的に削除されることはありません。pacmanは他のパッケージを壊すような削除を拒否します。

管理対象の言語バンドルを削除する場合、ターミナルに完全な削除警告が表示された後、[y/N]で確認が求められます。Enterを押すとキャンセルされます。Nodeの削除には、NVMで管理されているすべてのバージョンおよびグローバルnpmツールが含まれます。Pythonの削除はuvで管理されているバージョンとuv自体に影響し、システムPythonには影響しません。Javaは現在のSDKMAN JavaおよびMavenのバージョンを削除します。Rustは安定版（stable）ツールチェーンのみを削除します。RailsおよびLaravelはフレームワークツールを削除しますが、Ruby、PHP、Composerは保持します。プロジェクト、設定、認証情報は保持されますが、依存するツールや環境が動作しなくなる可能性があります。ネイティブアシスタントの削除では、キャッシュされたバージョンと設定が保持されます。

システム上にすでに存在するアプリは、名前の下に**Installed**と表示されます。これを選択すると、再インストールする代わりにその旨が表示されます。これは、SDKMANのJavaやNVMのNode.jsなど、独自のマネージャーでインストールされたツールも認識します。DBeaverのJavaのようにランタイムを必要とするパッケージは、提供するパッケージがまだ存在しない場合にのみ最小限のランタイムを導入します。

- **AI CLIs:** オプションのAIコマンドラインクライアント。
- **Browsers:** サポートされているブラウザの選択肢。
- **Databases:** DBeaver、データベースクライアント、Valkey（ArchがRedisの代わりに出荷しているRedis互換サーバー）などのオプションツール。
- **Development Languages:** オプションの言語ツールチェーン。Java/Flutterは必須のデスクトップ依存関係ではありません。
- **JavaScript Tools:** オプションのJavaScriptランタイムとツール。
- **Packages > Pacman**および**Packages > Yay (AUR):** 公式のArchパッケージまたはコミュニティAURパッケージを検索します。それぞれ提供元とインストール済みかどうかがラベル付けされています。検索欄が上部に、パッケージがその下に、選択したパッケージの詳細がさらに下に表示されます。**Ctrl+B**でビルドファイル（PKGBUILD）の表示と切り替え、**Ctrl+O**でブラウザでそのページを開き、**Tab**で複数選択し、**Enter**でインストールします。AURパッケージはビルドファイルに基づいてこのコンピューター上でビルドされるため、事前にビルドファイルを確認してください。これらは公式のArchパッケージではありません。

インストール、アップデート、セットアップのターミナルには、テーマに合わせたEITRバナーが表示されます。成功したタスクは通常自動的に閉じ、失敗した場合は表示されたままになります。クリーンアップなどのレポートは、内容を確認できるように開いたままになります。通常のターミナルやAboutにはタスクバナーは表示されません。

待機中のタスク、アカウント、レポート、Aboutのターミナルを閉じるには**Esc**を押します。Enterは、復旧キーの確認やインストーラーの電源オフなど、回答や確認のために使用されます。

公式パッケージを1つインストールするには`eitr package install NAME`、AURの場合は`eitr package install --aur NAME`、削除には`eitr package remove NAME`を使用します。ターミナルが必要です。テーマに沿った確認画面にパッケージと提供元が表示されます。Enterで確定し、Escでキャンセルします。AURの場合、Ctrl+Bでビルドファイルを閲覧でき（qで戻る）、Ctrl+Oでビルドリポジトリを開きます。コミュニティAURパッケージはEitrやArch Linuxによる検証を受けていません。すでにインストール済みのパッケージは正常終了します。失敗したタスクはEscを押すまで開いたままになります。プラグインでは`kitty --class eitr-menu-terminal -e eitr package install --aur lowfi`を使用できます。

## ツール

Apps内の**Calculator**（またはキーボードの電卓キー）を押すと、現在のテーマカラーでEitrの電卓が開きます。キー入力またはクリックが可能です: `+ − × ÷`、累乗の`^`、パーセントの`%`（`200×15%`）、`√`、括弧に対応しており、括弧の前の数値は掛け算として計算されます（`2(3+4)`）。Enterで結果を表示し、Backspaceで1文字削除、Escapeでクリア（2回押すと閉じる）、Ctrl+Cまたは**Copy**で結果をコピーします。コードとして実行するのではなく、数式自体を独自に解釈して計算します。

**オフライン音声入力**は、コンピューターの外部に音声データを送信しない音声認識機能です。**SUPER + D**を押したまま話して離すと、話した言語でカーソル位置に文字が入力されます。**SUPER + D**を一度押して話し、もう一度押すことでも入力できます。聞き取り中、時計の左隣にある赤いドットが音声に合わせて動く小さな波形に変わり、声が認識されていることを確認できます。離した後は文字が入力されるまで波形が点滅します。

初回使用時に、音声モデル（148 MB、公開チェックサムと照合済み）が`~/.local/share/eitr/whisper/`に一度だけダウンロードされます。その後はオフラインで動作します。音声を離してから文字変換されるまでに少し時間がかかります（古いプロセッサではより長くなります）。SUPERを先に離した場合でも、Dキーを離した時点、または120秒後に録音は停止し、通常通り文字に変換されます。

**Main > Tools > Reminders > New Reminder**では、通知する時間（`10m`や`1h30m`などの時間経過、または`18:30`のような時刻）とリマインダー内容を入力すると、指定した時刻にスヌーズボタンと閉じるボタンが付いた通知が表示されます。**Upcoming Reminders**には待機中のリマインダーが一覧表示され、選択してキャンセルできます。リマインダーは再起動後も保持され、PCの電源が切れている間に期限が到来したものは次回のログイン時に表示されます。ターミナルからは`eitr remind 25m お茶を取り出す`のように実行でき、`eitr remind`単体でリマインダー一覧が表示されます。

## ゲーム

Main > Gamingには**GeForce NOW**、**RetroArch**、**Steam**が並んでいます。選択すると、インストール済みの場合は起動し、そうでない場合はインストールされます。RetroArchはArchの公式パッケージから提供され、NES、SNES、ゲームボーイおよびゲームボーイアドバンス、メガドライブ/ジェネシス、PlayStation、NINTENDO64、ニンテンドーDS、PSP、ドリームキャストなどのクラシックゲーム機用コアが含まれます。独自のゲームや、ゲーム機に必要なBIOSファイルは各自で追加してください。Eitrはいずれも同梱していません。GeForce NOWはFlatpakからインストールされます。

**Quick Actions > Game Mode**は、プレイ中にデスクトップの干渉を抑えます。ウィンドウのアニメーション、ぼかし、影がオフになり、通知ポップアップが保留され（応答不可モード）、対応しているコンピューターでは電源プロファイルがパフォーマンスに切り替わります。オフにすると、変更された設定が元の状態に復元されます。Steamは**GameMode**および**MangoHud**とともにインストールされます。ゲーム中のCPUパフォーマンスを高め、FPSオーバーレイを表示するには、Steamのゲーム起動オプションに`gamemoderun mangohud %command%`を追加してください。

LocalSendのパッケージ版アプリには必要なランタイムが含まれており、実行のためだけにFlutter SDKを用意する必要はありません。開発者ツールはオプションのままです。

アップグレードには[アップデートとクリーンアップ](handbook:maintenance)を使用してください。単一パッケージのインストールは、スナップショットで保護されたシステムアップデートワークフローとは異なります。

Main > Tools > FunにはMusic VisualizerとRune Rainがあります。

**Music Visualizer**は、テーマカラーでcavaを開きます。メディアのイコライザーを右クリックしても同じビジュアライザーが開きます（左クリックは従来通りメディアの詳細を開きます）。**q**または**Esc**を押すと閉じます。既存のデスクトップ環境でcavaパッケージが存在しない場合は、初回起動時にまずインストールされます。

**Rune Rain**は、エルダーフサルクのルーン文字がテーマカラーで画面いっぱいに降り注ぎ、時折「ᛖᛁᛏᚱ」と綴られます。いずれかのキーを押すと終了します。ターミナル内では`eitr matrix`でその場で実行でき、`--speed slow|normal|fast`および`--seconds N`で速度や表示時間を変更できます。

接続されたモニターがHDR対応を報告している場合、EitrはSteam ProtonゲームのデフォルトをWaylandおよびHDRに設定します（`PROTON_ENABLE_WAYLAND=1`、`PROTON_ENABLE_HDR=1`、`DXVK_HDR=1`）。HDRモニターを持たないマシンの場合、既存のデフォルト設定が維持されます。ディスプレイが一覧表示されたり変更されたりした際、およびログイン時や再読み込み時にその設定が読み込まれる前に、ハードウェア検出によって生成されたディスプレイ構成が更新されます。

変更されたデフォルト設定を反映するには、新しいデスクトップセッションを開始してSteamを再起動してください。実行中のSteamプロセスは起動時の環境を保持します。ゲーム自体でHDRを有効にしてください。全画面ゲームは、デスクトップのHDRがオフの場合でもモニターを自動的に切り替えることができます。Waylandモードでは一部のゲームでSteamオーバーレイが表示されなくなる場合があります。特定のゲームでこれを無効化するには、Steamの起動オプションを`PROTON_ENABLE_WAYLAND=0 %command%`に設定してください。

ゲームのキャリブレーションを行うには、仕様表からモニターのHDRピーク輝度に合わせてゲームの最大輝度またはピーク輝度を設定し（DisplayHDR 400モニターの場合は約400 nit）、好みに応じてペーパーホワイトまたは全体の明るさを調整します。ハイライトのディテールが失われる場合はピーク輝度を下げ、画面が暗く見える場合はペーパーホワイトを上げてください。

ブラウザは、モニターでデスクトップHDRがオンになっている場合にのみHDRを使用し、自動的にオンに切り替えることはありません。全画面HDRゲームは、デスクトップHDRがオフの場合でも自動的に切り替わります。ブラウザでのHDR再生は、ブラウザの対応状況や設定にも依存します。

## 音声リマインダー

**SUPER + Shift + D**を押したまま話して離すか、Main > Tools > Reminders > Tell the assistant…を開いて文字を入力します。Eitrは音声入力と同じオフラインモデルを使用してローカルで音声をテキストに変換し、Development > AI > Default Assistantにリクエストの解釈を依頼します。アシスタントのプロバイダーに送信されるのは文字起こし結果とリマインダーのコンテキストのみです。音声データはローカルに留まり、文字起こし後に削除されます。

アシスタントはEitrの読み取り専用パスを介してヘッドレスで実行されます。EitrがJSONを検証し、リマインダーアクション自体を実行するため、アシスタントに変更用のツール権限を与えることはありません。Ratatoskr（Development > AI > Default Assistant）を使用する場合、文字起こし結果がこのPCから外部に出ることは一切ありません。

「明日15時に電話するようリマインドして」や「10月30日15時に歯医者、30分前に通知」のように伝えます。予定はデフォルトで1時間前（または指定した事前時間）と開始時刻に通知されます。通常のリマインダーは指定時刻に通知されます。時刻のない日付を指定すると、どのアシスタントでも時計が開きます。詳細の不足や曖昧さがある場合は、番号付きの完全な選択肢がターミナルに表示されます。番号または独自の回答を入力するか、SUPER + Dで音声入力してください。Escでキャンセルします。結果は通知で報告されます。リマインダーの一覧表示やキャンセルを依頼することもできます。

New Reminderでは`tomorrow 15:00`、曜日名、`2026-10-30 09:00`、`Oct 30 15:00`、`9am`、`in 5 minutes`、`every 29th`も受け付けます。CLIでは複数単語の日時をクォートで囲んでください。各アラートには独自のタイマーがあり、キャンセルするとすべてのアラートが削除されます。見逃したアラートは次回のログイン時に表示されます。文字入力または音声で時刻を指定しない日付を入力すると、小さな時計が開きます。HH:MMフィールドに24時間形式で時刻を入力します。Backspaceで最後の桁を削除し、矢印キーで時間や分を調整できます。Enterで時刻を設定し、Escでキャンセルします。

リマインダーのアラートでは、応答不可モード中を除き短い音が鳴ります。カレンダーには予定がある日がマークされます。日付をクリックすると、その日のリマインダー時刻とタイトルが即座に更新されて表示されます。一覧表示された各リマインダーにはゴミ箱ボタンがあります。1回限りのリマインダーを削除するには2回クリックし、繰り返しの場合は「This one」（次回の予定のみ）または「All」（すべて）を選択します。

Escapeキーを押すか、別の場所をクリックするか、数秒間入力を行わないとリマインダーが保持されます。

繰り返しリマインダーは`every day 08:00`、`every Monday 09:30`、`weekdays 07:00`、`every Monday and Thursday 09:30`、`every week`、`every month on the 15th`、`every year`（時刻指定付き）を受け付けます。CLIでは`eitr remind "every day 08:00" ストレッチ`のようにフレーズ全体をクォートで囲みます。アシスタントは間隔、終了日、発生回数の指定にも対応しています。31日などの月ごとの日付やうるう年の2月29日は、その月の最終日に自動調整されます。現地の時計時刻と相対アラートは保持されます。

タイマーが設定されるのは次回の発生分のみです。電源が切れていた後は、見逃した分が1回表示され、経過した分はスキップされて上限回数にカウントされます。Upcoming Remindersには次回の時刻とルールが表示されます。キャンセルするには「This occurrence」（今回の発生分）または「All future occurrences」（今後のすべての発生分）を選択します。CLIでは`eitr remind cancel ID occurrence`または`eitr remind cancel ID series`を使用します。カレンダーでは発生日のある日にドット、繰り返し項目には↻が表示され、カレンダーの高さは固定されたまま維持されます。

見逃したアラートを含むリマインダー通知では、ポップアップおよび通知履歴で**Snooze 5 min**、**Snooze 10 min**、**Snooze 1 hour**、**Dismiss**が提供されます。スヌーズを選択すると、クリックした時刻から同じテキストの1回限りのリマインダーが別途スケジュールされます。繰り返しリマインダーの本来のスケジュールは維持されます。Dismissを選択するとアラートを閉じます。アクションは最大24時間利用可能で、その後通知は期限切れになります。

**Main > Tools > Reminders > Calendar Sources > Add Calendar…**を使用すると、ログインすることなく読み取り専用で、Google、Outlook、またはその他のiCalカレンダーをカレンダーパネルに表示できます。プロバイダーを選択します: GoogleおよびOutlookの場合はブラウザで設定画面が開きます。Googleでは「マイカレンダーの設定」>「カレンダーの統合」>「iCal形式の非公開URL」をコピーします。Outlookでは「設定」>「カレンダー」>「共有カレンダー」でカレンダーを公開し、そのICSリンクをコピーします。

アドレス（`https://`または`webcal://`）を貼り付け、カレンダーに名前を付けます。そのアドレスを知っている人なら誰でもカレンダーを閲覧できるため、Eitrはそれを秘密ファイルに保存し、メニュー、通知、ログに表示することはありません。漏洩した場合はプロバイダー側で秘密アドレスを再発行してください。カレンダーはログイン時、15分ごと、およびカレンダーパネルを開いたとき（最大で毎分1回）に更新されます。

先週から今後60日間のイベントが、ゴミ箱ボタンなしでカレンダー名とともにリマインダーの隣に表示されます: 編集はGoogleまたはOutlookで行ってください。時刻指定のあるイベントは、開始時にリマインダー音とともにアラートが鳴ります。終日イベントではアラートは鳴りません。日ごと、週ごと、月ごと（日付の数値、または「最終金曜日」などの曜日）、年ごとの繰り返しが表示されます。より稀なルールの場合は初回イベントのみが表示されます。

Calendar Sourcesメニューでは、カレンダー上でEnterを押すと即座に更新され、確認後にDeleteで削除できます。双方向同期（プロバイダーイベントの作成や編集）には対応していません。ブラウザでリンクをコピーしている間ターミナルは開いたままになります。確認画面でEnterを押すと追加され、Escでキャンセルします。

## プラグイン

プラグインは、スクリプト、Walkerの行、オプションのビジュアルコンポーネント（タイル、パネル、デスクトップウィジェット、バー項目）、およびオプションで1つのユーザーサービスを含むGitリポジトリです。1つのリポジトリに複数のプラグインを含めることができます。プラグインはユーザー自身のアカウントの完全な権限で実行されます: ファイル、SSHキー、ブラウザデータの読み取り、それらを外部へ送信すること、自身のバックグラウンド実行を継続させることが可能です。

Eitrはそのコードを事前審査していません。コードは作者に帰属し、Eitrに帰属するものではありません。各プラグインの行にも「Plugin by Ada · not reviewed by Eitr」のように明記されています。信頼できる人物およびリポジトリのプラグインのみを追加してください。

プラグインは`packages`を宣言できます: 有効なArch公式リポジトリまたは`[eitr]`から、最大32個の一意のプレーンパッケージ名を指定できます。AUR、URL、ローカルファイルは指定できません。確認画面には、すでにインストールされているパッケージと不足しているパッケージが一覧表示されます。不明なパッケージがある場合、インストールは拒否されます。承認後、Eitrはシステムのpolkitダイアログを介して管理者パスワードを要求し、不足しているパッケージのみをインストールします。パッケージを追加するアップデートでも同様に確認が必要です。削除時には、プラグインのためにインストールされたパッケージで他に使用されていない依存関係になっているものをオプションでクリーンアップできます。明示的にインストールされたパッケージや他のプラグインに必要なパッケージは保持されます。

Main > Install > Plugins > Add Pluginsでは、HTTPSのGit URL、またはプライベートリポジトリ用の`git@github.com:you/plugin.git`のようなSSH URLを要求します（ssh-agent経由でSSHキーが使用されます）。追加には2回の確認があり、いずれもデフォルトは「No」です。まず、何もダウンロードされる前にセキュリティページでこれらのリスクが説明されます。Enterを押すと、確認用のプラグインがダウンロードされます。

次に、信頼に関する警告およびその他の警告（すべてのログイン時に開始されるバックグラウンドサービス、バイナリファイル）から始まる確認画面が表示され、マニフェストの作者、リポジトリ、正確なコミット、Git作者および日付、バージョン、実行可能ファイルの数、メニュー行が表示されます。Enterを押すとインストールされ、いずれのステップでもEscでキャンセルできます。

承認されるまで、プラグインのいかなる部分も実行されません。`eitr plugin add URL`でも同じ2つの質問が表示され（Enterで続行、Escでキャンセル）、ターミナルがない環境での実行は拒否されます。Main > Install > Plugins > Installed Pluginsにはインストール済みプラグインのフォルダが一覧表示されます。インストールされた各プラグインには、そのアクション、ビジュアル、削除、利用可能なアップデート用のフォルダが用意されています。

インストール確認画面でAを押すと、デフォルトのアシスタントにツール権限を与えずに、リポジトリの一時コピーをテキストとして検査させることができます。RatatoskrとClaudeがプラグインの検査に対応しています。非対応のデフォルトアシスタントが設定されている場合は、確認画面でその旨が表示されます。Claudeはテキストをプロバイダーに送信しますが、RatatoskrはこのPC内に保持します。

レポートはPgUp/PgDnでスクロールできます。AIが見落とす可能性もあります: これは助言であり承認ではなく、完全な権限に関する警告は引き続き適用されます。検査の実行中を含め、Enterでインストール、Escでキャンセルできます。エラー、空の回答、180秒のタイムアウトが発生した場合でも、通常の確認画面を利用できます。自動的にインストールされることはありません。カタログはデータのみのGitテーマパッケージにも対応しています。

Eitr Storeカタログを使用すると、ターミナルを開かずにプラグインをインストールおよびアップデートすることもできます。「Official」および「Community」カードを開くと、画像、動画、コンポーネント情報を含む詳細が表示され、「Install」でネイティブのコミット確認画面が開きます。Installed > Add from a Git addressではHTTPSまたはSSHを受け付けます。確認にはファイル、コマンド、QMLソース、作者、アップデートの変更点が含まれ、オプションでテキストのみのAIアドバイスも利用できます。

Enterで確定し、Escapeでキャンセルします。ステージングされた候補は、審査された正確なコミットと照合されます。Communityではインデックスの固定バージョン（pin）が使用されます。トークンは15分後に期限切れとなり、カタログを閉じると破棄されます。動画はミュート状態で開始され、閉じると停止します。

システムアップデートは、システムパッケージが最新の場合でも新しいプラグインコミットの確認のみを行い、件数とアップデート場所を表示します。プラグインの審査やアップデート自体を行うことは決してありません。ネットワークエラーは自動的に無視されます。**Control Center > Plugins**（Add Pluginsの隣）または**Plugins > Update Plugins**から**Update Plugins**を実行するか、`eitr plugin update`を使用してください。

Update Pluginsボタンおよびメニュー行は、前回の確認でアップデートが見つかった場合にのみ表示されます。プラグイン行の小さな↑マークと詳細画面の「Update available」は、承認されたコミットに対する前回の確認結果を反映しています。個別の更新アクションにより、既存のプラグインごとの差分、リスクフラグ、確認プロセスが維持されます。

各アップデートは概要から始まります: 新旧のコミット、コミットの件名、追加・削除された行数を含む変更ファイル、およびリスクフラグ（バックグラウンドサービスの追加・変更・削除、マニフェストの変更、新規または変更された実行可能ファイル、バイナリファイル、承認済みコミットの作者とは異なる作者によるコミット）が表示されます。

`d`を押すとページャー（`delta`がインストールされている場合はdelta、そうでない場合は`less -R`）で完全な差分を確認でき、Enterでアップデート、Escで現在のバージョンを維持します。履歴が書き換えられ、承認済みコミットが新しいコミットに含まれなくなった場合、Eitrは自動アップデートを行わず、その理由を説明します。引き続き信頼できる場合は、プラグインを一度削除して再度追加してください。

非対話型アップデートではプラグインはスキップされます。Plugins > Installed Plugins > 対象のプラグインでUpdateおよびRemoveが提供されます。削除時には確認が求められ、ファイル、行、サービスが削除されます。同じフローは`eitr plugin list`、`eitr plugin add URL`、`eitr plugin update [ID]`、`eitr plugin remove ID`からも利用できます。

Eitrは、署名された`eitr-desktop`パッケージ内にプラグインブロックリストを同梱しているため、pacmanのパッケージ署名によって保護されています。各エントリには、リポジトリ、コミット、またはプラグインIDと、その理由が記載されています。ブロックされたプラグインの追加やアップデートは拒否されます。すでにインストールされているプラグインがブロックされた場合、その動作は停止します: Plugins > Installed Pluginsから行が削除され、起動できなくなり、サービスは停止および無効化され、理由とRemoveボタンを含む通知が1回表示されます。

Plugins > Installed Pluginsではブロック対象としてマークされ、選択すると削除されます。ファイルが自動的に削除されることはありません。悪意のあるプラグインを報告するには、`https://github.com/eitr-org/eitr/issues/new?template=malicious-plugin.yml`を開いてください。パスワード、トークン、キーをレポートに貼り付けないでください。組織プロファイルを使用してプラグインを無効化したり、許可されたリポジトリのみに制限したりすることもできます（組織プロファイルを参照）。

プラグインは`$XDG_DATA_HOME/eitr/plugins/<id>/`（デフォルトは`~/.local/share/eitr/plugins/`）にのみ保存されます。承認情報は`$XDG_STATE_HOME/eitr/plugins.json`に保存されます。サービスは`NoNewPrivileges=yes`を指定した`$XDG_CONFIG_HOME/systemd/user/eitr-plugin-<id>.service`を使用するため、sudoなどのプログラムを介して権限を昇格することはできません。絶対にsudoを使用しないでください。アップデート時は別の候補を検証し、拒否または失敗した場合は以前の承認済みコミットを保持します。プラグインは実行中にファイルを変更する可能性があり、削除してもそれらの変更を元に戻すことはできません。

### マニフェストリファレンス

バージョン1: リポジトリのルートには`eitr-plugin.json`が含まれます。受け付けられるキーは以下のみです: `id`（単一のハイフンで区切られた英小文字/数字）、`name`, `description`（最大72文字）、`author`, `version`, `rows`（1〜20個。`ui`を宣言している場合は0〜20個）、およびオプションの`service`, `schemaVersion`, `packages`, `hooks`。各行には`title`, `description`（いずれも最大72文字）、`run`が必要です。オプションのキーは`icon`および`arguments`（固定文字列の配列）です。

サービスは`run`およびオプションの`arguments`のみを受け付けます。コマンドはargvを使用し、シェルの文字列は使用しません。`run`はリポジトリ内の実行可能ファイルを指定する必要があり、絶対パスや`..`は拒否されます。また、プラグイン内のあらゆる場所のシンボリックリンクも拒否されます。不明または重複したJSONキーは拒否されます。サブモジュールは初期化されません。

`distro/plugins/example/`にある最小限のサンプルには、マニフェストと`notify.sh`、1つの通知アクション、テーマフックが含まれ、サービスはありません。これを自身のGitリポジトリにコピーしてコミットし、HTTPSのGit URLを公開することで、完全なインストールフローを試すことができます。このサンプルはドキュメントとして提供されており、自動的にインストールされることはありません。ビジュアルプラグインについては、`https://github.com/eitr-org/eitr-plugins`の公式コレクションにVisualizerが用意されています。

スクリプトのみのマニフェストの場合は`schemaVersion: 1`を宣言し、後述のオプションの`ui`セクションを使用する場合は`schemaVersion: 2`を宣言します。バージョンのない古いマニフェストも確認画面で通知された上でv1として動作します。バージョン2を超える場合は、より新しいEitrが必要です。作成者向けガイド`distro/PLUGINS.md`（パッケージ版では`PLUGINS.md`）で、安定したバージョン1の仕様が定義されています。

プラグインは`theme-changed`、`wallpaper-changed`、`after-update`、`login`の各フックを宣言できます。これらはアクション後にバックグラウンドで実行され（loginはデスクトップセッションごとに1回）、30秒のタイムアウトが設定されています。失敗は`$XDG_STATE_HOME/eitr/plugin-hooks.log`に記録され、アクション自体が失敗することはありません。確認画面にはフックが一覧表示され、フックの追加や変更はアップデート時にRISKフラグを発生させます。ブロックリストや組織ポリシーはフックにも適用されます。

### ビジュアルプラグイン

スキーマバージョン2では、**Control Center > General > Plugins**にタイルを追加し、それらのタイルから開くパネルを追加できます。これらはEitrの色、フォント、角の丸みに従うことができます。バー項目はプラグインのインストール時にバーに配置され、ウィジェットは追加後に表示されます。インストール前にすべてのQMLファイルとその完全なソースコードが確認画面に表示されます。アップデート時は承認前にスクロール可能な差分と候補QMLが表示され、QMLの変更はRISKフラグを発生させます。QMLはサンドボックスではありません: バー内部でユーザーの完全な権限で実行されます。作者を信頼してください。ループやネイティブのクラッシュをローダーで隔離することはできません。

コンポーネントの読み込みエラーが発生すると、コンテンツの代わりにインラインエラーが表示され、`$XDG_STATE_HOME/eitr/plugin-ui.log`に記録されます。読み込みエラーまたは報告されたエラーが3回発生すると、アップデートをまたいでもそのプラグインのビジュアルコンポーネントは無効化されます。Control Center > Pluginsで**Re-enable**を選択するか、`eitr plugin enable-ui ID`を実行してください。しきい値に達する前であれば、Generalを一度閉じて再度開くことで再試行できます。

行、フック、サービスは独立しています。プラグインは既存のGeneralセクションの後に表示されます。パネルを開くと、タイトルと戻るシェブロンが表示されてタイルが置き換わります。「Back」またはEscapeを押すとタイルに戻り、もう一度Escapeを押すとControl Centerが閉じます。縦に長いパネルはサブビュー内でスクロールします。スキーマv2のサンプルには、Helloタイルとステータスパネルが含まれています。

スキーマv1プラグインも変更なく引き続きサポートされます。作成の詳細および最小限のスタイル/データAPIについては`distro/PLUGINS.md`に記載されています。このAPIはサポートされたインターフェースであり、セキュリティ境界ではありません。

### プラグインマネージャーとウィジェットオプション

**Control Center > Plugins**には、インストールされているすべてのプラグインがアイコン、作者、バージョン、説明、有効化ステータスとともに一覧表示されます。「Preview」を展開するとスクリーンショットが表示されます。有効化/無効化を切り替えても配置は保持され、サービス、Walkerの行、フック、ビジュアルの停止または復元が行われます。CLIでは`eitr plugin enable ID`または`eitr plugin disable ID`を使用します。「Add Plugins」、「Update」、「Remove」を押すと、審査付きのターミナルフローが開きます。削除時には確認が求められます。Generalにはプラグインのタイルのみが保持されます。ビジュアルの障害には独立した「Re-enable」アクションが用意されています。

ディスプレイにはウィジェットを何度でも自由に追加できます: 各コピーは独自のディスプレイ、位置、サイズ、回転、設定を保持します。複数のディスプレイがある場合、追加時にどのディスプレイに配置するかを尋ねられ、フォーカスされているディスプレイが先頭に表示されます。削除するとバー項目が非表示になり、アップデート後も非表示のまま維持されます。「Edit position」を行うと、一時的にそのコピーがウィンドウの手前に表示されます: タイトルまたはサイズ変更グリップをドラッグし、「Done」またはEscapeを押します。移動は滑らかに行われ、離すとデスクトップの間隔にスナップして保存されます。Pluginsページ内の各コピーのカード、および右クリックメニュー（ウィンドウの背面にあるウィジェット、または編集モード中の任意のウィジェット上）では、同じ設定が提供されます: 位置の編集（Edit position）、複製（Duplicate: ディスプレイの左上に新しいコピーを作成）、サイズ変更ステップ（縦横比と中心を画面内に保持したまま90% / 110%に変更）、全幅（Full width）、回転（Rotation: 3°以内で直角にスナップするスライダー、45°回転、リセット）、ディスプレイ（Display: 移動してもサイズと設定を維持）、パネル/透明背景（Panel/Transparent background）、ウィンドウの手前に表示（Show above windows）、プラグインオプション、デスクトップから削除（Remove from desktop）。

全幅を選択すると、同じ縦横比を維持したまま最大のサイズに調整されます。ウィンドウの手前に表示されたウィジェットはクリックが透過します。Pluginsページ内のオプションを使用してください。そのページまたはWalkerのVisualsでウィジェットの編集を行うと、「Done」またはEscapeを押すまで、すべてのウィジェットが対話可能に切り替わります（`plugin-widgets edit` / `done` IPC）。見つからないモニターがある場合でも、保存された配置は保持されます。

透明背景では、ホストの色、枠線、ぼかしがなくなり、編集用ハンドルのみが表示されます。新しいスキーマv2プラグインには正方形のPNG/SVGアイコンが必要です（最大512 KiB、PNGは64〜1024 px）。オプションのプレビューはPNG/JPEGで最大2 MiB、各軸最大3840 px、ホームページはHTTPSである必要があります。既存のアイコンのないプラグインには汎用アイコンと確認用の注記が使用されます。作者向けAPIには、Wave/Barsなどのオプション用に`api.setMenu([{id, text, checked, group}])`および`api.menuTriggered(id)`が追加されています。検証およびAPIの詳細については`distro/PLUGINS.md`を参照してください。

スキーマv2プラグインは`audio-spectrum`を要求できます。確認画面には、システムオーディオレベルのみを読み取ることが明記されます: 音声が録音または送信されることはなく、ホストがマイクをキャプチャすることもありません。この機能を追加するとRISKフラグが発生します。表示されているすべての利用者は1つの再生スペクトラムプロバイダーを共有します。プラグインは8〜128本のバーと最大毎秒60フレームを要求できます。

利用者が表示されていないときは停止します。宣言された`dataStream`コマンドは、そのコンポーネントが表示されている間にリアルタイムのテキスト行を配信し、毎秒60行、1行あたり4096バイトに制限されます。確認画面にこれが一覧表示され、変更はRISKフラグを発生させます。非表示のコンポーネントはそのストリームと子プロセスグループを停止します。障害発生時はバックオフ付きで再試行されます。

作成の詳細については`distro/PLUGINS.md`に記載されています。

プラグインの作者は、独自の色、画像、シェーダー、アニメーションを選択できます。テーマヘルパー（`api.palette`、color0〜15、名前付きロール、フォント、サイズ、角の丸み、`themeChanged`）はオプションです。ウィジェットおよびパネルのデフォルトは`surface: "none"`で、`"panel"`を指定するとEitrの背景が適用されます。明示的に保存されたウィジェットの背景設定はマニフェストの宣言よりも優先されます。それ以外の場合は宣言が適用されます。Control Centerは外側のページフレームを維持し、プラグインキャンバスの内部に余計な装飾を追加しません。

パネルは`header: false`が指定されていない限りナビゲーションヘッダーを保持し、Back/Escapeは引き続き機能します。タイルはデフォルトで`look: "eitr"`となり、`"custom"`を指定するとホストのアクティベーションとフォーカスリングのみを持つ固定スロット全体が描画されます。バースロットにはホバー時の塗りつぶしや色合いは追加されません。相対パスのQML画像はプラグインディレクトリ内で解決されます。境界、中央配置の時計、確認プロセス、機能、障害処理は従来通り維持されます。

サンプルでは両方のタイルのスタイルが実演されています。

## キーバインドとウィンドウルール

設定 > キーバインドでアクションやキーを検索し、編集を選んで組み合わせを押します。
Escape はキャンセル、Backspace は確認後に無効化します。競合時は交換かキャンセルを選びます。
変更した行には既定値とリセットが表示され、すべてリセットで既定値に戻ります。
SUPER + M（ロック）と D / SUPER + D / SUPER + SHIFT + D（音声入力の終了）は予約済みです。マウス操作は変わりません。
学習 > ショートカットには有効なキーが、ハンドブックの表には既定値が表示されます。

設定 > ウィンドウルールで、開いているウィンドウやクラスが分かるインストール済みアプリに
ルールを追加できます。アプリを選び、フローティング、ワークスペース（1–10、`name:NAME`
または `special:NAME`）、サイズ（正のピクセル値2つ、または100%以下の割合）、不透明度
（0.2–1.0）を指定します。クラスと任意のタイトルは完全一致です。編集で変更し、削除は確認が
必要です。個人ルールは Eitr のルールの後に適用されます。初期位置の確認にはアプリを開き直してください。

設定はこの PC の `~/.config/eitr/keybinds.json` と `window-rules.json`（または
`$XDG_CONFIG_HOME/eitr`）に保存されます。ヘルパーは `hypr/keybinds.lua` と
`hypr/window-rules.lua` を生成し、変更ごとに Hyprland を再読み込みします。更新でも保持されます。
Lua がない場合や壊れている場合は既定値を使います。変更をすべて削除すると生成ファイルも削除されます。
