# 組織プロファイル

公式ISOを変更せずに使用してください。`EITRANSWERS`というラベルが付いたFAT32 USBメモリに、`eitr-answers.json`の横または代わりに`eitr-profile.json`を配置します。プロファイルのみの場合、通常のウィザードの確認（Review）画面に変更内容が含まれます。両方のファイルがある場合、インストーラーは15秒のカウントダウンの前にディスク操作とすべてのプロファイルの変更を一覧表示します。Ctrl+Cを押すとディスク変更の前にキャンセルされます。電源を切るまでUSBメモリを接続したままにしてください。

完全な例（すべてのサンプルダイジェストを`sha256sum`からの実際の小文字SHA-256に置き換えてください。これらのファイルをUSBメモリにコピーします）:

```json
{
  "version": 1,
  "name": "Example office",
  "remove": ["steam", "moonlight-qt", "eitr-sunshine", "tailscale"],
  "add": {
    "recipes": ["productivity/libreoffice"],
    "packages": ["chromium"],
    "flathub": ["us.zoom.Zoom"],
    "files": [{"file": "packages/office-tools-1-1-any.pkg.tar.zst", "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}]
  },
  "defaults": {
    "theme": "eitr",
    "wallpaper": {"file": "office.png", "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"},
    "browser": "chromium",
    "update_channel": "stable",
    "repository": {
      "name": "office",
      "server": "https://packages.example.org/$arch",
      "key": {"file": "office-key.asc", "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}
    }
  },
  "setup": {"file": "setup.sh", "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"},
  "policies": {"remote_access": false, "assistants_together": false, "update_channel": "stable", "gaming": false}
}
```

必須項目は`version`と`name`のみです。未知のJSONキーや重複したキーはエラーとなります。不要なオプションセクションは削除してください。パスはUSBメモリからの相対パスであり、シンボリックリンク、親ディレクトリへの移動（`..`）、絶対パスは使用できません。参照されているすべてのファイルが存在し、インストーラーがいずれかのディスクを変更する前にチェックサムと一致している必要があります。壁紙ファイルはPNG、JPEG、WebPとしてデコードできる必要があります。リポジトリキーには正確に1つのOpenPGP公開鍵が含まれている必要があります。HTTPSサーバーに認証情報を含めることはできません。そのキーはpacmanのキーリングに追加されてローカルで信頼されます。信頼できる組織キーのみを使用してください。パッケージアーカイブおよびセットアップスクリプトは信頼された管理者コードであり、サンドボックス化されていません。

`remove`は検証済みの`distro/removable-apps.json`許可リストのみを受け入れます。各項目の検証内容は`distro/PROFILE-PACKAGE-REVIEW.md`にあります。保護されたパッケージや未知のパッケージが含まれている場合はプロファイル全体が拒絶されます。pacmanが依存関係をチェックし、削除において再帰的削除や依存関係のオーバーライドが使用されることは決してありません。グループポリシーは、そのグループ内のすべての許可リスト登録パッケージを除外します: `gaming`、`media`、`development`、`sharing`、`remote_access`。`true`は機能を許可し、`false`は無効化します。`update_channel`ポリシーは`"stable"`のみを受け入れます。省略されたポリシーには制限がありません。

`plugins`は、プラグインメニューを非表示にしてプラグインの追加、更新、起動を拒否する`false`、またはそれらのリポジトリのみを許可する`{"allow": ["https://git.example.org/team/tools.git", "git@github.com:team/plugin.git"]}`を受け入れます。許可リストのエントリはHTTPSまたはSSHのURLであり、スキーム、ユーザー、ポート、`.git`サフィックス、末尾のスラッシュ、大文字・小文字に関係なく一致します。`~/.ssh/config`からのSSHホストエイリアスは記載どおりにリストする必要があります。インストール済みのマシンにこのようなポリシーを適用すると、許可されなくなったプラグインのサービスが停止および無効化され、それらのファイルは保持されます。

レシピは`distro/software.json`の`group/name`を使用します。ビルド済みのpacmanおよびFlatpakレシピのみが受け入れられます。AURおよび対話型のマネージド/Webアプリレシピは拒絶されます。代わりに検証済みのビルド済みパッケージファイルを提供してください。リポジトリパッケージ、レシピ、Flathubの追加にはインターネットが必要です。依存関係がすでにISO上に存在するかUSBメモリ上でも提供されている場合、USBメモリのパッケージはオフラインでインストールされます。チェック時にpacmanの現在の同期データベースでパッケージ名が利用可能である必要があります。オンライン追加をチェックする前に、通常のアップデートワークフローでデータベースを更新してください。インストール中にAURビルドが実行されることはありません。オンラインでのpacman追加には完全なアップグレードが使用され、部分的なアップグレードが使用されることは決してありません。追加のリポジトリは将来のアップデート用に構成されます。そこでのみ利用可能なパッケージは、インストール用のUSBメモリファイルとして提供する必要があります。

インストール中、FlathubアプリとFlatpakレシピはデスクトップユーザー用にキューに入れられ、ネットワーク接続を伴う初回起動時にインストールされます。失敗したインストールは次回の起動時に再試行されます。インストール済みのマシンにプロファイルを適用すると、それらは直接インストールされます。

ブラウザのデフォルトはFirefoxとChromiumをサポートしています。Chromiumも追加する必要があります。テーマと壁紙のデフォルトは、選択したデスクトップユーザーの次回のログイン用に保存されます。プロファイルの適用によってユーザーのデスクトップが再起動することはありません。追加リポジトリとアップデートチャンネルはシステム全体に適用されます。`setup`はプロファイルが記録された後、ステージングされたUSBメモリディレクトリを作業ディレクトリとしてroot権限で実行されます。開始前にSHA-256マーカーによってその試行が記録されるため、失敗または中断されたスクリプトが通知なしに再実行されることはありません。スクリプト（およびそのダイジェスト）を変更して別の試行を承認してください。スクリプトの出力と失敗は表示されたままになります。インストールに失敗しても完了したパッケージトランザクションがロールバックされることはありません。

インストール済みのマシンでは:

```sh
eitr profile check /run/media/alex/EITRANSWERS
eitr profile apply /run/media/alex/EITRANSWERS
```

`check`はファイルとパッケージのメタデータを読み取り、一時的な検証ディレクトリを使用します。システム構成は何も変更されません。`apply`は明示的なroot所有の`eitr-system profile-apply`アクションを使用し、プライベートにUSBメモリをステージングして再チェックし、同様の要約を表示した上で、`APPLY PROFILE`と入力することを要求します。キャンセルしても何も変更されません。pacmanを通じてインストール済みの除外パッケージを削除し、追加パッケージをインストールし、デフォルト設定を保存し、root所有の`/etc/eitr/policies.json`（0644、root:root）を書き込み、`/etc/eitr/profile.json`を記録します。別のプロファイルを適用すると記録された選択肢が置き換えられます。以前に削除されたアプリが自動的に再インストールされたり、省略された設定がリセットされたりすることはありません。セットアップマーカーはプロファイルの置き換えをまたいで保持されます。

記録された除外設定は手動インストーラーのマニフェストをフィルタリングします。pacmanのオプションに含まれる`IgnorePkg`インクルードによって、System Updateが除外されたパッケージを依存関係として再度引き込むことも防止されます。そのような依存関係の競合が発生した場合はアップグレードを停止する必要があります。ユーザー設定のシードによってアプリケーションがインストールされることはありません。ポリシーはElephantのメニュー/検索行、Remote Accessのバーエントリ、アシスタント並行使用スイッチ、チャンネルコントロールを非表示にします。Eitrのツールもこれらのアクションを直接拒否します。既存のセッションでは、新しく適用されたポリシーを反映するために次回のメニュー/パネルの更新が必要になる場合があります。

**これはroot権限を持つユーザーに対する完全な制限（ロックダウン）ではありません。** root権限があればポリシーを編集したり他のツールを実行したりできます。真のロックダウンにはroot権限を付与しないことも含まれます。ポリシーは任意のサードパーティソフトウェアやフリート管理ではなく、Eitrのワークフローを管理するものです。

ネットワークありおよびなしでのインストール、拒絶されるプロファイル、インストール済みマシンへのプロファイルの適用、アップグレード、非表示のコントロール、すべての言語でのインストーラースクリーンがVMで合格しています（`distro/PROFILE-VM-TESTING.md`）。
