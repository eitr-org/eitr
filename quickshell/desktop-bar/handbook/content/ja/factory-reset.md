# 初期状態にリセット

Eitr ISOでインストールされたコンピューターは、Walker → Settings → System → Maintenance → Factory Resetから初回ログイン時の状態に戻すことができます。このリセットはローカルで行われます。同一ディスク上に保存された読み取り専用のコピーを復元します。これはバックアップではなく、完全なデータ消去でもありません。ディスク障害が発生した場合は、コンピューターと復旧ポイントの両方が失われます。

## 復旧ポイント

ガイド付きインストーラーの最後のステップで`eitr-factory-reset capture`が実行され、完了したインストールが最上位のBtrfsサブボリューム`@eitr-factory`の下に保存されます:

| パス | 内容 |
|---|---|
| `root` | `@`の読み取り専用スナップショット（システム、アカウント、設定） |
| `home` | `@home`の読み取り専用スナップショット（シードされたユーザーフォルダ） |
| `boot.tar` | EFIパーティションのファイル: Limine、そのメニュー、カーネル、initramfs |
| `manifest.json` | 作成日時、ファイルシステムおよびEFIパーティションのUUID、アカウント、`boot.tar`のSHA-256 |

その後、`@eitr-factory`自体が読み取り専用に設定されます。これは`@/.snapshots`内ではなく`@`の横に配置されるため、Snapperによって一覧表示されたりクリーンアップされたりすることはなく、Walkerにも削除する方法はありません。root権限であれば削除可能であり、フォーマットやディスク障害によって失われます。そのスナップショットは稼働中のシステムとデータを共有しているため、初期状態ではほとんど容量を消費せず、アップデートによって元のファイルが置き換えられるにつれて消費容量が増加します。

`capture`は既存の復旧ポイントの置き換えを拒絶します。ISOを使用せずにインストールされた環境には復旧ポイントが存在せず、Factory Resetはその旨を報告します。

## 2種類のリセット

**すべて削除**はコンピューターを初回ログイン時の状態に戻します。それ以降にインストールされたアプリ、変更された設定、後から追加されたアカウント、およびホームフォルダ内のすべてのファイルが削除されます。

**個人用ファイルを保持**はシステム、アプリ、設定を復元し、ホームフォルダは維持します。復旧ポイントに含まれる各アカウントについて、現在の隠し項目（`~/.config`、`~/.local`、`~/.ssh`、ブラウザプロファイルなど）がそのホームフォルダ内の`Settings before reset <date time>`という名前の表示フォルダに移動され、その後復旧ポイントの隠し項目がコピーされて戻されます。ホームフォルダ内の何かが削除されることはありません。インストール後に追加されたアカウントはシステムとともに削除されますが、そのホームフォルダは`/home`の下に残ります。

どちらのリセットでも、ディスク暗号化パスフレーズ（LUKSヘッダーには一切手が加えられません）と、復旧ポイントにも存在するすべてのアカウントの現在のパスワードが保持されます。TPMロック解除スロットはLUKSヘッダーに残りますが、復元されたinitramfsではTPMロック解除が再設定されるまでパスフレーズが要求されます。ログ（`@log`）とパッケージキャッシュ（`@pkg`）は保持されます。

## 確認手順

Walkerのアクションは、ターミナルに2つの個別警告を表示します:

1. 選択したリセットが何を削除し、何を保持するか。`y`または`yes`でのみ続行し、Enterでキャンセルします。
2. どのコンピューターがリセットされるか、直ちに再起動されること、保存されていない作業が失われること。正確に`RESET MY COMPUTER`と入力する必要があります。

root所有のヘルパー（`/usr/lib/eitr/eitr-factory-reset`）は、入力されたフレーズを再度確認し、変更を加える前に検証を行います:

- `/`がサブボリューム`@`であり、`/home`が同一Btrfsファイルシステム上の`@home`であり、`/boot`がFAT EFIパーティションであること。
- 復旧ポイントとそのスナップショットが依然として読み取り専用であり、そのマニフェストがこのファイルシステムとEFIパーティションを指定しており、`boot.tar`がそのSHA-256と一致していること。
- セキュアブートがオフであること: 復元されるブートファイルは登録されたキーで署名されていません。
- 以前のリセットが保留状態のままになっていないこと。

`sudo /usr/lib/eitr/eitr-factory-reset status`（Walker → Reset Status）は同様のチェックを実行し、何も変更しません。

## リセットの実行の流れ

稼働中のルートおよびホームに書き込みが行われることはありません。新しい最上位サブボリューム`@eitr-reset-previous`の下で、ヘルパーは以下を実行します:

1. 復旧ポイントのルートの書き込み可能なスナップショットを作成し、その中にSnapperの`.snapshots`サブボリュームを再作成し、現在のパスワードをコピーして、そこで`eitr-factory-reset-finish.service`を有効化します。
2. 新しいホームを作成します: 復旧ポイントのホームの書き込み可能なスナップショット（「すべて削除」）、または前述のとおり設定を退避させた現在の`@home`のスナップショット（「個人用ファイルを保持」）。
3. 現在のEFIパーティションファイルを`boot.tar`にアーカイブし、コピー用に復旧ポイントのアーカイブを展開します。

この時点までに障害が発生した場合、`@eitr-reset-previous`は削除され、コンピューターは変更されずに残ります。次にヘルパーは復元されたブートファイルをEFIパーティションにコピーし（失敗した場合は作成したばかりのアーカイブを復元します）、`@eitr-reset-previous`内部で`@`と`@home`を`old@`と`old@home`にリネームし、準備したサブボリュームを`@`と`@home`にリネームして再起動します。リネームに失敗した場合は、以前の名前とブートファイルが復元されます。

次回の起動時に、`eitr-factory-reset-finish.service`は稼働中のルートが復元されたものであることを確認し、`@eitr-reset-previous`（古いシステムのSnapperスナップショットを含む）を削除して自身を無効化します。

## 中断されたリセットの復旧

リネーム処理中の数秒間に停電が発生すると、`@`または`@home`が見つからない状態になる可能性があります。Eitr ISOを起動し、Escapeを押してウィザードを終了し、暗号化されている場合はディスクのロックを解除して（`cryptsetup open /dev/<partition> root`）、以下を確認してください:

```sh
mount -o subvolid=5 /dev/mapper/root /mnt   # or the Btrfs partition itself
btrfs subvolume list /mnt
cat /mnt/@eitr-reset-previous/manifest.json
```

- `@`と`@home`が両方とも存在し、`@eitr-reset-previous/new-root`が存在しない場合: 入れ替えは完了しています。再起動してください。finishサービスがクリーンアップを行います。
- `@`または`@home`が見つからない場合: 対応する`@eitr-reset-previous/old@`または`old@home`の名前を元に戻し（`mv /mnt/@eitr-reset-previous/old@ /mnt/@`）、古いシステムと一致するように`@eitr-reset-previous/boot.tar`をEFIパーティションに展開して再起動します。

システムが正常に起動した後にのみ、`btrfs subvolume delete --recursive`で`@eitr-reset-previous`を削除してください。それまでは以前のシステムがそこに保持されています。

## 検証

ネットワークのないUEFI VMでテスト済み（[LINUX-VM-TESTING.md](LINUX-VM-TESTING.md)を参照）: 暗号化なしの消去インストールでの両方のリセット、およびWindows形式のディスクの隣にあるLUKS2インストールでの両方のリセットにおいて、それぞれ起動、ログイン、finishサービスによるクリーンアップが成功することを確認しています。未テスト: 実機ハードウェア、入れ替え中の停電、オンラインシステムアップデートを通じた復旧ポイントの保持（VMにはネットワークがありませんでした）。
