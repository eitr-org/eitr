# Git 계정

Walker > 개발 > Git 계정을 엽니다. 동일한 제공자 또는 기업용 호스트 이름의 여러 계정을 포함하여 GitHub 및 GitLab 계정을 동시에 사용할 수 있습니다. GitHub CLI(`gh`) 및 GitLab CLI(`glab`)는 새로운 설치에 기본 포함되어 있습니다. 기존 ISO 이미지는 변경 사항을 포함하도록 다시 빌드해야 합니다.

각 계정은 Git에서 해당 계정이 사용되는 위치를 나타내는 행으로 표시됩니다: **기본값**, 폴더 이름 또는 **아직 사용되지 않음**. 계정에서 Enter를 누르면 동작이 열리고, Shift+Backspace를 누르면 목록으로 돌아갑니다.

## 최초 설정

1. **계정 추가**는 제공자, 계정 이름, 커밋 작성자 이름 및 이메일, 호스트 이름, 선택적 기존 비공개 SSH 키, 기본 ID 및 폴더 규칙에 대한 공용 단계별 양식을 엽니다. 모든 응답은 검토 단계에 표시되며, 적용하기 전에 언제든지 이전 단계로 돌아갈 수 있습니다. Esc 또는 Ctrl+C를 누르면 저장하지 않고 취소됩니다.
2. **기존 설정 가져오기**는 수동으로 구성된 ID를 대신 읽어옵니다. 기본 `user.name`/`user.email` 및 폴더별 `includeIf "gitdir:…"` 규칙(`~/.gitconfig` 또는 `~/.config/git/config`에 위치)을 읽으며, 포함된 파일이 라우팅하는 SSH 별칭과 키(`url.<alias>.insteadOf`)도 포함됩니다. 발견된 항목을 나열하고 확인을 거친 후 일치하는 계정과 규칙을 생성합니다. 기존 파일은 변경되지 않으며 와일드카드 폴더 패턴은 건너뛴 것으로 나열됩니다.

## 기본값 및 폴더

**기본값** 계정은 자체 계정이 없는 모든 폴더에 적용됩니다. **폴더** 계정은 해당 폴더 내부의 저장소에만 적용됩니다. 가장 구체적인 폴더가 우선 적용되며, 저장소 로컬 설정과 Git 명령줄 또는 환경 재정의가 여전히 최우선 순위를 갖습니다. EITR은 기존 전역 구성과 주석을 보존하면서 `~/.gitconfig` 끝에 표시된 include를 추가하며, 확인된 규칙은 외부 include의 ID를 재정의합니다.

저장 전에 각각 확인을 거치고 알림으로 보고되는 Walker의 계정 동작: **기본값으로 설정** 또는 **기본값으로 사용 중지**, **폴더 추가**(`~/Development` 또는 그 안의 폴더를 선택하거나 경로를 직접 입력하는 **다른 폴더…**) 및 **폴더 제거**. Git은 실제 `.git` 디렉터리와 일치하므로 연결된 작업 트리와 서브모듈은 상위 저장소의 계정을 따를 수 있습니다.

## SSH 키

커밋 ID가 저장소 액세스 권한을 부여하는 것은 아닙니다. **공개 키 표시**는 계정의 공개 키를 출력하고 클립보드에 복사하며 키를 추가할 제공자 페이지(GitHub: Settings > SSH keys)를 안내합니다. **기존 SSH 키 설정**은 `~/.ssh`에서 키를 선택합니다. **SSH 키 만들기**는 암호문구가 있는 Ed25519 키를 생성한 후 공개 키를 표시합니다. **연결 테스트**는 "Hi username!"과 같은 제공자의 환영 메시지를 알림으로 보고합니다. 비공개 키는 절대 공유하지 마세요.

키는 해당 제공자 SSH 호스트 이름에만 적용됩니다. 런처는 연결하지 않고 기존 SSH 별칭을 확인한 다음 해당 연결에 대한 다른 SSH 구성을 무시하고 선택한 키만 사용합니다. 프록시 연결은 거부되며, 고급 설정의 경우 저장소 로컬 `core.sshCommand`를 유지하세요. 알려진 호스트 확인(Known-host verification)은 계속 활성화됩니다. 구성된 키가 없는 계정은 다른 계정의 키가 아닌 일반 SSH를 사용합니다. HTTPS 자격 증명 및 자격 증명 도우미는 변경되지 않습니다.

## 제공자 CLI

**CLI에 로그인**은 각 계정별로 별도의 구성 디렉터리에 로그인하며, 일반 전역 `gh` 또는 `glab` 계정을 전환하지 않습니다. 해당 프로세스에서는 상속된 제공자 토큰 변수가 제거됩니다. 확인 메시지에서는 토큰이 암호화되지 않은 비공개 CLI 프로필 파일에 저장되어 동일한 호스트의 계정 간에 키링 항목이 공유되는 것을 방지한다고 설명합니다. `~/.config/eitr/git-accounts/cli`는 절대 공유하지 마세요. 이 디렉터리는 EITR 백업에 포함되지 않습니다.

저장소 내에서는 계정을 인식하는 CLI를 사용하세요:

```sh
eitr-git cli auth status
eitr-git cli repo view
```

선택한 기본값/폴더 계정에 따라 `gh` 또는 `glab`이 선택됩니다. 일반 CLI 명령은 기존의 전역 동작을 유지합니다. SSH 키 등록이 CLI API 작업까지 인증하지는 않습니다. Bitbucket CLI는 번들로 제공되지 않습니다.

## 제거 및 복구

**이름 및 이메일 수정**은 ID 필드를 변경합니다. **계정 제거**는 확인 후 계정과 해당 규칙을 제거합니다. 폴더 규칙을 제거하면 더 광범위한 규칙이나 기본값으로 대체되며, 기본값을 지우면 남아 있는 규칙 외의 기존 Git 설정이 복원됩니다. 프로젝트, 키 및 CLI 자격 증명은 절대 삭제되지 않으며, 규칙을 제거해도 제공자 액세스 권한이 취소되지 않습니다.

버전 관리되는 설정은 `~/.config/eitr/git-accounts.json`에 저장됩니다. 적용할 때마다 전역 Git 파일, 활성 include 및 설정을 비공개 권한으로 `~/.local/state/eitr/git-account-backups/<id>` 아래에 백업합니다. `manifest.json`은 원본 경로, 백업 파일 이름 및 모드를 식별합니다. 키와 CLI 토큰은 절대 복사되지 않습니다. 수동으로 복구하려면 해당 매니페스트를 검토하고 백업 이후 수정된 내용을 유지한 후 파일을 복원하세요. 편집되었거나 형식이 잘못된 EITR include 블록은 자동으로 대체되지 않고 거부됩니다.
