# 앱 및 설치

공식 패키지를 설치하기 전에 터미널에 보류 중인 시스템 업데이트를 확인 중이라는 메시지가 표시됩니다. 관리자 비밀번호를 요청하기까지 이 확인 작업에 시간이 다소 걸릴 수 있습니다. Flatpak 설치 시에도 준비 단계가 표시됩니다. 대기 중인 업데이트가 있는 경우 그 이유가 설명됩니다. Arch는 최신 상태의 시스템에만 앱을 설치하며, 지금 설치를 진행하면 복구 스냅샷 없이 시스템의 일부도 함께 업그레이드되기 때문입니다. Enter를 누르면 스냅샷과 함께 시스템 업데이트를 실행한 후 설치를 진행하며, Esc를 누르면 아무것도 변경하지 않고 취소합니다.

**SUPER + Space** 및 메인 > 앱은 동일한 앱 목록을 엽니다. Enter는 앱을 실행합니다. 앱 메뉴에서는 Delete 키를 사용할 수 있으며 제거 확인을 요청합니다. **SUPER + F**의 전역 검색은 앱을 실행하지만 제거 동작을 노출하지 않습니다. 별도의 고정 기반 앱 메뉴는 없습니다.

메인 메뉴에서 입력하면 설치된 앱과 모든 하위 메뉴의 동작을 검색합니다. 시스템 또는 설치와 같은 하위 메뉴 내에서 입력하면 해당 하위 메뉴와 그 아래의 모든 항목을 검색합니다. 키보드 레이아웃 및 클라우드 계정 아래의 항목(서비스, 리소스, 로그)은 해당 자체 메뉴 내에서만 검색되며, 클라우드 계정 목록은 검색 대상에 유지됩니다.

동적 메뉴는 설치된 플러그인 또는 Git 계정 내부의 동작과 같이 이미 로드된 하위 동작도 검색합니다. 입력 시 메뉴가 로드한 내용을 재사용합니다. 다른 제공업체 읽기가 필요한 선택 항목을 검색하려면 리소스 선택기 또는 시각 요소를 여세요. 하위 메뉴 행은 **>**로 끝나며, **Shift + Backspace**를 누르면 상위 메뉴로 돌아갑니다.

## 기본 앱 선택

설정 > 기본 앱을 열어 웹 링크, 파일, 텍스트, 이미지, 비디오, 음악, 메일 및 PDF에 대해 설치된 핸들러를 선택하세요. 터미널 선택 항목은 모양 > 터미널과 공유됩니다. 다른 플레이어를 선택하지 않는 한 음악 파일은 Decibels에서 열립니다. GNOME Music은 설치되어 있더라도 자체 라이브러리의 음악만 재생하며 파일을 열 수 없습니다.

## 설치

이름이 지정된 설치 목록에서 설치된 항목에 Delete 키를 누르면 확인 후 제거할 수 있습니다. 웹 앱은 제거 동작을 유지합니다. 패키지 목록(Pacman 및 Yay)에서는 강조 표시된 설치된 패키지를 확인 후 Ctrl+D로 제거합니다. Ctrl+F는 설치된 패키지만 표시할지 모든 패키지를 표시할지 전환합니다. Eitr 패키지는 설치된 상태로 유지됩니다. 필수 시스템 종속성은 재귀적으로 제거되지 않으며, pacman은 다른 패키지를 손상시킬 수 있는 제거를 거부합니다.

관리형 언어 번들은 [y/N]으로 확인을 요청하기 전에 터미널에 전체 제거 경고를 표시합니다. Enter를 누르면 취소됩니다. Node 제거에는 모든 NVM 관리 버전과 해당 전역 npm 도구가 포함됩니다. Python 제거는 uv 관리 버전 및 uv에 영향을 미치며 시스템 Python에는 영향을 주지 않습니다. Java는 현재 SDKMAN Java 및 Maven 버전을 제거하고, Rust는 안정(stable) 툴체인만 제거합니다. Rails 및 Laravel은 프레임워크 도구를 제거하는 동안 Ruby, PHP 및 Composer는 유지합니다. 프로젝트, 설정 및 자격 증명은 유지되지만 종속 도구 및 환경이 작동하지 않을 수 있습니다. 네이티브 어시스턴트 제거 시에는 캐시된 버전과 설정이 유지됩니다.

시스템에 이미 있는 앱은 이름 아래에 **설치됨**이 표시되며, 이를 선택하면 다시 설치하는 대신 이미 설치되어 있다고 안내합니다. 또한 SDKMAN의 Java 또는 NVM의 Node.js와 같이 자체 관리자에 의해 설치된 도구도 인식합니다. DBeaver의 Java와 같이 런타임이 필요한 패키지는 아직 어떤 패키지도 이를 제공하지 않는 경우에만 소형 런타임을 함께 가져옵니다.

- **AI CLI:** 선택적 AI 명령줄 클라이언트.
- **브라우저:** 지원되는 브라우저 선택 항목.
- **데이터베이스:** DBeaver, 데이터베이스 클라이언트 및 Valkey(Arch가 Redis 대신 제공하는 Redis 호환 서버)와 같은 선택적 도구.
- **개발 언어:** 선택적 언어 툴체인. Java/Flutter는 필수 데스크톱 종속성이 아닙니다.
- **JavaScript 도구:** 선택적 JavaScript 런타임 및 도구.
- **패키지 > Pacman** 및 **패키지 > Yay (AUR):** 공식 Arch 패키지 또는 커뮤니티 AUR 패키지를 검색하며, 각각 출처와 설치 여부가 라벨로 표시됩니다. 검색창은 맨 위에, 패키지는 그 아래에, 선택한 패키지의 세부 정보는 하단에 표시됩니다. **Ctrl+B**는 빌드 파일(PKGBUILD)을 표시하거나 돌아가고, **Ctrl+O**는 브라우저에서 해당 페이지를 열며, **Tab**은 여러 항목을 선택하고 **Enter**는 설치를 진행합니다. AUR 패키지는 빌드 파일로부터 이 컴퓨터에서 직접 빌드되므로 먼저 빌드 파일을 읽어보세요. 이들은 공식 Arch 패키지가 아닙니다.

설치/업데이트/설정 터미널에는 테마가 적용된 EITR 배너가 표시됩니다. 성공한 작업은 일반적으로 자동으로 닫히며, 실패한 작업은 계속 표시됩니다. 정리와 같은 보고서는 내용을 읽을 수 있도록 열린 상태로 유지됩니다. 일반 터미널과 정보 화면에는 작업 배너가 표시되지 않습니다.

대기 중인 작업, 계정, 보고서 및 정보 터미널을 닫으려면 **Esc**를 누르세요. Enter 키는 복구 키 확인 및 설치 프로그램 전원 끄기를 포함한 응답 및 확인에 사용됩니다.

단일 공식 패키지의 경우 `eitr package install NAME`, AUR의 경우 `eitr package install --aur NAME`, 제거의 경우 `eitr package remove NAME`을 사용하세요. 터미널이 필요합니다. 테마가 적용된 검토 창에 패키지와 소스가 표시됩니다. Enter로 확인하고 Esc로 취소합니다. AUR의 경우 Ctrl+B는 빌드 파일을 읽고(q로 복귀), Ctrl+O는 빌드 저장소를 엽니다. 커뮤니티 AUR 패키지는 Eitr 또는 Arch Linux에서 검토되지 않습니다. 이미 설치된 패키지는 성공으로 종료됩니다. 실패한 작업은 Esc를 누를 때까지 열린 상태로 유지됩니다. 플러그인은 `kitty --class eitr-menu-terminal -e eitr package install --aur lowfi`를 사용할 수 있습니다.

## 도구

앱 메뉴의 **계산기**(또는 키보드의 계산기 키)는 현재 테마 색상으로 Eitr 계산기를 엽니다. 입력하거나 클릭하세요: `+ − × ÷`, 거듭제곱을 위한 `^`, 백분율을 위한 `%`(`200×15%`), `√` 및 괄호. 괄호 앞의 숫자는 곱셈으로 처리됩니다(`2(3+4)`). Enter는 결과를 표시하고, 백스페이스는 문자를 제거하며, Escape는 지우고(두 번 누르면 닫힘), Ctrl+C 또는 **복사**는 결과를 복사합니다. 코드로 실행하는 대신 수식 자체를 직접 계산합니다.

**오프라인 받아쓰기**는 음성을 텍스트로 변환하며 오디오가 컴퓨터 외부로 나가지 않습니다. **SUPER + D**를 길게 누르고 말한 뒤 손을 떼세요. 커서가 있는 위치에 사용자가 말한 언어로 단어가 입력됩니다. **SUPER + D**를 한 번 눌러 말하고 다시 누를 수도 있습니다. 듣는 동안 시계 바로 왼쪽의 빨간색 점이 사용자의 음성에 따라 움직이는 작은 파형으로 바뀌어 소리를 감지하고 있음을 확인할 수 있습니다. 손을 뗀 후에는 단어가 입력될 때까지 펄스 형태로 깜빡입니다.

처음 사용할 때 음성 모델(148 MB, 공개된 체크섬으로 확인됨)을 `~/.local/share/eitr/whisper/`에 한 번 다운로드하며, 그 이후에는 오프라인으로 작동합니다. 손을 뗀 후 변환에 잠시 시간이 걸리며 구형 프로세서에서는 더 오래 걸릴 수 있습니다. SUPER를 먼저 떼더라도 D에서 손을 떼거나 120초가 지나면 녹음이 중지되며, 이후 단어가 정상적으로 변환됩니다.

**메인 > 도구 > 알림 > 새 알림**은 시간(`10m`, `1h30m`과 같은 지연 시간 또는 `18:30`과 같은 시각)과 내용을 묻고 해당 시간에 다시 알림 및 닫기 버튼이 있는 알림을 표시합니다. **예정된 알림**은 대기 중인 항목을 나열하며, 하나를 선택하여 취소할 수 있습니다. 알림은 재시작 후에도 유지되며 컴퓨터가 꺼져 있는 동안 만료된 알림은 다음 로그인 시 표시됩니다. 터미널에서는 `eitr remind 25m Take the tea out`과 같이 사용하며, `eitr remind`만 입력하면 목록이 표시됩니다.

## 게임

메인 > 게임에는 **GeForce NOW**, **RetroArch** 및 **Steam**이 나열됩니다. 하나를 선택하면 설치된 경우 실행되고 그렇지 않으면 설치됩니다. RetroArch는 클래식 콘솔(NES, SNES, Game Boy 및 Game Boy Advance, Mega Drive/Genesis, PlayStation, Nintendo 64, Nintendo DS, PSP, Dreamcast)용 코어와 함께 Arch의 공식 패키지에서 제공됩니다. 본인의 게임과 필요한 경우 콘솔의 BIOS 파일을 직접 추가하세요. Eitr는 둘 다 제공하지 않습니다. GeForce NOW는 Flatpak에서 설치됩니다.

**빠른 동작 > 게임 모드**는 게임을 플레이하는 동안 데스크톱 방해 요소를 제거합니다. 창 애니메이션, 블러 및 그림자가 꺼지고 알림 팝업이 대기 상태(방해 금지)로 전환되며, 컴퓨터에서 지원하는 경우 전원 프로필이 성능으로 전환됩니다. 게임 모드를 끄면 변경된 항목이 정확히 복원됩니다. Steam은 **GameMode** 및 **MangoHud**와 함께 설치됩니다. Steam의 게임 실행 옵션에 `gamemoderun mangohud %command%`를 추가하면 게임 중에 CPU를 부스트하고 FPS 오버레이를 표시할 수 있습니다.

LocalSend의 패키지 앱에는 자체 런타임 요구 사항이 포함되어 있으므로 실행하기 위해 Flutter SDK가 필요하지 않습니다. 개발자 도구는 선택 사항으로 유지됩니다.

업그레이드에는 [업데이트 및 정리](handbook:maintenance)를 사용하세요. 단일 패키지를 설치하는 것은 스냅샷으로 보호되는 시스템 업데이트 워크플로와 다릅니다.

메인 > 도구 > 재미에는 음악 시각화 도구와 룬 비가 포함되어 있습니다.

**음악 시각화 도구**는 테마 색상으로 cava를 엽니다. 미디어 이퀄라이저를 마우스 오른쪽 버튼으로 클릭해도 동일한 시각화 도구가 열립니다. 왼쪽 클릭은 기존처럼 미디어 세부 정보를 엽니다. **q** 또는 **Esc**를 누르면 닫힙니다. 기존 데스크톱에서는 누락된 cava 패키지가 먼저 설치됩니다.

**룬 비**는 테마 색상으로 떨어지는 엘더 푸사르크 룬 문자로 화면을 가득 채우며 때때로 ᛖᛁᛏᚱ을 표기합니다. 아무 키나 누르면 닫힙니다. 터미널에서는 `eitr matrix`로 해당 자리에서 실행할 수 있으며, `--speed slow|normal|fast` 및 `--seconds N`으로 속도와 길이를 변경할 수 있습니다.

연결된 모니터가 HDR 지원을 보고하면 Eitr는 `PROTON_ENABLE_WAYLAND=1`, `PROTON_ENABLE_HDR=1`, `DXVK_HDR=1`을 사용하여 Steam Proton 게임을 기본적으로 Wayland 및 HDR로 설정합니다. HDR 모니터가 없는 머신은 기존 기본값을 유지합니다. 하드웨어 감지는 디스플레이가 나열되거나 변경될 때, 그리고 로그인 또는 새로고침 시 해당 구성이 로드되기 전에 생성된 디스플레이 구성을 새로고침합니다.

새 데스크톱 세션을 시작하고 Steam을 다시 시작하여 변경된 기본값을 적용하세요. 이미 실행 중인 Steam 프로세스는 자체 환경을 유지합니다. 게임 자체에서 HDR을 활성화하세요. 전체 화면 게임은 데스크톱 HDR이 꺼져 있어도 모니터를 자동으로 전환할 수 있습니다. 일부 게임은 Wayland 모드에서 Steam 오버레이를 잃을 수 있습니다. 단일 게임에 대해 이를 해제하려면 Steam 실행 옵션을 `PROTON_ENABLE_WAYLAND=0 %command%`로 설정하세요.

게임을 보정하려면 사양에 명시된 모니터의 HDR 최대 밝기에 맞게 게임의 최대 밝기 또는 피크 밝기를 설정한 다음(DisplayHDR 400 모니터의 경우 약 400 nits 피크), 취향에 따라 페이퍼 화이트 또는 전체 밝기를 조정하세요. 하이라이트 디테일이 손실되면 피크 값을 낮추고 이미지가 칙칙해 보이면 페이퍼 화이트를 높이세요.

브라우저는 모니터에 데스크톱 HDR이 켜져 있는 경우에만 HDR을 사용하며 자동으로 켜지지 않습니다. 전체 화면 HDR 게임은 데스크톱 HDR이 꺼져 있어도 자동으로 전환됩니다. 브라우저 HDR 재생은 브라우저 지원 및 설정에 따라서도 달라집니다.

## 음성 알림

**SUPER + Shift + D**를 누른 채 말하고 손을 떼거나 메인 > 도구 > 알림 > 어시스턴트에게 말하기…를 열어 입력하세요. Eitr는 받아쓰기와 동일한 오프라인 모델을 사용하여 로컬에서 텍스트로 변환한 다음 개발 > AI > 기본 어시스턴트에 요청 해석을 문의합니다. 녹취록과 알림 컨텍스트만 해당 어시스턴트 제공업체로 전송되며, 오디오는 로컬에 유지되고 변환 후 삭제됩니다.

어시스턴트는 Eitr의 읽기 전용 경로를 통해 헤드리스로 실행됩니다. Eitr는 JSON을 검증하고 어시스턴트에게 아무것도 변경할 수 있는 도구를 제공하지 않고 알림 동작을 직접 실행합니다. Ratatoskr(개발 > AI > 기본 어시스턴트)를 사용하면 녹취록이 이 PC 외부로 나가지 않습니다.

“내일 15시에 전화하라고 알려줘” 또는 “10월 30일 15시 치과, 30분 전에 알려줘”라고 말해보세요. 일정 알림은 기본적으로 1시간 전(또는 사용자가 선택한 시간)과 이벤트 발생 시에 알림을 울리며, 일반 알림은 해당 시간에 울립니다. 시간이 없는 날짜는 어떤 어시스턴트를 사용하든 시계를 엽니다. 기타 누락된 세부 정보나 모호한 점이 있는 경우 번호가 매겨진 전체 선택 항목이 포함된 터미널이 열립니다. 번호나 본인의 답변을 입력하거나 SUPER + D로 받아쓰기하세요. Esc로 취소합니다. 알림을 통해 결과가 보고됩니다. 알림 목록 조회나 취소도 요청할 수 있습니다.

새 알림은 `tomorrow 15:00`, 요일 이름, `2026-10-30 09:00`, `Oct 30 15:00`, `9am`, `in 5 minutes`, `every 29th`도 지원합니다. CLI에서는 여러 단어로 된 날짜를 따옴표로 묶으세요. 각 알림에는 자체 타이머가 있으며 취소하면 모든 알림이 제거됩니다. 놓친 알림은 다음 로그인 시 나타납니다. 입력하거나 말한 날짜에 시간이 없으면 작은 시계가 열립니다: HH:MM 필드에 24시간 형식의 시간을 입력하세요. 백스페이스는 마지막 숫자를 제거하고 방향키는 시 또는 분을 조정하며 Enter는 시간을 설정하고 Esc는 취소합니다.

방해 금지 모드가 아닐 때 알림이 울리면 짧은 소리가 재생됩니다. 캘린더에는 이벤트가 있는 날이 표시되며 날짜를 클릭하면 알림 시간과 제목이 즉시 업데이트되어 표시됩니다. 나열된 각 알림에는 휴지통 버튼이 있습니다: 일회성 알림은 두 번 클릭하여 삭제하고, 반복 알림은 이번 항목만(다음 예정 항목만) 또는 전체를 선택하세요.

Escape를 누르거나 다른 곳을 클릭하거나 몇 초 동안 입력이 없으면 알림이 유지됩니다.

반복 알림은 `every day 08:00`, `every Monday 09:30`, `weekdays 07:00`, `every Monday and Thursday 09:30`, `every week`, `every month on the 15th` 및 `every year`(시간 포함)를 지원합니다. `eitr remind "every day 08:00" Stretch`와 같이 전체 문구를 따옴표로 묶으세요. 어시스턴트는 반복 간격 및 종료 날짜 또는 발생 횟수도 지원합니다. 31일과 같은 월별 날짜 및 윤년 2월 29일은 해당 월의 마지막 날로 대체됩니다. 로컬 실제 시계 시간과 상대적 알림이 보존됩니다.

다음 번 발생 항목에만 타이머가 설정됩니다. 시스템이 꺼져 있던 시간 이후에는 놓친 항목 하나가 표시되고 경과된 발생 항목은 건너뛰며 한도에 반영됩니다. 예정된 알림에는 다음 시간과 규칙이 표시됩니다. 취소하려면 이번 항목만 또는 향후 모든 항목을 선택하세요. CLI에서는 `eitr remind cancel ID occurrence` 또는 `eitr remind cancel ID series`를 사용합니다. 캘린더는 발생 요일을 점으로 표시하고 반복 항목을 ↻로 표시하며 높이는 고정된 상태로 유지됩니다.

놓친 알림을 포함한 알림 팝업 및 알림 기록에서는 **5분 다시 알림**, **10분 다시 알림**, **1시간 다시 알림** 및 **닫기**를 제공합니다. 다시 알림을 선택하면 클릭한 시간부터 동일한 텍스트로 별도의 일회성 알림이 예약되며, 반복 알림은 일정을 그대로 유지합니다. 닫기는 알림을 종료합니다. 동작은 최대 24시간 동안 사용 가능하며 그 후에는 알림이 만료됩니다.

**메인 > 도구 > 알림 > 캘린더 소스 > 캘린더 추가…**는 Google, Outlook 또는 기타 iCal 캘린더를 로그인 없이 읽기 전용으로 캘린더 패널에 표시합니다. 제공업체를 선택하세요: Google과 Outlook은 브라우저에서 해당 설정을 엽니다. Google에서는 내 캘린더 설정 > 캘린더 통합 > iCal 형식의 비공개 주소를 복사하고, Outlook에서는 설정 > 캘린더 > 공유 캘린더에서 캘린더를 게시하고 해당 ICS 링크를 복사하세요.

주소(`https://` 또는 `webcal://`)를 붙여넣은 다음 캘린더 이름을 지정하세요. 해당 주소를 아는 사람은 누구나 캘린더를 읽을 수 있으므로 Eitr는 이를 비공개 파일에 보관하며 메뉴, 알림 또는 로그에 절대 표시하지 않습니다. 유출된 경우 제공업체에서 비공개 주소를 재설정하세요. 캘린더는 로그인 시, 15분마다, 그리고 캘린더 패널을 열 때(최대 분당 1회) 새로고침됩니다.

지난주부터 향후 60일까지의 이벤트가 캘린더 이름과 함께 휴지통 버튼 없이 알림 옆에 표시됩니다: 수정은 Google 또는 Outlook에서 진행하세요. 시간이 지정된 이벤트는 알림 소리와 함께 시작 시 울리며, 종일 이벤트는 울리지 않습니다. 매일, 매주, 매월(특정 일자 또는 마지막 금요일과 같은 요일) 및 매년 반복이 표시되며, 드문 규칙은 첫 번째 이벤트만 표시됩니다.

캘린더 소스 메뉴에서 캘린더에 대해 Enter를 누르면 지금 새로고침되고 Delete를 누르면 확인 후 제거됩니다. 양방향 동기화(제공업체 이벤트 생성 또는 편집)는 지원되지 않습니다. 브라우저에서 링크를 복사하는 동안 터미널이 열린 상태로 유지되며 검토 화면에서 Enter를 누르면 추가되고 Esc를 누르면 취소됩니다.

## 플러그인

플러그인은 스크립트, Walker 행, 선택적 시각 요소(타일, 패널, 데스크톱 위젯 및 바 항목), 그리고 선택적으로 하나의 사용자 서비스를 포함하는 Git 저장소입니다. 하나의 저장소에 여러 플러그인이 포함될 수 있습니다. 플러그인은 사용자 계정의 전체 권한으로 사용자 본인으로서 실행됩니다: 사용자의 파일, SSH 키 및 브라우저 데이터를 읽고 이를 어디로든 전송할 수 있으며 자체적으로 계속 실행되도록 유지할 수 있습니다.

Eitr는 해당 코드를 검토하지 않았습니다. 코드는 Eitr가 아닌 작성자의 소유이며 모든 플러그인 행에 예를 들어 Ada 제작 플러그인 · Eitr 검토 미완료와 같이 명시됩니다. 신뢰할 수 있는 사람과 저장소의 플러그인만 추가하세요.

플러그인은 `packages`를 선언할 수 있습니다: 활성화된 공식 Arch 저장소 또는 `[eitr]`에서 최대 32개의 고유한 일반 패키지 이름을 지정할 수 있으며 AUR, URL 또는 로컬 파일은 허용되지 않습니다. 검토 시 이미 설치된 패키지와 누락된 패키지가 나열되며 알 수 없는 패키지는 설치가 거부됩니다. 승인 후 Eitr는 시스템 polkit 대화 상자를 통해 관리자 비밀번호를 요청하고 누락된 패키지만 설치합니다. 패키지를 추가하는 업데이트도 검토가 필요합니다. 제거 시 해당 플러그인을 위해 설치된 패키지를 선택적으로 정리할 수 있지만 사용되지 않는 종속성으로 남아 있는 경우에만 가능합니다. 명시적으로 설치되었거나 다른 플러그인에 필요한 패키지는 유지됩니다.

메인 > 설치 > 플러그인 > 플러그인 추가는 HTTPS Git URL을 요청하거나 비공개 저장소의 경우 `git@github.com:you/plugin.git`과 같은 SSH URL을 요청합니다(에이전트를 통해 사용자의 SSH 키를 사용함). 추가하려면 두 번의 확인이 필요하며 둘 다 기본값은 아니오입니다. 먼저 아무것도 다운로드되기 전에 안전 페이지에서 이러한 위험을 설명합니다. 검토를 위해 플러그인을 다운로드하려면 Enter를 누르세요.

그런 다음 신뢰 경고 및 모든 경고(모든 로그인 시 시작되는 백그라운드 서비스, 바이너리 파일)로 검토가 시작되고, 매니페스트 작성자, 저장소, 정확한 커밋, Git 작성자 및 날짜, 버전, 실행 파일 수 및 행이 표시됩니다. Enter를 눌러 설치하고 어느 단계에서든 Esc로 취소할 수 있습니다.

승인 전에는 플러그인의 어떤 것도 실행되지 않습니다. `eitr plugin add URL`도 동일한 두 가지 질문을 묻고(Enter로 계속, Esc로 취소) 터미널 없이는 실행을 거부합니다. 메인 > 설치 > 플러그인 > 설치된 플러그인은 설치된 플러그인 폴더를 나열합니다. 설치된 각 플러그인에는 동작, 시각 요소, 제거 및 사용 가능한 업데이트를 위한 폴더가 있습니다.

설치 검토 시 A를 누르면 기본 어시스턴트에게 도구 없이 텍스트로서 저장소의 임시 복사본을 확인하도록 요청할 수 있습니다. Ratatoskr 및 Claude가 플러그인을 확인할 수 있으며, 지원되지 않는 기본값은 검토에 표시됩니다. Claude는 텍스트를 제공업체로 보내고 Ratatoskr는 이 PC에 보관합니다.

PgUp/PgDn으로 보고서를 스크롤하세요. AI도 놓치는 부분이 있을 수 있습니다: 이는 조언일 뿐 승인이 아니며 전체 권한 경고는 여전히 유효합니다. Enter로 설치하고 확인이 실행되는 중에도 Esc로 취소할 수 있습니다. 오류, 빈 답변 및 180초 시간 초과 시에는 일반 검토를 계속 사용할 수 있습니다. 어떤 것도 자동으로 설치되지 않습니다. 카탈로그는 데이터 전용 Git 테마 패키지도 지원합니다.

애드온 카탈로그는 터미널을 열지 않고도 플러그인을 설치하고 업데이트할 수 있습니다. 공식 및 커뮤니티 카드는 사진, 비디오 및 구성 요소 정보가 포함된 세부 정보를 열며, 설치는 네이티브 커밋 검토를 엽니다. 설치됨 > Git 주소에서 추가는 HTTPS 또는 SSH를 허용합니다. 검토에는 파일, 명령, QML 소스, 작성자 및 업데이트 변경 사항이 포함되며 선택적 텍스트 전용 AI 조언도 제공됩니다.

Enter로 확인하고 Escape로 취소합니다. 준비된 후보는 정확히 검토된 커밋과 대조 확인되며, 커뮤니티는 색인의 고정(pin)을 사용합니다. 토큰은 15분 후에 만료되며 카탈로그를 닫으면 폐기됩니다. 비디오는 음소거 상태로 시작되며 닫을 때 중지됩니다.

시스템 업데이트는 시스템 패키지가 최신 상태인 경우에도 새 플러그인 커밋만 확인하며 개수와 업데이트 위치를 출력합니다. 플러그인을 검토하거나 업데이트하지 않으며 네트워크 오류는 조용히 무시됩니다. **제어 센터 > 플러그인**(플러그인 추가 옆) 또는 **플러그인 > 플러그인 업데이트**에서 **플러그인 업데이트**를 실행하거나 `eitr plugin update`를 사용하세요.

플러그인 업데이트 버튼과 행은 마지막 확인에서 업데이트를 발견한 경우에만 나타납니다. 플러그인 행의 작은 ↑ 표시와 세부 정보의 “업데이트 사용 가능”은 승인된 커밋에 대한 마지막 확인 결과를 반영합니다. 별도의 작업을 통해 플러그인별 기존 diff, 위험 플래그 및 확인 절차를 유지합니다.

각 업데이트는 이전 및 새 커밋, 커밋 제목, 추가 및 제거된 행이 포함된 변경된 파일, 그리고 추가·변경 또는 제거된 백그라운드 서비스, 매니페스트 변경, 신규 또는 변경된 실행 파일, 바이너리 파일, 승인된 커밋의 작성자와 다른 작성자의 커밋에 대한 위험(RISK) 플래그 요약으로 시작됩니다.

페이저(`delta`가 설치된 경우 delta, 그렇지 않은 경우 `less -R`)에서 전체 diff를 읽으려면 `d`를 누르고, 업데이트하려면 Enter를, 현재 버전을 유지하려면 Esc를 누르세요. 히스토리가 다시 작성되어 승인된 커밋이 새 커밋의 일부가 아닌 경우 Eitr는 자동으로 업데이트하지 않고 그 이유를 설명합니다. 여전히 신뢰하는 경우 플러그인을 제거하고 다시 추가하세요.

비대화형 업데이트는 플러그인을 건너뜁니다. 플러그인 > 설치된 플러그인 > 해당 플러그인은 업데이트 및 제거를 제공합니다. 제거 시 확인을 요청하고 해당 파일, 행 및 서비스를 제거합니다. 동일한 흐름을 `eitr plugin list`, `eitr plugin add URL`, `eitr plugin update [ID]`, `eitr plugin remove ID`를 통해 사용할 수 있습니다.

Eitr는 서명된 `eitr-desktop` 패키지 내에 플러그인 차단 목록을 제공하므로 pacman의 패키지 서명이 이를 보호합니다. 각 항목은 이유와 함께 저장소, 커밋 또는 플러그인 ID를 지정합니다. 차단된 플러그인의 추가 또는 업데이트는 거부됩니다. 설치된 플러그인이 차단 대상이 되면 중지됩니다: 플러그인 > 설치된 플러그인에서 해당 행이 제거되고, 실행할 수 없으며, 해당 서비스가 중지 및 비활성화되고, 제거 버튼과 함께 해당 플러그인과 이유를 명시하는 알림이 한 번 표시됩니다.

플러그인 > 설치된 플러그인에 차단됨으로 표시되며 이를 선택하면 제거됩니다. 해당 파일은 자동으로 삭제되지 않습니다. 유해한 플러그인을 신고하려면 `https://github.com/eitr-org/eitr/issues/new?template=malicious-plugin.yml`을 여세요. 신고서에 비밀번호, 토큰 또는 키를 절대 붙여넣지 마세요. 조직 프로필을 통해 플러그인을 끄거나 목록에 있는 저장소만 허용할 수도 있습니다(조직 프로필 참조).

플러그인은 `$XDG_DATA_HOME/eitr/plugins/<id>/`(기본값 `~/.local/share/eitr/plugins/`)에만 존재하며 승인 정보는 `$XDG_STATE_HOME/eitr/plugins.json`에 있습니다. 서비스는 `NoNewPrivileges=yes`가 적용된 `$XDG_CONFIG_HOME/systemd/user/eitr-plugin-<id>.service`를 사용하므로 sudo와 같은 프로그램을 통해 권한을 상승시킬 수 없습니다. sudo를 절대 사용하지 마세요. 업데이트는 별도의 후보를 검증하며 거부 또는 실패 시 이전 승인된 커밋을 유지합니다. 플러그인은 실행 중에 파일을 수정할 수 있으며 제거해도 해당 변경 사항을 되돌릴 수 없습니다.

### 매니페스트 참조

버전 1: 저장소 루트에 `eitr-plugin.json`이 포함되어 있습니다. 허용되는 키는 `id`(단일 하이픈으로 구분된 소문자/숫자), `name`, `description`(최대 72자), `author`, `version`, `rows`(`ui`를 선언할 경우 0–20; 그렇지 않으면 1–20), 그리고 선택적 `service`, `schemaVersion`, `packages`, `hooks`뿐입니다. 각 행에는 `title`, `description`(둘 다 최대 72자) 및 `run`이 필요하며 선택적 키는 `icon` 및 `arguments`(고정 문자열 배열)입니다.

서비스는 `run` 및 선택적 `arguments`만 허용합니다. 명령은 셸 문자열이 아닌 argv를 사용합니다. `run`은 저장소 내부의 실행 파일 이름을 지정해야 합니다: 절대 경로와 `..`는 거부되며 플러그인 내 어느 위치에서든 심볼릭 링크도 거부됩니다. 알 수 없거나 중복된 JSON 키는 거부됩니다. 서브모듈은 초기화되지 않습니다.

`distro/plugins/example/`의 작은 예제에는 매니페스트와 `notify.sh`, 알림 동작 하나, 테마 훅이 포함되어 있고 서비스는 없습니다. 이를 본인의 Git 저장소에 복사하고 커밋한 후 HTTPS Git URL을 게시하여 전체 설치 흐름을 시험해 보세요. 이 예제는 문서용으로 제공되며 자동으로 설치되지 않습니다. 시각적 플러그인의 경우 공식 모음인 `https://github.com/eitr-org/eitr-plugins`에 시각화 도구가 있습니다.

스크립트 전용 매니페스트의 경우 `schemaVersion: 1`을 선언하고 아래의 선택적 `ui` 섹션을 사용하려면 `schemaVersion: 2`를 선언하세요. 버전이 없는 이전 매니페스트는 검토 시 알림과 함께 v1으로 계속 작동합니다. 2보다 높은 버전은 최신 Eitr가 필요합니다. 작성자 가이드인 `distro/PLUGINS.md`(패키지명 `PLUGINS.md`)에서 안정적인 버전 1 계약을 정의합니다.

플러그인은 `theme-changed`, `wallpaper-changed`, `after-update`, `login` 훅을 선언할 수 있습니다. 이들은 동작 후 백그라운드에서 실행되며(login은 데스크톱 세션당 한 번), 30초의 제한 시간을 갖습니다. 실패는 `$XDG_STATE_HOME/eitr/plugin-hooks.log`에 기록되며 동작을 실패 처리하지 않습니다. 검토에서 훅을 나열하며 추가되거나 변경된 훅은 업데이트 위험(RISK) 플래그를 발생시킵니다. 차단 목록 및 조직 정책은 훅에도 적용됩니다.

### 시각적 플러그인

스키마 버전 2는 **제어 센터 > 일반 > 플러그인**에 타일을 추가하고 해당 타일에서 열리는 패널을 추가할 수 있습니다. 이들은 Eitr의 색상, 글꼴 및 모서리를 따를 수 있습니다. 바 항목은 플러그인이 설치될 때 바에 배치되고 위젯은 사용자가 추가한 후에 나타납니다. 검토 시 설치 전에 모든 QML 파일과 전체 소스를 나열합니다. 업데이트 시 승인 전에 스크롤 가능한 diff와 후보 QML을 표시하며, QML 변경은 위험(RISK) 플래그를 발생시킵니다. QML은 샌드박스가 아닙니다: 사용자의 전체 권한으로 바 내부에서 실행됩니다. 작성자를 신뢰하세요. 무한 루프나 네이티브 충돌은 로더에 의해 격리될 수 없습니다.

구성 요소 로드 오류는 콘텐츠 대신 인라인 오류를 표시하며 `$XDG_STATE_HOME/eitr/plugin-ui.log`에 기록됩니다. 3회의 로드 또는 보고된 오류가 발생하면 해당 플러그인의 시각적 구성 요소가 비활성화되며 업데이트 간에도 유지됩니다. 제어 센터 > 플러그인에서 **다시 활성화**를 선택하거나 `eitr plugin enable-ui ID`를 실행하세요. 임계값에 도달하기 전에는 일반 페이지를 닫았다가 다시 열어 재시도할 수 있습니다.

행, 훅 및 서비스는 독립적입니다. 플러그인은 기존 일반 섹션 뒤에 나타납니다. 패널은 제목과 뒤로 가기 셰브론으로 타일을 대체합니다. Back 또는 Escape는 제어 센터를 닫는 추가 Escape 전에 타일로 돌아갑니다. 긴 패널은 하위 뷰 내부에서 스크롤됩니다. 스키마 v2 예제에는 Hello 타일과 상태 패널이 있습니다.

스키마 v1 플러그인은 변경 없이 계속 지원됩니다. 작성 세부 정보와 제한된 스타일/데이터 API는 `distro/PLUGINS.md`에 있습니다. API는 지원되는 인터페이스일 뿐 보안 경계가 아닙니다.

### 플러그인 관리자 및 위젯 옵션

**제어 센터 > 플러그인**은 설치된 모든 플러그인을 아이콘, 작성자, 버전, 설명 및 활성화 상태와 함께 나열합니다. 스크린샷을 보려면 미리보기를 펼치세요. 활성화/비활성화는 배치를 유지하면서 서비스, Walker 행, 훅 및 시각 요소를 중지하거나 복원합니다. CLI는 `eitr plugin enable ID` 또는 `eitr plugin disable ID`입니다. 플러그인 추가, 업데이트 및 제거는 검토된 터미널 흐름을 열며 제거 시 확인을 요청합니다. 일반 페이지에는 플러그인 타일만 유지됩니다. 시각적 오류에는 독립적인 다시 활성화 동작이 제공됩니다.

원하는 만큼 디스플레이에 위젯을 추가할 수 있습니다: 각 복사본은 자체 디스플레이, 위치, 크기, 회전 및 설정을 유지합니다. 디스플레이가 여러 개인 경우 추가 시 포커스된 디스플레이를 맨 위에 두고 어느 디스플레이에 추가할지 묻습니다. 제거는 바 항목을 숨기며 업데이트 후에도 숨겨진 상태를 유지합니다. 위치 편집은 일시적으로 창 위로 복사본을 올립니다: 제목 또는 크기 조절 핸들을 드래그한 다음 완료 또는 Escape를 누르세요. 움직임은 부드럽게 이어지며 손을 떼면 데스크톱 간격에 스냅되어 저장됩니다. 플러그인 페이지의 각 복사본 카드와 마우스 오른쪽 버튼 메뉴(창 뒤에 있는 위젯 또는 편집 모드의 모든 위젯)는 동일한 설정을 제공합니다: 위치 편집, 복제(디스플레이 왼쪽 상단에 새 복사본), 크기 단계(90% / 110%, 화면 제한 내에서 화면비와 중심 유지), 전체 너비, 회전(3° 내에서 90도 회전에 스냅되는 슬라이더, 45도 회전 및 재설정), 디스플레이(이동 시 크기와 설정 유지), 패널/투명 배경, 창 위에 표시, 플러그인 옵션 및 데스크톱에서 제거.

전체 너비는 동일한 화면비로 가장 큰 크기에 맞춥니다. 창 위의 위젯은 클릭이 통과됩니다. 플러그인 페이지에서 해당 옵션을 사용하세요. 해당 페이지 또는 Walker 시각 요소에서 위젯 편집을 누르면 완료 또는 Escape를 누를 때까지 모든 위젯이 대화형 상태로 전환됩니다(`plugin-widgets edit` / `done` IPC). 누락된 모니터는 저장된 배치를 유지합니다.

투명 배경에는 호스트 색상, 테두리 또는 블러가 없습니다. 편집 핸들은 계속 표시됩니다. 새 스키마 v2 플러그인에는 정사각형 PNG/SVG 아이콘(최대 512 KiB, PNG 64–1024 px)이 필요합니다. 선택적 미리보기는 축당 최대 2 MiB 및 3840 px의 PNG/JPEG이며 홈페이지는 HTTPS여야 합니다. 아이콘이 없는 기존 플러그인은 일반 아이콘과 검토 알림을 사용합니다. 작성자 API는 파형/막대와 같은 옵션을 위해 `api.setMenu([{id, text, checked, group}])` 및 `api.menuTriggered(id)`를 추가합니다. 유효성 검사 및 API 세부 정보는 `distro/PLUGINS.md`를 참조하세요.

스키마 v2 플러그인은 `audio-spectrum`을 요청할 수 있습니다. 검토에서는 시스템 오디오 레벨만 읽는다고 명시합니다: 어떤 오디오도 녹음되거나 전송되지 않으며 호스트는 마이크를 절대 캡처하지 않습니다. 이 기능을 추가하면 위험(RISK) 플래그가 발생합니다. 표시되는 모든 소비자는 하나의 재생 스펙트럼 공급자를 공유합니다. 플러그인은 8~128개의 막대와 초당 최대 60프레임을 요청합니다.

표시되는 소비자가 없을 때 중지됩니다. 선언된 `dataStream` 명령은 구성 요소가 표시되는 동안 라이브 텍스트 라인을 전달하며 초당 60라인 및 라인당 4096바이트로 제한됩니다. 검토에 나열되며 변경 사항은 위험(RISK) 플래그를 발생시킵니다. 숨겨진 구성 요소는 스트림과 하위 프로세스 그룹을 중지합니다. 실패 시 백오프로 재시도합니다.

작성 세부 정보는 `distro/PLUGINS.md`에 있습니다.

플러그인 작성자는 자체 색상, 이미지, 셰이더 및 애니메이션을 선택합니다. 테마 헬퍼(`api.palette`, color0–15 및 명명된 역할, 글꼴, 크기, 반경 및 `themeChanged`)는 선택 사항입니다. 위젯과 패널의 기본값은 `surface: "none"`이며 `"panel"`은 Eitr의 배경을 사용하도록 선택합니다. 명시적으로 저장된 위젯 배경은 선언을 재정의하며, 그렇지 않으면 선언이 적용됩니다. 제어 센터는 플러그인 캔버스 내부에 장식을 추가하지 않고 외부 페이지 프레임을 유지합니다.

패널은 `header: false`가 아닌 한 탐색 헤더를 유지합니다. Back/Escape는 계속 작동합니다. 타일의 기본값은 `look: "eitr"`입니다. `"custom"`은 호스트 활성화 및 포커스 링만 있는 전체 고정 슬롯을 그립니다. 바 슬롯은 호버 채우기나 틴트를 추가하지 않습니다. 상대 QML 이미지는 플러그인 디렉터리에서 확인됩니다. 경계, 중앙 시계, 검토, 기능 및 오류 처리는 변경되지 않고 유지됩니다.

예제는 두 가지 타일 스타일을 모두 보여줍니다.

## 단축키와 창 규칙

설정 > 단축키에서 동작이나 키를 검색하고 편집을 선택한 뒤 키 조합을 누릅니다.
Escape는 취소하고 Backspace는 확인 후 비활성화합니다. 충돌하면 교환 또는 취소를 선택합니다.
변경된 행에는 기본값과 초기화가 표시되며 모두 초기화는 모든 기본값을 복원합니다.
SUPER + M(잠금)과 D / SUPER + D / SUPER + SHIFT + D(받아쓰기 종료)는 예약되어 있습니다. 마우스 단축키는 바뀌지 않습니다.
학습 > 단축키는 현재 키를 표시하고 설명서 표는 기본값을 표시합니다.

설정 > 창 규칙에서 열린 창이나 클래스가 알려진 설치된 앱의 규칙을 추가합니다.
앱을 선택하고 떠 있는 창, 작업 공간(1–10, `name:NAME` 또는 `special:NAME`),
크기(양의 픽셀 값 두 개 또는 100% 이하 백분율), 불투명도(0.2–1.0)를 설정합니다.
클래스와 선택적 제목은 정확히 일치합니다. 편집으로 변경하며 삭제는 확인이 필요합니다.
개인 규칙은 Eitr 규칙 뒤에 적용됩니다. 초기 위치를 확인하려면 앱을 다시 여세요.

앱 선택기는 데스크톱 항목의 아이콘을 표시하며, 찾을 수 없으면 일반 창 아이콘을 사용합니다. 클래스가 이름과 다른 경우에만 이름 아래에 표시됩니다.

설정은 이 PC의 `~/.config/eitr/keybinds.json` 및 `window-rules.json`(또는
`$XDG_CONFIG_HOME/eitr`)에 유지됩니다. 도우미는 `hypr/keybinds.lua` 및
`hypr/window-rules.lua`를 생성하고 변경할 때마다 Hyprland를 다시 읽습니다. 업데이트해도 유지됩니다.
Lua 파일이 없거나 손상되면 기본값을 사용합니다. 모든 변경을 제거하면 생성 파일도 제거됩니다.
