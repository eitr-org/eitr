# 개발 도구

메인 > 개발에는 **AI**, **Cloud**, **Git 계정**, **모니터링**, **LazyVim** 및 **VS Code**가 그룹으로 묶여 있습니다. 프로젝트 선택기를 사용하면 선택한 디렉터리가 편집기에서 열리며, 테마 통합을 통해 LazyVim 세션을 포함하여 지원되는 열려 있는 편집기가 업데이트됩니다.

**Git 계정**은 기본 GitHub/GitLab ID, 폴더별 재정의, SSH 키 및 개별 제공업체 CLI 로그인을 구성합니다. 모든 규칙 변경에는 미리보기 확인이 필요하며, 프로젝트 리모트를 다시 쓰거나 전역 CLI 계정을 변경하지 않습니다. [Git 계정](handbook:git-accounts)을 참조하세요.

## 선택적 툴체인

설치 > 개발 언어 및 JavaScript 도구에서 원하는 도구를 설치할 수 있습니다. EITR의 바, 런처 또는 테마를 실행하는 데 Java, Flutter 및 데이터베이스 클라이언트는 필수가 아닙니다. 설치 > 데이터베이스에서는 선택적 데이터베이스 도구를 제공합니다. 설치 > 개발자 앱에서는 Bruno, Cursor, GitHub Desktop, Insomnia, JetBrains Toolbox, Meld, Postman, VS Code 및 Zed를 제공하며, 설치 > 생산성에서는 1Password, Bitwarden, Discord, LibreOffice, Obsidian, Slack 및 Thunderbird를 제공합니다. AUR 항목은 사용자의 머신에서 직접 다운로드되고 빌드됩니다. 일부 라이선스는 EITR에서의 번들 제공을 허용하지 않습니다.

개발 언어에서는 선택적 Arch 패키지로 **mise (다중 런타임)**도 제공합니다. `~/.zshrc`에 `eval "$(mise activate zsh)"`를 추가하여 수동으로 활성화하세요. 동일한 런타임에 대해 nvm/uv와 충돌할 수 있습니다. 언어별 기존 관리자는 변경되지 않고 그대로 유지됩니다.

## 웹 앱

설치 > 웹 앱 > 웹 앱 만들기는 이름과 주소를 입력받아 사이트를 자체 창에서 여는 런처를 추가합니다. 사이트 아이콘은 만들 때 HTTP(S)를 통해서만 다운로드됩니다. 매니페스트 형식이 잘못되었거나 아이콘을 사용할 수 없는 경우 페이지 아이콘이나 일반 브라우저 아이콘으로 대체됩니다.

주소에 로그인 자격 증명을 입력하지 마세요. 런처와 아이콘은 사용자 지정 `XDG_DATA_HOME`을 포함한 XDG 데이터 디렉터리를 사용하며, 두 메뉴를 통한 제거 시에도 동일한 위치가 사용됩니다. 웹 앱을 실행하려면 Chrome, Chromium, Edge, Brave 또는 Vivaldi(설치 > 브라우저)가 필요하며, Netflix와 같은 DRM 스트리밍 사이트는 Chrome이 필요합니다. 설치 > 웹 앱 또는 앱 메뉴에서 Delete를 눌러 웹 앱을 제거할 수 있습니다.

브라우저 프로필이 여러 개인 경우 웹 앱을 만들 때 어떤 프로필에서 열지 묻습니다. 이를 변경하려면 앱을 제거한 후 다시 추가하세요.

설치 > 브라우저에서는 Brave(AUR)도 제공합니다. 설치 > 생산성에서는 Basecamp와 Notion을 선택적 웹 앱으로 제공합니다. 이러한 레시피에는 이름과 URL만 포함되어 있으며, 설치할 때 사용자의 머신에 사이트 아이콘이 다운로드됩니다. 사전 설치되는 항목은 없습니다.

## AI 어시스턴트

설정 > AI 어시스턴트를 열어 기본값을 선택하고, 계정 및 어시스턴트 접근 권한을 관리하거나, 동의 후 어시스턴트 간 협업을 허용하세요. 개발 > AI에는 세션 런처가 유지됩니다.

**SUPER + A**는 홈 폴더에서 어시스턴트를 열고, 안전하게 지원되는 경우 해당 폴더를 신뢰하며, 지원되는 추가 지침 옵션을 통해 핸드북 안내를 전달합니다. 개발 > AI는 홈 폴더부터 시작하여 폴더를 요청하고 자체 명령처럼 해당 위치에서 어시스턴트를 엽니다. CLI 제한 사항은 distro/ASSISTANT-STARTUP.md에 나열되어 있습니다. 읽기 전용 빠른 채팅에는 Eitr 기본 안내서 및 관련 현지화된 핸드북 발췌본이 포함되어 있으며, 핸드북에서 다루지 않는 질문인 경우 이를 알려줍니다.

AI 코딩 에이전트를 나란히 실행할 수 있는 터미널인 [herdr](https://herdr.dev)가 Eitr에 기본 포함되어 있습니다. 첫 로그인 시(그리고 기존 데스크톱에서는 다음 로그인 시) Eitr는 백그라운드에서 herdr의 공식 설치 프로그램을 실행하여 다운로드를 확인하고 `~/.local/bin`에 `herdr`를 배치합니다. 연결이 없는 경우 이후 로그인 시 다시 시도합니다. 한 번 설치되면 다시 설치되지 않으므로 제거하면 제거된 상태로 유지됩니다. `herdr update`로 업데이트하세요. Walker > 학습 > Herdr 명령에 키와 명령이 나열되어 있으며, Walker > 개발 > 에이전트 작업 공간은 터미널에서 herdr 또는 cmux를 엽니다.

각 클라우드 어시스턴트에는 개발 > AI 아래에 계정 하위 메뉴가 있습니다. 기본값은 파일을 이동하지 않고 기존 구성과 로그인을 사용합니다. 계정 추가…는 라벨을 요청하고 검토를 표시한 다음 지원되는 경우 비공개 브라우저 창으로 CLI 자체 로그인을 엽니다(알 수 없는 브라우저는 일반 열기 프로그램 사용). Enter로 확인하고 Esc로 취소합니다.

계정을 선택하여 향후 대화형 세션, AI에게 문의 및 읽기 전용 헬퍼를 수동으로 전환하세요. 실행 중인 세션은 해당 계정을 유지합니다. Delete는 확인 후 추가된 계정과 로컬 구성을 제거합니다. 기본값은 제거할 수 없습니다. 선택한 계정을 제거하면 기본값으로 돌아가며 다른 계정에서 로그아웃되지 않습니다. Antigravity CLI는 지원되는 구성 폴더 재정의가 없으므로 기본값만 제공합니다.

Ratatoskr에는 하나의 로컬 계정이 있습니다. 계정 라벨 및 선택 항목은 이 PC의 `eitr/ai-accounts.json`(0600)에 유지되며, 별도의 폴더는 `$XDG_DATA_HOME/eitr/ai-accounts/`(0700) 아래에 있습니다. AI 사용량은 읽을 수 있는 계정을 어시스턴트별로 그룹화하고 읽을 수 없거나 지원되지 않는 사용량은 숨깁니다. 섹션은 로그인 시 닫힌 상태로 시작하며 세션 동안 열림 또는 닫힘 상태를 유지합니다.

개발 > AI는 설치된 각 어시스턴트(Antigravity CLI, Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, Grok Build, OpenCode 및 Pi)에 대한 메뉴를 제공합니다. 설치 > AI CLI에서 설치하세요. 아무것도 설치되지 않은 경우 개발 > AI가 해당 위치로 연결됩니다.

세션 메뉴는 **새 세션**을 맨 위에 두고 다른 동작은 알파벳순으로 정렬합니다. Claude Code 및 GitHub Copilot CLI는 **이름을 지정하여 새로 만들기**, **마지막 세션 계속하기**, **세션 선택기**, 이름 또는 ID로 재개(Claude는 **이름으로 재개**로 표시)를 제공합니다. Codex는 **마지막 세션 계속하기**, **세션 선택기**, **이름 또는 ID로 재개**를 제공합니다. Gemini CLI는 **마지막 세션 계속하기**, Walker **세션 선택기**, **번호로 재개**를 제공합니다. 마지막 옵션은 번호를 묻기 전에 터미널에 번호가 매겨진 세션 목록을 표시합니다.

Grok Build는 **마지막 세션 계속하기**, Walker **세션 선택기**, **ID 또는 제목으로 재개**를 제공합니다. OpenCode는 세션 ID 옵션을 통해 **마지막 세션 계속하기**, Walker **세션 선택기**, **ID로 재개**, **이름을 지정하여 새로 만들기**를 제공합니다. 새 이름은 세션을 생성하고 기존 ID는 세션을 재개합니다. Antigravity CLI는 지원되는 목록 또는 이름 지정 옵션 없이 **마지막 세션 계속하기** 및 **ID로 재개**를 제공합니다.

Pi는 사용 가능한 패키지 문서에서 세션 옵션을 확인할 수 없었기 때문에 **새 세션**만 유지합니다. Walker 선택기는 가능한 경우 세션 제목과 날짜를 표시하며 목록이 비어 있으면 메시지를 표시합니다. 이름/ID 입력 프롬프트에서 빈 상태로 두면 취소됩니다. 계정 하위 메뉴는 계속 사용할 수 있습니다.

LazyVim 또는 VS Code 프로젝트를 열면 먼저 홈 폴더부터 시작하여 폴더를 묻습니다(숨김 폴더는 제외됨). 폴더를 선택하여 더 깊이 들어가고, 열기를 눌러 현재 폴더를 사용하며, 뒤로 가기를 눌러 한 수준 위로 올라가거나 맨 위에서 메뉴로 돌아갈 수 있습니다. 키를 입력하면 현재 위치 아래 6단계 깊이까지 모든 폴더를 검색하며, `node_modules`, `target`, `build`, `dist`, `venv`, `__pycache__`는 건너뛰고 정확히 일치하는 이름의 폴더를 먼저 나열하며 깊은 폴더보다 가까운 폴더를 먼저 표시합니다. AI 메뉴의 폴더 선택 단계도 동일하게 작동합니다.

Antigravity CLI, Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, Grok Build, OpenCode 및 Pi는 명령으로도 시작할 수 있습니다. 도구가 없는 경우 Eitr가 이를 설명하고 설치 > AI CLI와 동일한 설치 옵션을 제공합니다. Enter로 설치를 확인하고 Esc로 취소합니다. 대화형 터미널이 없으면 명령이 설치 지침과 함께 종료됩니다. 설치된 바이너리가 이러한 런처보다 우선합니다. 각 도구 자체의 워크플로를 통해 로그인하세요. 어시스턴트 바이너리나 자격 증명은 번들로 제공되지 않습니다.

개발 > AI > 기본 어시스턴트는 이 컴퓨터에 설치된 어시스턴트 중 하나를 선택합니다. **SUPER + A**는 터미널에서 이를 열며 기본값이 없으면 선택기가 열립니다. SUPER + A 어시스턴트는 기본적으로 전체 권한으로 열립니다. 즉, 묻지 않고 파일을 변경하고 명령을 실행할 수 있습니다. 개발 > AI에서 연 어시스턴트는 일반 권한 프롬프트를 유지합니다.

일반 권한 프롬프트를 복원하려면 **설정 > AI 어시스턴트 > 어시스턴트 접근 권한 > 변경 전 확인**을 선택하세요. 기본 설정은 이 PC의 `eitr/ai.json`에만 저장됩니다. 조직 제한 사항이 있는 경우 권한 프롬프트가 강제됩니다. sudo는 여전히 비밀번호를 요구합니다. 헤드리스 협업 및 음성 알림은 읽기 전용으로 유지됩니다.

테마 변경은 기존의 읽기 가능한 Claude Code, Gemini CLI 및 Grok Build 설정에서 라이트/다크 테마 설정만 업데이트합니다. 기타 설정 및 서식은 그대로 유지됩니다. 누락되었거나 손상되었거나 제거된 클라이언트는 건너뜁니다. 지원되는 라이트/다크 설정이 없는 어시스턴트는 해당 터미널의 색상을 따릅니다.

설치된 SDK 버전 및 설치 프로그램 소스는 배포판 매니페스트에서 유지 관리됩니다. 핸드북 예제가 최신 업스트림 버전에 대한 약속이라고 가정하기보다는 실제 선택기를 따르세요. 툴체인 설치 시 다운로드가 필요할 수 있습니다.

### OpenCode, Pi 및 Eitr 스킬

설치 > AI CLI에서는 **OpenCode**(`opencode`, 공식 Arch 패키지) 및 **Pi**(`pi`, npm 패키지 `@mariozechner/pi-coding-agent`)도 제공합니다. 둘 다 개발 > AI 메뉴, 최초 사용 명령 런처 및 SUPER + A용 기본 어시스턴트 선택 항목을 가지고 있습니다. OpenCode는 전체 접근 권한을 위해 `--auto`를 사용합니다. 계정 메뉴에서는 기본값만 제공합니다. 구성 디렉터리 재정의가 자격 증명을 격리하지 않기 때문입니다. Pi는 `PI_CODING_AGENT_DIR`을 통해 별도의 계정을 지원하며 `--append-system-prompt`를 통해 핸드북 안내를 수신합니다. Pi에는 내장 권한 프롬프트가 없습니다. Eitr는 변경 전 확인 모드 또는 조직 제한 하에서 대화형 실행을 거부합니다. 둘 다 읽기 전용 협업 헬퍼가 아닙니다.

패키지된 **Eitr** 스킬은 안전한 데스크톱 변경 사항을 학습시키고 이 오프라인 핸드북을 안내합니다. 스킬 검색이 활성화된 경우 `eitr-config seed`는 동일한 소스를 Claude Code의 경우 `~/.claude/skills/eitr/SKILL.md`로, Codex, Gemini CLI 및 OpenCode의 경우 `~/.agents/skills/eitr/SKILL.md`로 복사합니다. `eitr-config update`는 편집되지 않은 복사본을 새로고침하고, 사용자가 만들었거나 편집한 복사본을 유지하며, 변경된 기본값을 검토할 수 있도록 `.eitr-new`에 기록합니다. 기존 설치 환경은 로그인 시 누락된 스킬을 수신합니다. CLI별 시작 지침은 활성 상태로 유지되며 로그인은 수행되지 않습니다.

### Ratatoskr(로컬, 실험적)

개발 > AI > 기본 어시스턴트는 항상 계정이나 구독이 필요 없는 **Ratatoskr(로컬, 실험적)**을 제공합니다. 처음 선택하면 변경하기 전에 일회성 다운로드에 대해 터미널에서 설명합니다: Arch 패키지 `ollama`(약 15 MB) 및 언어 모델 `qwen3:4b`(약 2.5 GB, Apache-2.0 라이선스). 한 번 확인하면(Enter로 확인, Esc로 취소) 패키지를 설치하고, 사용자 서비스 `eitr-ollama.service`를 생성하며, 진행률을 표시하면서 모델을 다운로드하고 이를 기본값으로 설정합니다. 단계가 실패하면 출력이 화면에 유지되고 이전 기본값이 유지됩니다.

모든 것은 이 PC에 유지됩니다. 서비스는 `127.0.0.1:11434`에서만 수신 대기하고 필요할 때 시작되며 모델을 `~/.local/share/eitr/ollama`에 보관합니다. 클라우드 어시스턴트보다 신뢰성이 눈에 띄게 떨어지며, 특히 특이한 표현에서 그렇고 프로세서에서 더 느립니다. 음성 알림은 다른 어시스턴트와 마찬가지로 답변을 확인하므로 잘못된 답변이 시스템을 변경하지 않습니다. **SUPER + A**는 모델과의 채팅을 열고 `/bye`는 이를 닫습니다. 어시스턴트 협업 헬퍼로 사용되지 않으며 AI 사용량 항목도 없습니다.

동일한 메뉴에서 **Ratatoskr**를 선택하고 **Delete**를 누르세요. 제거 시 한 번 확인을 요청한 다음 서비스와 모델을 삭제하고, 기본값이 로컬이었던 경우 재설정하며, 설정 시 설치한 경우 `ollama`를 제거합니다. `~/.ollama`에 있는 Ollama 고유 키와 채팅 기록은 유지됩니다.

## 모니터링

개발 > 모니터링을 사용하면 검색 한 번으로 대시보드에 접근할 수 있습니다. **대시보드 추가**는 서비스(Grafana, Datadog, Sentry, New Relic, Prometheus 또는 기타), 이름 및 주소를 요청하며, 이후 메뉴에서 브라우저로 대시보드가 열립니다. 대시보드는 이 컴퓨터의 `~/.config/eitr/monitoring.json`에만 저장됩니다. Delete로 제거할 수 있습니다. 주소에 비밀번호나 토큰을 절대 입력하지 마세요.

**모니터링 도구**는 명령줄 도구인 Prometheus의 `promtool`과 Sentry CLI를 설치합니다. Amazon Managed Grafana 작업 공간은 다른 AWS 도구와 함께 Cloud > AWS > 내 계정 > Grafana에 있습니다.

## 계정 및 클라우드 워크플로

AI 사용량을 확인하려면 클라이언트가 설치 및 구성되어 있어야 합니다. 일반 워크플로를 통해 로그인하세요. 계정 할당량 및 엔터프라이즈/API 결제는 지원되는 개인 계정 패널과 다를 수 있습니다. EITR에는 자격 증명이 번들되어 있지 않습니다.

클라우드 메뉴는 로컬 공급자 계정/프로필을 사용합니다. AWS 프로필은 로컬 AWS 구성 또는 구성된 EITR 클라우드 프로필 매핑에서 가져옵니다. Google Cloud는 계정 및 프로젝트와 함께 이름이 지정된 gcloud 구성을 나열합니다. 프로젝트가 없는 구성은 리소스 도구를 열 때 프로젝트를 선택하도록 요청하므로 프로젝트 검색 전에도 로그인이 계속 가능합니다.

Azure는 테넌트 ID와 함께 활성화된 구독을 나열합니다. 도구를 선택하기 전에 컨텍스트를 먼저 선택하세요. Google Cloud 및 Azure 도구는 전역 검색이 아니라 해당 컨텍스트 메뉴 내에서 검색됩니다. Google 컨텍스트를 열면 관련 없는 상속된 프로젝트 재정의가 지워집니다. 프로젝트가 없는 구성은 리소스 도구에 대해 하나를 선택하도록 요청합니다.

터미널에서 복귀해도 전역 CLI 기본값을 전환하지 않고 컨텍스트와 프로젝트 없는 구성에 대해 선택한 프로젝트를 유지합니다. 로그인, 인증 확인 및 새로고침은 감지된 각 컨텍스트 내에 있습니다. Google 로그인은 구성된 계정을 대상으로 하며, Azure 로그인은 해당 테넌트를 대상으로 하고 인증 후 이전 기본 구독을 복원합니다. Azure 새로고침은 구독 캐시를 업데이트하고 선택한 구독을 표시합니다.

AWS 계정은 AWS 구성 파일(`~/.aws/config` 또는 설정된 경우 `AWS_CONFIG_FILE`)에 일치하는 `[default]` 또는 `[profile NAME]` 섹션이 있어야 합니다. 자격 증명 파일에서만 발견된 프로필은 제외되며, 중첩된 서비스 설정 및 참조된 `[services NAME]` 그룹을 포함하여 `endpoint_url`을 설정하는 구성 프로필(빈 값 포함)도 Cloudflare R2와 같은 S3 호환 서비스를 대상으로 할 수 있으므로 제외됩니다. `EITR_AWS_PROFILES`는 적격 프로필에 라벨을 지정하거나 제한할 수 있지만 제외된 프로필을 포함할 수는 없습니다. EITR은 두 AWS 파일 모두 편집하지 않습니다.

각 제공업체 메뉴는 **AWS 계정 추가**, **GCP 계정 추가** 또는 **Azure 계정 추가**를 제공하므로 회사의 개발 및 프로덕션과 같이 필요한 만큼 계정을 설정할 수 있습니다. 먼저 이름을 묻고 해당 이름으로 공급자 CLI 자체 설정을 실행합니다. AWS SSO(IAM Identity Center) 또는 액세스 키를 통한 AWS 프로필, 로그인 및 프로젝트가 포함된 별도의 gcloud 구성, 또는 사용자가 구독 이름을 지정하는 Azure 로그인이 여기에 해당합니다.

`gcloud` 또는 `az`가 없으면 먼저 설치를 제안합니다. **Ctrl+R**은 계정 이름을 바꿉니다. 이름은 `~/.config/eitr/cloud-contexts.json`에 저장됩니다(AWS 프로필, gcloud 구성 또는 구독 ID로 키 지정). EITR은 환경을 추론하거나 자격 증명을 저장하지 않으며 추가 시 전역 CLI 기본값을 전환하지 않습니다. Grafana 및 클라우드 작업에는 해당 계정과 권한이 필요합니다.

일부 작업은 읽기 전용이지만 다른 작업은 원격 리소스를 수정할 수 있습니다. 확인하기 전에 요청된 작업과 계정을 검토하세요.

토큰, `.env` 비밀 및 자격 증명은 공유 dotfile 및 스크린샷 외부에 보관하세요. 셸 구성은 설치 프로그램이 프로필을 덮어쓰지 않고도 지원되는 관리자를 로드합니다. 학습에는 전용 LazyVim, tmux 및 cmux 참조가 유지됩니다.

## 어시스턴트 협업

개발 > AI > 어시스턴트 협업 허용은 기본적으로 꺼져 있습니다. 이를 활성화하면 로그인된 것으로 표시되는 설치된 Claude Code, Codex, Copilot, Grok 및 Gemini CLI 클라이언트가 서로 연결됩니다. 각 인계는 헬퍼의 구독 또는 API 결제를 사용하며 해당 한도에 반영됩니다. 다른 클라이언트의 API 키 전용 및 키링 전용 로그인은 감지되지 않습니다.

Gemini는 비어 있지 않은 `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY`가 있거나 `~/.gemini/settings.json`에서 `security.auth.selectedType`이 `gemini-api-key` 또는 `vertex-ai`로 설정된 경우에만 감지됩니다. 개인 Google 로그인은 Google에서 더 이상 지원하지 않으므로 포함되지 않습니다. Gemini는 MCP 서버 및 확장이 제외된 plan 모드로 헤드리스 실행됩니다. Eitr는 무료 API key로 이를 테스트했습니다. 읽기 전용 질문과 브리지를 통해 전달된 질문 모두 응답을 받았습니다. Plan 모드는 읽기 전용으로 문서화되어 있으며, Eitr는 파일, 셸 또는 plan 파일 동작을 독립적으로 검증하지 않았습니다.

주 어시스턴트에게 검토, 설명 또는 제안을 위해 다른 어시스턴트에게 자문을 구하도록 요청하세요. 호출하는 어시스턴트의 일반 도구 프롬프트를 통해 각 인계를 승인해야 합니다. Eitr는 이러한 도구를 사전 승인하지 않습니다. 어시스턴트 서버에 대해 자동 도구 승인을 활성화하지 마세요. 헬퍼는 읽기만 수행하며 편집은 주 어시스턴트가 담당합니다. 헬퍼는 다른 헬퍼에게 요청할 수 없습니다. 알림을 통해 누가 누구에게 요청했는지 식별되며 각 요청의 제한 시간은 3분입니다. 헬퍼는 호출자의 현재 작업 디렉터리를 읽으며 질문과 컨텍스트가 해당 어시스턴트의 제공업체로 전송될 수 있습니다.

이 스위치는 각 어시스턴트 자체 명령(`claude mcp add`, `codex mcp add`, `copilot mcp add`, `grok mcp add`, `gemini mcp add -s user`)을 통해 하나의 `assistants` MCP 서버를 등록하므로 각 어시스턴트가 자체 설정을 작성합니다. 동일한 이름의 기존 서버는 변경되지 않고 보고됩니다. 변경 사항은 이 컴퓨터의 `~/.local/state/eitr/assistants.json`(또는 `XDG_STATE_HOME`)에만 기록됩니다. 스위치를 끄면 Eitr의 항목만 정확히 제거되며, 이후 항목이 편집된 경우 Eitr는 이를 유지하고 충돌을 보고합니다.

스위치를 변경한 후 기존 어시스턴트 세션을 다시 시작하세요. 실제 계정 인계는 아직 별도의 엔드투엔드 검증을 기다리고 있습니다.

Antigravity CLI(`agy`)는 설치 > AI CLI 및 최초 사용 런처를 통해 개인 Google 계정에서 사용할 수 있습니다. 번들로 제공되지 않습니다. 다운로드를 확인하는 Google의 공식 설치 프로그램을 통해 설치되며 Google 계정으로 로그인합니다. 아직 어시스턴트 협업 헬퍼로는 제공되지 않습니다. 이미 설치된 `agy`는 정상적으로 실행할 수 있습니다.

Gemini CLI에는 Gemini API 키 또는 Google Cloud/회사 계정이 필요합니다. Antigravity는 협업 헬퍼가 아닙니다. 헤드리스 모드에서는 읽기조차 거부합니다. 유일한 잠금 해제 방식은 권한을 우회하거나 전역 규칙을 변경하는 것입니다. Eitr는 실행별 권한 또는 읽기 전용 헤드리스 모드가 제공될 때 이를 재검토할 예정입니다.

### 추가 제공업체

개발 > Cloud에는 Cloudflare(`wrangler`), DigitalOcean(`doctl`), Hetzner Cloud(`hcloud`), Oracle Cloud(`oci`), Vercel, Netlify 및 IBM Cloud(`ibmcloud`)도 나열됩니다. 숫자나 하이픈이 포함된 소문자 이름을 사용하여 계정을 추가하세요. 이러한 계정은 `~/.config/eitr/cloud-accounts/<provider>/<name>` 아래의 비공개 작업 공간이며 기존 제공업체 구성은 절대 가져오지 않습니다. 선택한 제공업체와 작업 공간은 도구 선택기와 터미널에 계속 표시됩니다. 터미널에서 동일한 작업 공간으로 돌아가며 Shift+Backspace를 누르면 계정 목록으로 돌아갑니다. 작업 공간을 선택해도 전역 CLI 기본값은 전환되지 않습니다.

누락된 `wrangler`, `doctl` 및 `hcloud`는 Arch의 공식 저장소(extra의 `doctl` 및 `hcloud`)에서 설치를 제안합니다. Oracle Cloud 및 IBM Cloud는 `distro/installers.json`의 공식 HTTPS 셸 설치 프로그램을 사용하며 Oracle은 `--accept-all-defaults`를 전달합니다. Vercel(`vercel`) 및 Netlify(`netlify-cli`, 명령 `netlify`)는 기존 NVM/npm 설치 레시피를 사용합니다. 설치 시 확인이 필요합니다. 로그인 및 계정 작업은 선택한 비공개 작업 공간 내에서만 실행됩니다.

DigitalOcean 및 Hetzner는 기본 컨텍스트를 나열하며 Oracle은 해당 작업 공간의 `~/.oci/config`에서 프로필을 나열합니다. 컨텍스트/프로필을 선택하면 로컬 선택 항목이 저장되고 전역 기본값을 변경하지 않고 명령별 플래그가 사용됩니다. Vercel 및 Netlify는 기본 전환 동작을 노출하며 이후에 선택한 팀/계정 라벨을 입력하세요. Vercel은 로그인 전에 범위를 묻고 후속 명령에 `--scope TEAM`을 전달합니다.

IBM은 SSO 및 API 키 로그인을 제공하고 `ibmcloud target`을 표시하며 명시적인 계정과 리전을 대상으로 지정합니다. 메뉴로 돌아올 때 선택한 컨텍스트/프로필/범위/계정 및 저장된 리전이 계속 표시됩니다. 이러한 라벨은 로컬 선택 항목이며 검증된 원격 ID가 아닙니다. 기존 자격 증명 및 공급자 재정의는 상속되지 않습니다. 브라우저 콘솔은 자체 세션을 사용하므로 작업하기 전에 계정을 확인하세요.

7개의 비공개 작업 공간 제공업체는 간단한 설명과 함께 중립적인 리소스 및 동작 아이콘을 사용합니다. 계정은 알파벳순으로 먼저 표시되고 그 뒤에 계정 추가가 이어지며, 도구는 번역된 이름순으로 알파벳순 정렬됩니다. 선택기에는 선택한 계정, 컨텍스트 및 저장된 리전이 표시되며 각 읽기 전용 보고서는 출력 위에 해당 컨텍스트를 반복하여 표시합니다. 보고서는 공유 AWS 페이저를 유지하며 추가 리소스 명령이나 로그 검색은 도입되지 않습니다.

| 제공업체 | 로그인 | 목록 / 전환 / 명령 컨텍스트 |
| --- | --- | --- |
| Cloudflare | `wrangler login` | — |
| DigitalOcean | `doctl auth init --context NAME` | `doctl auth list`; `doctl auth switch --context NAME`; `--context NAME` |
| Hetzner Cloud | `hcloud context create NAME` | `hcloud context list`; `hcloud context use NAME`; `--context NAME` |
| Oracle Cloud | `oci session authenticate --profile-name NAME --region REGION` | `~/.oci/config`; `--profile NAME --auth security_token` |
| Vercel | `vercel login` | `vercel switch`; `--scope TEAM` |
| Netlify | `netlify login` | `netlify switch` |
| IBM Cloud | `ibmcloud login --sso`; `ibmcloud login --apikey` | `ibmcloud target`; `ibmcloud target -c ACCOUNT -r REGION` |

클라우드 탐색은 실제 Elephant 메뉴를 사용합니다. Shift+Backspace는 이전 메뉴로 이동합니다. 서비스 또는 리소스 선택은 포함된 메뉴로 돌아가고, 계정 메뉴는 제공업체의 계정 목록으로 돌아가며, 해당 목록은 Cloud로 돌아갑니다. 선택한 계정과 컨텍스트는 계속 표시됩니다. Eitr는 이 탐색 선택 항목을 `~/.config/eitr/cloud-navigation.json`에 저장하며 제공업체 CLI 기본값은 변경되지 않습니다. 보고서는 페이저를 유지하고 로그 검색은 fzf를 유지하며 설정은 검토된 터미널 형식을 유지합니다. 자유 텍스트 검색 프롬프트는 Walker에서 계속 텍스트를 입력받으며 탐색 목록이 아닙니다.

계정 행에서 Delete 키를 누르거나 메뉴 내에서 **계정 삭제**를 사용하여 계정을 삭제할 수 있습니다. 확인 메시지에는 제공업체와 계정 이름이 표시됩니다. 원격 계정에 영향을 주지 않고 이 컴퓨터에서 해당 계정에 대한 공급자의 로그인을 제거합니다. 취소하면 아무것도 변경되지 않습니다. 선택한 Eitr 비공개 계정 폴더만 제거되며, 심볼릭 링크, 제공업체 루트 외부의 경로 및 실행 중인 Eitr 동작이 있는 계정은 거부됩니다. AWS, Azure 및 Google Cloud에는 새로운 삭제 동작이 없습니다. 확인은 취소 및 확인과 함께 Walker 내에서 열리며 터미널은 열리지 않습니다.

읽기 전용 보고서는 선택한 비공개 계정 환경과 기존 클라우드 페이저를 사용합니다. Cloudflare: Account, R2 Buckets, D1 Databases, KV Namespaces, Pages Projects, Queues. DigitalOcean: Droplets, Apps, Databases, Kubernetes, Volumes, Domains, Load Balancers, Balance. Hetzner: Servers, Volumes, Networks, Firewalls, Load Balancers, Primary IPs, Snapshots. Oracle: Compartments, Instances, Buckets, VCNs. Vercel: Projects, Deployments, Domains.

Netlify: Status, Sites. IBM: Account, Target, Resource Groups, Service Instances. DigitalOcean 및 Hetzner는 항상 선택한 컨텍스트를 전달하고, Oracle은 선택한 프로필 및 보안 토큰 인증을 전달하여 해당 계정의 비공개 프로필에서만 테넌시를 읽습니다. 버킷 목록 조회는 먼저 네임스페이스를 읽습니다. Vercel은 선택한 팀 범위를 전달합니다. 오류는 읽을 수 있는 상태로 유지되며 다른 계정으로의 재시도를 트리거하지 않습니다.

로그 검색은 기존 fzf 뷰어를 유지합니다. 실제 계정을 사용한 실시간 확인은 보류 상태로 유지됩니다.

클라우드 계정, Git 계정(추가 및 편집), 모니터링 대시보드 및 웹 앱의 설정 양식은 왼쪽에 단계가, 오른쪽에 현재 답변이 나열됩니다. 방향키 또는 Tab을 사용하여 단계를 선택하고 Enter를 눌러 응답하세요. 검토에서는 적용하기 전에 모든 응답을 나열합니다. 왼쪽 방향키 또는 화살표 키로 단계로 돌아가고, 긴 검토 내용은 PgUp/PgDn을 사용하여 스크롤하세요.

Esc 또는 Ctrl+C는 저장하지 않고 취소합니다. 벤더 로그인은 검토 후에 시작되며, 실패하거나 중단된 로그인은 새 계정을 폐기합니다. Google Cloud는 로그인 전에 선택적 프로젝트 ID를 묻고, Azure는 로그인 전에 선택적 구독 라벨을 묻고 그렇지 않으면 각 구독의 기존 이름을 유지합니다. Vercel은 로그인 전에 범위를 묻습니다.

## Docker

Docker, docker-compose 및 Lazydocker가 설치되어 있지만 Docker 서비스는 기본적으로 꺼져 있습니다. `sudo systemctl enable --now docker.service`로 활성화하세요.

`docker ps`에서 권한 거부(permission denied)가 보고되면 `sudo usermod -aG docker $USER`로 사용자를 추가하세요. docker 그룹의 멤버십은 root와 동등한 권한을 가집니다. 로그아웃했다가 다시 로그인하거나 단일 터미널에서 `newgrp docker`를 사용하세요. `id -nG`로 그룹을 확인하세요.
