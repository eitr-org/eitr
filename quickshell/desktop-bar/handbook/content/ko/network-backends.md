# 네트워크 백엔드

설정 > 연결 > Wi-Fi > WiFi 백엔드에서 iwd(새 설치 기본값) 또는 wpa_supplicant 기반의 NetworkManager를 선택할 수 있습니다. 둘 다 DNS에 systemd-resolved를 사용합니다. 공유 WiFi 패널은 다음 부팅을 위해 저장된 선택 항목이 아니라 현재 실행 중인 백엔드를 감지합니다. 현재 연결은 다시 시작되지 않습니다. root 소유 도우미가 파일을 준비하고 `--now` 옵션 없이 부팅 서비스를 활성화 또는 비활성화한 다음 재부팅 여부를 묻습니다. 재부팅을 거부하면 다음 재부팅까지 선택 사항이 대기열에 유지됩니다.

저장된 WiFi 프로필은 각 백엔드의 자체 스토리지에 유지됩니다. 자동으로 삭제되거나 변환되지 않으므로 처음 전환할 때 다시 연결해야 하며, 이전 백엔드로 다시 전환하면 기존 프로필이 재사용됩니다. 전환하기 전에 사용자 지정 고정 IP, VPN, 브리지, networkd 파일 또는 기타 네트워크 관리자를 검토하세요. 마스킹된 서비스, 다른 활성 관리자 또는 사용자 지정 리졸버가 있으면 자동으로 대체하지 않고 전환을 거부합니다. 원래 관리되던 파일과 서비스 활성화 상태는 `/var/lib/eitr/network-backend`에 비공개로 저장되며, 원래 네트워크 구성 복원을 사용하면 현재 네트워킹을 중단하지 않고 다음 부팅을 위해 복원합니다.

`eitr-desktop` 패키지에는 두 백엔드와 root 소유 도우미인 `/usr/lib/eitr/eitr-network`가 모두 포함되어 있습니다. 도우미를 직접 복사하지 말고 패키지를 설치하세요(배포판 README 참조). 이전에 수동으로 설치한 도우미가 있다면 `distro/system/adopt-unowned-files.sh --apply`로 아카이브할 때까지 패키지 설치가 차단됩니다. 사용자가 쓰기 가능한 경로에 있는 도우미는 절대 권한을 승격하여 실행하지 마세요. 도우미를 설치한다고 해서 백엔드가 선택되는 것은 아닙니다.

## 기업용 WiFi

패널은 사용자 이름, 선택적 익명 ID, 비밀번호, 인증 서버 도메인 및 PEM CA 인증서 경로를 사용하는 PEAP/MSCHAPv2 및 TTLS/PAP를 지원합니다. 이러한 설정은 네트워크 관리자에게 문의하세요. 서버 인증서 유효성 검사는 필수입니다. EAP-TLS/클라이언트 인증서, SIM/AKA 및 기타 고급 방식에는 여전히 외부 프로비저닝이 필요합니다. Impala는 이러한 구성을 위한 선택적 대체 수단으로 유지되므로 일반적인 방법이 지원된다는 이유만으로 제거하지 마세요.

자격 증명은 명령줄 인수가 아닌 프로세스 stdin 및 D-Bus를 통해 전달됩니다. NetworkManager는 일반 연결 프로필을 저장하며, iwd 프로비저닝은 PolicyKit 인증과 CA가 포함된 비공개 root 소유 `.8021x` 프로필을 사용합니다. 기존 기업용 프로필은 덮어쓰지 않으므로 교체하기 전에 프로필을 명시적으로 지우세요. root 소유이며 그룹 또는 다른 사용자의 쓰기 권한이 없는 도우미만 허용됩니다. 자동화된 테스트에서는 실제 백엔드 전환, WiFi 연결 또는 기업용 인증이 실행되지 않으므로 하드웨어에서 테스트되었다고 명시하기 전에 예비 하드웨어 또는 격리된 VM에서 둘 다 검증하세요.
