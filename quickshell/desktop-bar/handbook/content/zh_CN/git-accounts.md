# Git 账户

打开 Walker > 开发 > Git 账户。GitHub 和 GitLab 账户可以同时使用，包括在同一提供商或企业主机名上的多个账户。GitHub CLI (`gh`) 和 GitLab CLI (`glab`) 随新系统安装一并提供。现有的 ISO 镜像必须重新构建以包含相关更改。

每个账户都以独立的一行显示 Git 在何处使用它：**默认**、其**文件夹名称**或**尚未使用**。在某个账户上按 Enter 可打开其操作菜单；按 Shift + Backspace 可返回列表。

## 初次设置

1. **添加账户**会打开通用的分步向导，用于设置提供商、账户名称、提交作者姓名与邮箱、主机名、可选的现有 SSH 私钥、默认身份以及文件夹规则。所有回答都会显示在“审查”步骤中；在确认应用之前可随时返回修改任一步骤。按 Esc 或 Ctrl+C 可取消且不保存任何内容。
2. **导入现有设置**可读取手动配置的身份：`~/.gitconfig` 或 `~/.config/git/config` 中的默认 `user.name`/`user.email` 以及按文件夹划分的 `includeIf "gitdir:…"` 规则，包括引入的文件所路由的 SSH 别名与密钥 (`url.<alias>.insteadOf`)。它会列出检测到的内容，并在确认后创建匹配的账户和规则。您的文件保持不变；带通配符的文件夹模式将被列为跳过项。

## 默认账户与文件夹规则

**默认**账户适用于所有未配置独立账户的文件夹。**文件夹**账户仅适用于该文件夹内部的代码仓库。越具体的文件夹优先级越高；代码仓库本地的设置以及 Git 命令行参数或环境变量覆盖项始终拥有最高优先权。EITR 会保留现有的全局配置和注释，仅在 `~/.gitconfig` 末尾添加一个带标记的 include，确认后的规则将覆盖外部引入的身份。

Walker 中的账户操作在保存前均需确认，并通过通知报告结果：**设为默认**或**停止用作默认**、**添加文件夹**（选取 `~/Development` 或其内部的文件夹，或点击**其他文件夹…**以键入路径）以及**移除文件夹**。Git 匹配实际的 `.git` 目录，因此关联的 worktree 和子模块可以沿用父仓库的账户。

## SSH 密钥

提交身份并不代表授予了代码仓库的访问权限。**显示公钥**可打印该账户的公钥，将其复制到剪贴板，并指明应添加到的提供商设置页面（GitHub：Settings > SSH keys）。**设置现有 SSH 密钥**可从 `~/.ssh` 中选取密钥；**创建 SSH 密钥**会生成带有密码短语的 Ed25519 密钥并显示其公钥。**测试连接**会通过通知反馈提供商的问候信息（如“Hi username!”）。切勿泄露或分享私钥。

密钥仅作用于其对应提供商的 SSH 主机名。启动器会在不建立连接的情况下解析现有的 SSH 别名，随后仅使用选定的密钥，忽略该连接的其他 SSH 配置。代理连接将被拒绝；针对复杂的高级网络配置，请保留仓库本地的 `core.sshCommand`。Known-host 主机验证保持启用。未配置专属密钥的账户使用常规 SSH，不会冒用其他账户的密钥。HTTPS 凭据和凭据助手保持不变。

## 提供商 CLI

**登录到 CLI** 会为每个账户登录到独立的配置目录；它不会切换常规的全局 `gh` 或 `glab` 账户。继承的提供商令牌环境变量在该进程中会被剥离。确认提示会明确说明令牌保存在私有的未加密 CLI 配置文件中，避免同一主机上的不同账户共用密钥环条目。切勿分享 `~/.config/eitr/git-accounts/cli`；它不包含在 EITR 备份中。

在代码仓库中，可使用能感知具体账户的 CLI：

```sh
eitr-git cli auth status
eitr-git cli repo view
```

选定的默认/文件夹账户会自动决定调用 `gh` 还是 `glab`。常规 CLI 命令保留其现有的全局行为。登记 SSH 密钥并不会自动验证 CLI API 操作。未打包 Bitbucket CLI。

## 移除与恢复

**编辑姓名和电子邮件**可修改身份字段；**移除账户**在确认后会删除账户及其规则。移除文件夹规则会回退到更宽泛的规则或默认账户；清除默认账户会恢复剩余规则之外的现有 Git 设置。项目、密钥和 CLI 凭据绝不会被删除，移除规则也不会撤销提供商那端的访问权限。

版本化设置保存在 `~/.config/eitr/git-accounts.json` 中。每次应用更改都会将全局 Git 文件、活动引入和设置以私有权限备份至 `~/.local/state/eitr/git-account-backups/<id>`。`manifest.json` 记录了原始路径、备份文件名和文件权限模式。密钥和 CLI 令牌绝不会被复制。如需手动恢复，在恢复文件前请仔细检查清单，并保留自备份以来所作的修改。被修改或损坏的 EITR include 块将被拒绝，而不会被静默替换。

参考资料：[Git 条件引入](https://git-scm.com/docs/git-config)、[GitHub CLI 配置文件](https://cli.github.com/manual/gh_help_environment)、[GitLab CLI 配置文件](https://docs.gitlab.com/cli/configuration/)。
