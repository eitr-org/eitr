# 故障排除

## 检查此电脑

打开“设置 > 检查此电脑”并按“检查此电脑”以获取只读排查结果。它绝不会修复或重启任何内容。如需交互式报告、更深入的检查以及下文所述的复制操作，请运行 `eitr check` 或使用“Walker > 设置 > 系统 > 检查此电脑”。缓存的更新列表不会刷新；DNS 解析使用网络。`eitr check --json` 输出技术证据且不出现交互提示。

除重启、磁盘空间、更新、恢复、服务、内存、网络和安全之外，它还检查显示器（屏幕运行低于其分辨率的最佳刷新率）、图形显卡（每个显卡的驱动程序和硬件加速）以及音频（声音系统、输出设备、音量和麦克风）。每个警告和问题均以一句通俗简明的说明开始（说明其含义和建议尝试的操作），随后附带**详情：**，列出技术证据及修复位置。

**运行更深层的检查（需要输入密码）**：按 Enter 在同一个终端中运行 `sudo /usr/lib/eitr/eitr-system selfcheck-deeper`，或按 Esc 跳过。检查结果会替换匹配的已跳过检查。这会读取 root 的 Snapper 配置、保留的升级前后快照对、上次成功软件包升级的描述、现有的 Btrfs qgroups、引导防护 JSON、已挂载的出厂还原清单以及通过 `pacman-key --list-keys` 列出受信任的 Arch Linux/Eitr 密钥。

它绝不会启用配额或挂载出厂还原点。缺失的证据会被跳过并说明原因。单独的出厂还原清单无法验证归档的完整性。ESP 检查仅在未以读写方式挂载的唯一识别 FAT ESP 上使用 `fsck.vfat -n`；否则它会提示需要未挂载的文件系统并跳过。

失败的单元最多显示三个名称和一个状态命令。快照描述不能证明后续的桌面更新步骤成功；hook 日志没有时间戳。桌面栏加载错误没有结构化查询。完成后，按 **Enter** 复制脱敏后的报告，按 **Esc** 关闭。在共享前请先审核文本；复制操作需要 `wl-copy`。

## 菜单操作提示缺少工具

全新安装的发行版清单包含桌面运行时依赖项，但现有的 Arch 桌面可能缺少其中某些依赖。请阅读具体的错误信息，并通过“安装 > 软件包 > Pacman”或常规的全系统更新安装相应的软件包。不要仅仅因为设置位于原生面板中就移除 BlueZ/iwd/PipeWire/WirePlumber：面板仍然需要这些后端支持。

本手册不需要 `less`。它是原生窗口中的内置 Markdown。如果阅读器报告目录缺失或过旧，请更新 EITR 桌面文件。

## 缺少 root 所属的辅助工具

网络切换、安全、电池限制和恢复操作需要经过审核的 root 所属辅助工具。仅包含 dotfiles 的桌面可能尚未安装打包好的辅助工具。请参阅相关章节；绝不要通过以 root 身份运行用户可写的下载辅助工具来绕过检查。选择器绝不能仅仅因为您打开了它就断开网络连接。

## 配置或服务问题

Quickshell 显示易读的重新加载错误，并在可能的情况下保留先前的正常配置。请修复提示的文件；不要反复重启登录管理器。**绝不要在桌面会话期间重启 SDDM。**

重启 Elephant 会重新加载菜单定义。其服务必须为辅助工具和后备启动保留 `KillMode=process`。在 uwsm 会话中，启动的应用和终端在独立的应用程序作用域中运行。主题会重新生成样式，因此如果更改在稍后消失，请一并修复生成器及生成的文件。

## WiFi 数据停止刷新

桌面栏在各个屏幕之间共享一个 WiFi 读取代理。如果它退出，上次正常的网络数据将继续标记为过旧，同时代理以递增的延迟重试。在六次失败的重试后，它将等待显式的重试操作。原生控件依然可用。WiFi 操作在各屏幕间共享有序队列和忙碌状态。如果某项操作超时或代理退出，其结果是未知的：在显式重试之前请先刷新状态。写入操作绝不会自动重放。二维码生成依然是独立的辅助工具。

如需技术状态快照，请使用：
`eitr-shell desktop-bar ipc call -- data status`。它报告主题数据存在时长、错误代码、正在进行的读取、观察者和重启情况，且不包含网络名称或地址。使用 `eitr-shell desktop-bar ipc call -- data retry` 重试。

OBS 捕获在各屏幕间使用相同的代理。仅当已知存在 OBS 窗口或进程时，每 2 秒运行一次共享检查。仅当打开录制面板时，录制详情每 2 秒刷新一次，并提供共享状态。未知状态会保留上次已知的捕获状态并禁用控件，直到成功刷新为止。

捕获操作和选项写入共享有序队列；超时或代理退出会使结果处于未知状态，且绝不会自动重复该操作。独立 OBS 命令对 Walker 和截图快捷键依然可用。

电池、电源配置文件和飞行模式状态也共享此代理。电池读取每 30 秒运行一次；配置文件和无线电读取仅在打开相关面板时运行。外围设备电池不会启用笔记本电脑控件。低电量 hook 和警告保留其阈值。电源配置文件和飞行模式操作是有序的，向发起请求的面板报告错误，且在出现未知结果后绝不会重放。独立命令依然可用。

显示拓扑、亮度和夜览读取也共享该代理。显示器事件和主显示器首选项更改会刷新跨屏幕的几何布局。亮度和夜览仅在被观察时刷新；DDC 亮度不会进行轮询。显示试用保持其独立的自动回滚，即使桌面栏或代理退出也是如此。独立显示和空闲变暗/恢复命令依然可用。

## 安装与恢复检查

EITR 仍处于测试阶段：虚拟机测试覆盖并不能证明每个 WiFi 网卡、蓝牙配对代理、TPM、GPU、指纹识别器或 Secure Boot 设置都能正常工作。当前后端/企业级 WiFi 代码经过模拟测试；在依赖它之前请先测试真实的身份验证。仓库清单更改时现有的 ISO 文件不会随之更改：重新构建 payload/ISO 才能将这些更改应用到新安装中。

在安装到备用 SSD 之前，请备份其他磁盘并仔细验证目标磁盘。安装程序会抹掉您确认的磁盘。请将加密密码和恢复密钥离线妥善保存。同一块 SSD 上的快照并不是独立的备份。请先阅读[恢复与快照](handbook:recovery)。

## 报告问题

**Walker > 设置 > 系统 > 报告问题**收集 EITR 和软件包版本、显卡硬件、Hyprland 错误、失败的服务、近期警告、过去一周的崩溃记录、上次启动的错误、安装日志以及近期的软件包更改到 `~/Documents/eitr-problem-report-<time>.txt` 中，该文件仅对您可读。它会移除您的用户名、计算机名称、主目录路径、电子邮件、IP 和 MAC 地址，但日志中仍可能提及应用程序或文件名：请在发送前仔细阅读。

报告不会自动发送，终端仅显示报告保存的位置。随后它提供发送方式或先阅读报告的选项：

1. **电子邮件**发送至 `reports@eitr.info`：您的邮件应用会打开包含简短摘要的邮件；请附上保存的文件。
2. **GitHub issue**（需要 GitHub 账户）：浏览器在 Eitr 项目上打开新 issue。Issue 是公开的。
3. **复制**报告以粘贴到任何位置。
4. **阅读**报告：在文本编辑器中打开。

报告仅用于查找和修复问题，问题修复后即予删除。电子邮件会共享您的邮箱地址；回复该邮件可随时要求删除您的报告。

### 当程序崩溃时

崩溃通知默认开启。用户服务为您的程序监视新的、可读的 systemd-coredump 记录。每次崩溃提供“报告问题”、“忽略”和“将此程序静音”；当安装并选择了默认助手时，还会显示“咨询 AI”。同一程序的重复崩溃限制为每五分钟通知一次。

导致会话结束的崩溃会在下次登录时提示，但在您注销、重启或关机后一分钟内崩溃的程序则不会提示：它们只是在其周围的桌面正在退出。在“设置 > 通知”或“控制中心 > 通用 > 快捷操作”中切换崩溃通知。

偏好设置和静音的程序路径保存在 `~/.config/eitr/crash-help.json` 中；从 `ignored` 中移除路径可重新允许通知。

“咨询 AI”使用仅来自 `coredumpctl info` 的程序、信号和回溯信息打开默认助手，请求解释和建议修复方案，除非您同意，否则不会更改系统。不传递核心转储文件本身。当您选择此操作时，您的助手可能会将该摘要发送给其提供商。“报告问题”将相同的摘要附加到现有的报告工作流中：在共享前请先审核；不会自动发送任何内容。

如果栏在没有崩溃的情况下消失，Eitr 会在 `~/.local/state/eitr/shell-exits/` 中记录它的结束情况：日志末尾、可能的核心转储和内存不足消息（保留最新十个）。重启和注销不会留下记录。报告时请附上最新的文件。

## 自定义与更新

EITR 自身的代码安装在 `/usr/share/eitr` 下并随 `eitr-desktop` 软件包更新；您的设置保存在 `~/.config` 中。请将持久更改放在更新绝不会触碰的位置：

- 显示器、设备、额外快捷键绑定和规则：`~/.config/hypr/local.lua`。
- Shell 增项：`~/.config/eitr/shell.local.zsh`。
- 终端选项：`~/.config/kitty/local.conf`。
- 启动器颜色：`~/.config/walker/style.override.css`。
- 随附文件的完整替代品：`~/.config/eitr/overrides` 下的相同相对路径。该文件将不再接收来自更新的修复。

当您切换主题以及每次软件包更新后，主题文件（如 `kitty/theme.conf` 和 Walker 样式）均会重新生成；以前的副本保存在 `~/.local/state/eitr/generated-backups` 下。当更新更改设置的存储方式时，会在登录时转换一次；转换失败会报告并在下次登录时重试（`~/.local/state/eitr/migrations.log`）。
`eitr-config status` 列出当前生效的设置和替代项。

失败的任务终端在选定默认助手时提供 **A: 咨询 AI**；按 **Esc** 关闭。内存中仅保留最后 200 行输出，在共享前移除 ANSI 转义字符并隐藏明显的机密信息：云端助手会将此输出发送给其提供商，而 Ratatoskr 将其保留在本地计算机上。

硬件在各屏幕和“硬件”面板之间使用同一个代理采样器。打开硬件面板会立即刷新，随后在任何硬件面板处于打开状态时每两秒刷新一次。关闭最后一个面板会停止采样。CPU、根分区磁盘和 GPU 标识在代理会话期间保持缓存，包括不可用或超时的 GPU 探测。读取失败时，上次正常的部分保持可见。独立的 `system-details.py` CLI 依然可用；`eitr-shell desktop-bar ipc call -- data status` 包含 `hardware.details` 诊断信息。

远程访问使用共享代理：Sunshine 的状态在打开时刷新，并且在任何远程面板观察它时每 10 秒刷新一次。关闭最后一个面板会停止状态读取。策略可用性仅在启动和策略更改时读取。操作仍使用现有的 Walker 辅助工具；代理不更改任何远程设置。独立的 `remote-status.py` CLI 依然可用。`eitr-shell desktop-bar ipc call -- data status` 包含 `remote.status` 和 `remote.availability` 诊断信息。

天气在各屏幕和面板之间共享同一个默认天气预报，使用 15 分钟的缓存和刷新间隔。城市搜索和备选城市仅属于发起请求的面板，不替换默认天气预报。AI 使用量共享其缓存，在打开时刷新，随后仅在用量面板处于打开状态时每五分钟刷新一次。

关闭最后一个面板会停止排队的账户任务；活动调用在其现有超时内完成，随后释放 AI 适配器。严格遵守提供商冷却时间。独立天气和 AI 命令以及会话选择文件依然可用。`eitr-shell desktop-bar ipc call -- data status` 包含 `weather.default` 和 `ai.usage` 计数器，且不包含账户名称或提供商有效负载。

更新检查在各屏幕间共享桌面栏数据代理：启动后 45 秒、每六小时以及部分更新或手动刷新后检查一次；成功的系统更新后，图标显示为最新状态，直到下一次检查。在检查期间发起的刷新会排队一次后续操作。离线和无法读取的检查绝不会报告“已是最新”；右键单击更新图标可重试。更新通知和任务终端仍由 shell 所属。独立更新检查 CLI 依然可用。上述数据状态命令包含 `updates.status` 诊断信息。
