# Applications et installation

Avant l’installation des paquets officiels, le terminal indique qu’il recherche les mises à jour du système en attente. Cette vérification peut prendre un moment avant de vous demander le mot de passe administrateur. Les installations avec Flatpak indiquent également leur étape de préparation. Si des mises à jour sont en attente, il explique pourquoi : Arch n’installe des apps que sur un système à jour, et installer maintenant mettrait aussi à jour une partie du système sans instantané de récupération. Entrée lance la Mise à jour du système avec son instantané puis installe ; Échap annule sans rien changer.

**SUPER + Space** et Principal > Applications ouvrent la même liste. Enter lance une application. Delete permet de la désinstaller dans Applications après confirmation. La recherche globale par **SUPER + F** lance les applications sans proposer leur désinstallation. Il n’existe pas de menu distinct fondé sur des applications épinglées.

Saisir dans le menu principal recherche les applications installées et les actions de tous les sous-menus. Dans un sous-menu comme Système ou Installer, la recherche couvre celui-ci et ses descendants. Les dispositions de clavier et ce qui se trouve sous un compte cloud (services, ressources, journaux) ne sont recherchés que dans leur propre menu ; les listes de comptes cloud restent dans la recherche. Les lignes de sous-menu se terminent par **>** ; **Shift + Backspace** revient au parent.

## Installer

Appuyez sur Delete sur une entrée installée dans les listes d’applications et d’outils d’Installer pour la désinstaller après confirmation. Applications web conserve son action de suppression. Paquets (Pacman et Yay) reste réservé à l’installation, sans action Delete. Les dépendances nécessaires au système ne sont jamais supprimées récursivement ; pacman refuse une suppression qui casserait un autre paquet.

Les ensembles de langages gérés affichent leur avertissement complet dans un terminal avant de demander confirmation avec [y/N] ; Enter annule. La suppression de Node inclut toutes les versions gérées par NVM et leurs outils npm globaux. Celle de Python concerne les versions gérées par uv et uv lui-même, pas Python du système. Pour Java, les versions actuelles de Java et Maven dans SDKMAN sont supprimées ; pour Rust, seule la chaîne d’outils stable est supprimée. Rails et Laravel suppriment leurs outils de framework en conservant Ruby, PHP et Composer. Vos projets, paramètres et identifiants sont conservés, mais certains outils et environnements dépendants pourraient ne plus fonctionner. La suppression des assistants natifs conserve les versions en cache et les paramètres.


Les applications présentes affichent **Installé** sous leur nom ; les choisir l’indique au lieu de réinstaller. Cela reconnaît aussi les outils installés par leur gestionnaire, comme Java avec SDKMAN ou Node.js avec NVM. Un paquet nécessitant un environnement d’exécution, tel Java pour DBeaver, n’en ajoute un petit que si aucun paquet ne le fournit déjà.

- **CLI d’IA:** clients IA facultatifs en ligne de commande.
- **Navigateurs:** choix de navigateurs compatibles.
- **Bases de données:** outils facultatifs comme DBeaver, clients de bases et Valkey, le serveur compatible Redis distribué par Arch à la place de Redis.
- **Langages de développement:** outils facultatifs ; Java/Flutter ne sont pas des dépendances obligatoires du bureau.
- **Outils JavaScript:** environnements d’exécution et outils JavaScript facultatifs.
- **Paquets > Pacman** et **Paquets > Yay (AUR):** recherche de paquets officiels Arch ou communautaires AUR, avec origine et état d’installation. La recherche est en haut, les paquets dessous et les détails de la sélection en bas. **Ctrl+B** alterne avec les instructions de compilation (PKGBUILD), **Ctrl+O** ouvre la page web, **Tab** sélectionne plusieurs paquets et **Enter** les installe. Les paquets AUR sont compilés ici à partir de ces instructions : lisez-les d’abord. Ce ne sont pas des paquets officiels Arch.

Les terminaux d’installation, mise à jour et configuration affichent le bandeau EITR aux couleurs du thème. Les tâches réussies se ferment normalement ; les échecs restent visibles. Les rapports comme Nettoyage restent ouverts pour lecture. Les terminaux ordinaires et À propos n’affichent pas ce bandeau.

Appuyez sur **Échap** pour fermer les terminaux de tâches, de comptes, de rapports et À propos qui attendent une touche. Entrée reste utilisée pour les réponses et confirmations, notamment après avoir noté la clé de récupération et pour éteindre le programme d’installation.

## Outils

**Calculatrice** dans Applications, ou la touche calculatrice, ouvre celle d’Eitr aux couleurs du thème. Saisissez ou cliquez : `+ − × ÷`, `^` pour les puissances, `%` pour les pourcentages (`200×15%`), `√` et parenthèses. Un nombre avant une parenthèse multiplie (`2(3+4)`). Enter affiche le résultat, Backspace supprime un caractère, Escape efface (deux fois ferme), Ctrl+C ou **Copier** copie le résultat. L’expression est calculée sans être exécutée comme du code.

**Dictée hors ligne** transforme la parole en texte sans l’envoyer hors de l’ordinateur. Maintenez **SUPER + D**, parlez et relâchez : les mots sont saisis au curseur dans la langue parlée. Vous pouvez aussi appuyer brièvement sur **SUPER + D**, parler, puis appuyer à nouveau. Pendant l’écoute, le point rouge à gauche de l’horloge devient une petite onde suivant votre voix, pour confirmer sa réception ; après relâchement, elle pulse jusqu’à la saisie du texte. Le premier usage télécharge une fois le modèle vocal (148 Mo, vérifié avec sa somme de contrôle publiée) dans `~/.local/share/eitr/whisper/` ; ensuite, tout fonctionne hors ligne. La transcription prend un moment après relâchement, davantage sur les anciens processeurs. L’enregistrement s’arrête au relâchement de D, même si SUPER a été relâché avant, ou après 120 secondes ; les mots sont ensuite transcrits comme d’habitude.

**Principal > Outils > Rappels > Nouveau rappel** demande quand (durée comme `10m` ou `1h30m`, heure comme `18:30`) et quoi, puis affiche à cet instant une notification restant jusqu’à fermeture. **Rappels à venir** liste ceux en attente ; choisissez-en un pour l’annuler. Ils survivent au redémarrage ; ceux échus pendant l’arrêt apparaissent à la prochaine connexion. Dans un terminal : `eitr remind 25m Take the tea out` ; `eitr remind` seul les liste.

## Jeux

Principal > Jeux liste **GeForce NOW**, **RetroArch** et **Steam**. Choisir l’un l’ouvre s’il est installé, sinon l’installe. RetroArch provient des paquets officiels Arch avec des cœurs pour NES, SNES, Game Boy et Game Boy Advance, Mega Drive/Genesis, PlayStation, Nintendo 64, Nintendo DS, PSP et Dreamcast. Ajoutez vos jeux et les fichiers BIOS nécessaires aux consoles ; Eitr ne fournit ni les uns ni les autres. GeForce NOW s’installe par Flatpak.

**Basculer > Mode jeu** limite les interventions du bureau : animations, flou et ombres désactivés, notifications contextuelles différées (Ne pas déranger), profil de performances activé si disponible. Le désactiver restaure exactement ses changements. Steam inclut **GameMode** et **MangoHud** : ajoutez `gamemoderun mangohud %command%` aux options de lancement du jeu dans Steam pour optimiser le processeur et afficher les FPS.

Le paquet LocalSend inclut ses besoins d’exécution : le Flutter SDK n’est pas nécessaire pour l’utiliser. Les outils de développement restent facultatifs.

Pour mettre à jour, consultez [Mises à jour et nettoyage](handbook:maintenance) ; installer un seul paquet n’équivaut pas à la Mise à jour du système protégée par instantanés.

**Visualiseur de musique** dans **Principal > Outils** ouvre cava avec les couleurs du thème. Un clic droit sur l’égaliseur multimédia ouvre ce visualiseur ; le clic gauche ouvre toujours les détails multimédias. Appuyez sur **q** ou **Échap** pour le fermer. Si cava manque, il est installé au préalable.

Lorsqu’un moniteur connecté prend en charge HDR, Eitr utilise par défaut Wayland et HDR pour les jeux Proton de Steam avec `PROTON_ENABLE_WAYLAND=1`, `PROTON_ENABLE_HDR=1` et `DXVK_HDR=1`. Sans moniteur HDR, les réglages existants sont conservés. La détection matérielle actualise la configuration d’affichage générée à chaque liste ou modification des écrans et avant son chargement à la connexion ou au rechargement. Ouvrez une nouvelle session de bureau et redémarrez Steam pour hériter des changements ; Steam déjà lancé conserve son environnement. Activez HDR dans le jeu ; les jeux en plein écran peuvent basculer automatiquement le moniteur même sans HDR du bureau. Quelques jeux perdent la superposition Steam sous Wayland. Pour exclure un jeu, utilisez `PROTON_ENABLE_WAYLAND=0 %command%` dans ses options de lancement Steam. Pour calibrer un jeu, réglez sa luminosité maximale ou de crête sur le pic HDR indiqué dans les caractéristiques de votre moniteur (un moniteur DisplayHDR 400 atteint environ 400 nits), puis ajustez le blanc papier ou la luminosité générale à votre goût. Si les zones claires perdent du détail, baissez le pic ; si l’image paraît terne, augmentez le blanc papier.


## Rappels vocaux

Maintenez **SUPER + Shift + D**, parlez puis relâchez, ou saisissez du texte dans Principal > Outils > Rappels > Parler à l’assistant…. Eitr transcrit localement avec le modèle hors ligne de la dictée, puis consulte l’assistant choisi dans Développement > Assistant par défaut. Seuls la transcription et le contexte des rappels vont à son fournisseur ; l’audio reste local et est supprimé après transcription. L’assistant fonctionne sans fenêtre par la voie en lecture seule d’Eitr. Eitr valide son JSON et exécute les actions ; l’assistant ne reçoit aucun outil permettant des modifications. Avec Ratatoskr (Développement > Assistant par défaut), la transcription ne quitte jamais ce PC.

Dites « Rappelle-moi d’appeler demain à 15 h » ou « Dentiste le 30 octobre à 15 h, prévenir 30 minutes avant ». Les rendez-vous déclenchent un avis une heure avant par défaut (ou selon le délai demandé), puis à l’heure prévue ; les rappels simples seulement à leur heure. En cas d’ambiguïté ou de détails manquants, un terminal affiche les choix numérotés en entier. Saisissez le numéro ou votre propre réponse, ou dictez-le avec SUPER + D ; Esc annule. Une date sans heure ouvre l’horloge, quel que soit l’assistant. Une notification indique le résultat. Vous pouvez aussi demander de lister ou d’annuler les rappels.

Nouveau rappel accepte `tomorrow 15:00`, les jours anglais, `2026-10-30 09:00`, `Oct 30 15:00`, `9am`, `in 5 minutes` et `every 29th`. Mettez les dates contenant des espaces entre guillemets dans la CLI. Chaque avis possède son minuteur ; l’annulation les supprime tous. Les avis manqués apparaissent à la prochaine connexion. Une date sans heure, saisie ou dictée, ouvre une petite horloge : saisissez une heure sur 24 heures dans HH:MM ; Retour arrière efface le dernier chiffre et les flèches règlent les heures ou minutes ; Entrée valide l’heure et Échap annule. Les avis de rappel émettent un son bref, sauf en mode Ne pas déranger. Le calendrier marque les jours concernés ; cliquez pour voir les heures et titres immédiatement actualisés. Chaque rappel listé a un bouton corbeille : cliquez deux fois pour supprimer un rappel unique, ou choisissez Celle-ci (seulement la prochaine occurrence) ou Toutes pour un rappel répété. Échap, un clic ailleurs ou quelques secondes sans action conservent le rappel.

Les rappels récurrents acceptent `every day 08:00`, `every Monday 09:30`, `weekdays 07:00`, `every Monday and Thursday 09:30`, `every week`, `every month on the 15th` et `every year` (avec une heure). Utilisez des guillemets : `eitr remind "every day 08:00" Stretch`. L’assistant accepte un intervalle, une date de fin ou un nombre d’occurrences. Les dates inexistantes utilisent le dernier jour du mois. L’heure locale et les alertes relatives sont conservées. Seule la prochaine occurrence a des minuteries ; après un arrêt, un seul rappel manqué apparaît et les occurrences passées sont sautées, en comptant pour la limite. La liste montre la prochaine heure et la règle. Annulez une occurrence ou la série : `eitr remind cancel ID occurrence` ou `eitr remind cancel ID series`. Le calendrier affiche des points et ↻ sans changer de hauteur.

**Principal > Outils > Calendriers > Ajouter un calendrier…** affiche un calendrier Google, Outlook ou un autre calendrier iCal dans le panneau du calendrier, en lecture seule et sans connexion. Choisissez le fournisseur : Google et Outlook ouvrent leurs paramètres dans le navigateur. Dans Google, copiez Paramètres de mes agendas > Intégrer l’agenda > Adresse secrète au format iCal ; dans Outlook, publiez un calendrier sous Paramètres > Calendrier > Calendriers partagés et copiez son lien ICS. Collez l’adresse (`https://` ou `webcal://`), puis nommez le calendrier. Toute personne qui connaît cette adresse peut lire le calendrier : Eitr la garde donc dans un fichier privé et ne l’affiche jamais dans les menus, les notifications ou les journaux ; réinitialisez l’adresse secrète chez le fournisseur si elle fuit. Les calendriers se mettent à jour à la connexion, toutes les 15 minutes et à l’ouverture du panneau du calendrier (au plus une fois par minute). Les événements de la semaine dernière aux 60 prochains jours apparaissent à côté des rappels avec le nom du calendrier et sans corbeille : modifiez-les dans Google ou Outlook. Les événements avec heure préviennent à leur début avec le son des rappels ; ceux sur toute la journée ne préviennent pas. Les répétitions quotidiennes, hebdomadaires, mensuelles (un jour du mois ou un jour de la semaine comme le dernier vendredi) et annuelles sont affichées ; les règles plus rares ne montrent que leur premier événement. Dans le menu Calendriers, Entrée actualise un calendrier tout de suite et Suppr le retire après confirmation. La synchronisation dans les deux sens (créer ou modifier des événements chez le fournisseur) n’est pas prise en charge. Le terminal reste ouvert pendant la copie du lien dans le navigateur ; Entrée sur le récapitulatif ajoute le calendrier et Échap annule.

## Plugins

Un plugin est un dépôt Git contenant des scripts, des entrées Walker et éventuellement un service utilisateur. Un plugin s’exécute en votre nom, avec toutes les permissions de votre compte : il peut lire vos fichiers, vos clés SSH et les données de votre navigateur, les envoyer n’importe où et continuer à tourner. Eitr n’a pas vérifié son code ; le code appartient à son auteur, pas à Eitr, et chaque entrée de plugin l’indique, par exemple Plugin de Ada · non vérifié par Eitr. N’ajoutez que des plugins de personnes et de dépôts de confiance.

Eitr ne demande votre mot de passe que dans un terminal qu’il a ouvert pour une étape que vous avez lancée, comme Mise à jour du système, jamais dans une fenêtre surgissante. Si un plugin vous demande votre mot de passe, ce n’est pas Eitr : ne le saisissez pas.

Principal > Installer > Plugins > Ajouter un plugin… demande une URL Git HTTPS ou, pour un dépôt privé, une URL SSH comme `git@github.com:you/plugin.git` (elle utilise vos clés SSH via l’agent). L’ajout demande deux confirmations, toutes deux à Non par défaut. D’abord, avant tout téléchargement, une page de sécurité explique ces risques ; appuyez sur Entrée pour télécharger le plugin et le vérifier. Ensuite, la vérification commence par l’avertissement de confiance et les éventuels avertissements (un service en arrière-plan lancé à chaque connexion, des fichiers binaires), puis présente l’auteur du manifeste, le dépôt, le commit exact, l’auteur Git et sa date, la version, le nombre de fichiers exécutables et les entrées. Appuyez sur Entrée pour installer ; Échap annule à chaque étape et les autres touches ne font rien. Rien du plugin ne s’exécute avant l’approbation. `eitr plugin add URL` pose les deux mêmes questions (Entrée continue, Échap annule) et refuse de fonctionner sans terminal. Principal > Outils > Plugins liste ses actions ; la saisie dans Outils les recherche aussi. Le menu vide affiche Aucun plugin installé.

Mise à jour du système vérifie les plugins même sans mise à jour des paquets. Chaque mise à jour commence par un résumé : ancien et nouveau commit, sujets des commits, fichiers modifiés avec lignes ajoutées et supprimées, et signaux de RISQUE pour un service en arrière-plan ajouté, modifié ou supprimé, toute modification du manifeste, des fichiers exécutables nouveaux ou modifiés, des fichiers binaires et des commits d’un autre auteur que celui du commit approuvé. Appuyez sur `d` pour lire le diff complet dans un pager (`delta` s’il est installé, sinon `less -R`), Entrée pour mettre à jour, ou Échap pour garder la version actuelle. Si l’historique a été réécrit et que le commit approuvé ne fait plus partie du nouveau, Eitr ne met pas à jour automatiquement et explique pourquoi ; supprimez le plugin et ajoutez-le de nouveau si vous lui faites toujours confiance. Les mises à jour non interactives ignorent les plugins. Installer > Plugins > le plugin propose Mise à jour et Supprimer ; la suppression demande confirmation et retire fichiers, entrées et service. Les mêmes parcours existent avec `eitr plugin list`, `eitr plugin add URL`, `eitr plugin update [ID]` et `eitr plugin remove ID`.

Eitr fournit une liste de blocage des plugins dans le paquet signé `eitr-desktop`, si bien que la signature du paquet par pacman la protège. Chaque entrée désigne un dépôt, un commit ou un identifiant de plugin, avec un motif. L’ajout ou la mise à jour d’un plugin bloqué est refusé. Un plugin installé qui devient bloqué s’arrête : ses entrées quittent Outils > Plugins, il ne peut plus être lancé, son service est arrêté et désactivé, et une seule notification le nomme avec le motif, accompagnée d’un bouton Supprimer. Installer > Plugins le marque comme bloqué, et le sélectionner le supprime. Ses fichiers ne sont jamais effacés automatiquement. Pour signaler un plugin nuisible, ouvrez `https://github.com/eitr-org/eitr/issues/new?template=malicious-plugin.yml` ; ne collez jamais de mots de passe, jetons ou clés dans le signalement. Un profil d’organisation peut aussi désactiver les plugins ou n’autoriser que les dépôts d’une liste (voir Profils d’organisation).

Les plugins résident uniquement dans `$XDG_DATA_HOME/eitr/plugins/<id>/` (par défaut `~/.local/share/eitr/plugins/`) ; les approbations dans `$XDG_STATE_HOME/eitr/plugins.json`. Les services utilisent `$XDG_CONFIG_HOME/systemd/user/eitr-plugin-<id>.service` avec `NoNewPrivileges=yes` et ne peuvent donc pas obtenir de privilèges via des programmes comme sudo. N’utilisez jamais sudo. Les mises à jour valident un candidat séparé et gardent le commit approuvé en cas de refus ou d’échec. Un plugin peut modifier vos fichiers pendant son exécution ; le supprimer n’annule pas ces modifications.

### Référence du manifeste

La racine contient `eitr-plugin.json`. Seules ces clés sont admises : `id` (minuscules et chiffres séparés par des tirets simples), `name`, `description` (72 caractères maximum), `author`, `version`, `rows` (1–20) et `service` facultatif. Chaque entrée exige `title`, `description` (72 caractères maximum chacun) et `run` ; `icon` et `arguments` (liste de chaînes fixes) sont facultatifs. Un service accepte seulement `run` et éventuellement `arguments`. Les commandes utilisent argv, jamais des chaînes de shell. `run` doit désigner un exécutable interne au dépôt : chemins absolus et `..` sont refusés, tout comme un lien symbolique n’importe où dans le plugin. Les clés JSON inconnues ou dupliquées sont refusées. Les sous-modules ne sont pas initialisés.

L’exemple dans `distro/plugins/example/` contient un manifeste et `notify.sh`, une action de notification sans service. Copiez-le dans votre dépôt Git, créez un commit et publiez une URL Git HTTPS pour essayer le parcours complet. Il est fourni comme documentation, sans installation automatique.
