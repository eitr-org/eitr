# Before Publishing Eitr

This repository is public on GitHub and is also the owner's desktop backup. The
public beta is out; this checklist tracks what remains before a wider release and
should be rechecked before each ISO. Each item lists why it matters and the fix.

## 1. Separate the distro from the personal backup

The product and the owner's machine still live in one repository.

- `.githooks/` guard commit identities and the push remote, reading them from the
  checkout's local Git config (`eitr.guard.*`); `AGENTS.md` and the hooks name
  no identity. The owner's identity rules live in their local agent instructions.
- Machine-specific settings (monitor layout, mouse, primary display) should
  live only in machine-local files such as `~/.config/hypr/local.lua`.
- Developer tooling (the Cloud accounts menu and Development > Monitoring) is
  generic and stays in the distro.

Recommended: create a clean public `eitr` repository for the distro and keep a
private overlay repository (identity hooks, AGENTS rules, personal configs,
`local.lua`) that is applied on top of the owner's machine.

## 2. Repository size and history

Done. On 2026-10-19 the history was squashed into one commit, and later that day
third-party reference wallpapers were removed from every commit; a fresh clone is about
275 MB. The lockscreen videos are gone and wallpapers ship as JPEG
(`distro/RELEASES.md`). Keep new large media small (JPEG for paintings) so the
history stays lean; Git LFS is not needed at this size.

## 3. Licensing and artwork rights

- EITR's own code and configs are GPL-3.0-or-later (top-level `LICENSE`).
- `NOTICE.md` lists every third-party component, bundled package and where to
  get its source; `distro/tests/test_notice.py` fails when one is missing.
- No imported theme files or third-party wallpapers remain: each theme's icon,
  VS Code, Neovim and btop files are generated by
  `themes/build-theme-files.py` from Eitr's `integrations.json` and palettes.
- Four lockscreen layouts are adapted from qylock (GPL-3.0, credited).
- GPL source: Arch packages point to Arch's servers; the AUR packages EITR builds
  have their source archives saved by `build-payload.py --sources` and kept
  offline (`distro/RELEASES.md`), backing the offer in `NOTICE.md`.
- Franchise artwork was removed or renamed; `distro/ARTWORK-LICENSING.md` and
  `python3 distro/artwork-check.py --public` track what remains under review
  (currently nothing).

## 4. Secrets and personal data

On 2026-10-16 gitleaks 8.21.2 scanned all 598 commits on every branch and the
working tree: no leaks. A search for private keys and GitHub, AWS, Slack and API
tokens in the full history found none either. Rerun before each release:

```sh
gitleaks git --redact --log-opts="--all" .
```

Work details (the employer's name, the work email and account) were removed
from the tree and, by a history rewrite with `git filter-repo`, from every
commit, message and tag on 2026-10-16. The repository was then recreated as
`eitr-org/eitr`, so no pull request still references the old commits, and on
2026-10-19 its history was squashed into a single commit to make it smaller
(`distro/RELEASES.md`).

Also review: names and emails in commit metadata (all commits use the personal
identity), clone URLs pointing at `eitr-org/eitr`, and anything under
`HOME_FILES/` (shell history, tokens and SSH config must never be included).

## 5. Support tooling for other users

Once other people run Eitr, add a Walker "Collect diagnostics" action that
bundles `hyprctl configerrors`, package and component versions, the bar and
lockscreen logs, and recent journal excerpts into one archive, redacting WiFi
names, IP addresses, usernames and tokens. It turns "it doesn't work" reports
into something debuggable.
